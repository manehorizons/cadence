## Key decisions

### Foundational (locked in via brainstorming Q&A this session)

- **Cardinality: 1:1.** One recommendation converts to exactly one phase. Schema: `Recommendation.convertedToPhaseId?: string` (singular, exact-optional). If a rec is too big for one phase, operator splits the rec before promoting. Rejected alternatives: 1:many (`convertedToPhaseIds: string[]`), many:many (would require phase-side metadata file).
- **Promotion mechanic: explicit transition command.** `cadence recommendation convert <recId> --to-phase <phaseId>`. Mirrors Slice 13 vocabulary. Rejected: `--from-rec` flag on `spec new` (breaks down for backfill), both-at-once (too much surface).
- **FK validation: strict.** `.cadence/phases/<phaseId>/` must be an existing directory at convert time. Refuses with `cannot convert: phase <phaseId> not found` on miss. Mirrors Slice 28's `--by` FK pattern. Rejected: lax (rec gets dangling pointer; audit flags it later), strict-with-force-bypass (too many flags).
- **Reversibility: terminal.** No `unconvert` transition. Conversion is a historical fact ("rec X was implemented in phase Y"), distinct from `decision.supersede` ("decision was wrong, replaced"). Phase deletion is caught by the audit dim (Slice 34.2), not a status flip. Rejected: `unconvert` symmetric to `reactivate`, and a new `withdrawn-conversion` status enum value.
- **Layering: Approach A — loose coupling.** Praxis records the conversion event; CADENCE engine stays Praxis-unaware. No phase-side metadata file (no `.cadence/phases/<id>/SOURCE.json`). No auto-flip-on-settle. Reverse-lookup is a CLI query (`recommendation list --filter-converted-to <phaseId>` in 34.4), not a derived field. Rejected: Approach B (bidirectional metadata; couples layers), Approach C (engine-integrated promotion; breaks "Praxis sits above the loop" architecture).

### Slice 34.1 scope (next concrete slice after 34)

- **Schema additive**: `Recommendation.convertedToPhaseId?: z.string().optional()` on `RecommendationZ`. Exact-optional (Slice 28 pattern, NOT Slice 11 `.default([])`).
- **Pure helper**: `applyRecommendationTransition(ledger, id, action, toPhase?)` returning `DecisionTransitionResult`-shaped result. Pure, sync, testable without disk.
- **I/O wrapper**: `runRecommendationTransition(root, id, action, toPhase?)` does the filesystem FK check via `phaseDirectoryExists(root, phaseId)` BEFORE delegating to the pure helper. Filesystem read stays out of the pure layer (deliberate departure from Slice 28's all-pure transition — phase existence is a fs fact, not a ledger fact).
- **Transition matrix**: `convert` allowed from `['candidate', 'accepted']`. Refused from `'deferred'`, `'rejected'`, `'converted'`. Refusal: `cannot convert recommendation in status <status>`.
- **State propagation on convert success**: `recommendation.status` → `'converted'`; `recommendation.convertedToPhaseId` → `<phaseId>`; `recommendation.updatedAt` bumped; `RECOMMENDATIONS.md` re-renders via the existing `rerenderRecommendationsMdIfPresent` hook (Slice 15). No state.json touch. No phase-side write.
- **CLI**: `cadence recommendation convert <recId> --to-phase <phaseId>`. `--to-phase` is required. Output: `recommendation <recId> → converted (to <phaseId>)\n`.
- **Render**: `render-recommendation-detail.ts` gains `- converted-to-phase: <phaseId>` bullet between `- status:` and the inverse-link arrays. **No `(not found)` fallback at render** — render stays pure (no disk reads); drift is the audit dim's job. JSON envelope: existing serialization already covers the new field.
- **RECOMMENDATIONS.md (bucket render)**: NOT extended. The Slice 15 status-annotated bullets already show `(converted)` via the status enum. Adding inline phase-id would be visual noise (same precedent as Slice 31's decision bucket-render decision).
- **Reconcile interaction**: none. Convert is operator-explicit, not derived.
- **Idempotency on re-convert**: refused naturally. Already-converted recs have status `'converted'`, which isn't in `convert`'s ALLOWED list.
- **Scope estimate**: ~150–200 LoC including tests. In line with Slice 31.

### Slice 34.2 scope (audit dim — separate slice after 34.1)

- **New finding kind**: `| { kind: 'stale-converted-phase'; recommendationId: string; missingPhaseId: string }` on `IntelligenceAuditFinding` union.
- **`computeIntelligenceAudit` signature extension**: new parameter `existingPhaseIds: Set<string>`. Stays pure-sync. The `intelligence audit` CLI command pre-computes the set via `readdir(.cadence/phases)` once and passes it in. Cleaner than making `computeIntelligenceAudit` async.
- **Render extension**: new `## Stale converted-to-phase Refs (N)` section before `## Remediation`. Bullet shape: `- <recommendationId> convertedToPhaseId missing phase: <missingPhaseId>` (mirrors Slice 30 line shape).
- **Remediation hint**: new bullet — "verify the phase id is correct (typo?), OR hand-edit the rec to clear `convertedToPhaseId` then run `cadence intelligence reconcile`".
- **Scope estimate**: ~80 LoC. Tighter than Slice 30 because the pattern is proven.
