# 194-01 — Exempt telemetry-only counters from revision-guarded commits

## Objective

Fix GitHub issue #234: `cadence settle run` deterministically fails with
`StateConflictError` whenever a long-running (`host-cli`) verifier gate
overlaps another subagent's `SubagentStop` → `handleSubagentResult()`
commit, because that handler's *only* mutation in its common early-return
paths is `state.session.subagentSpawns += 1` — a purely informational
counter — yet it still goes through the same revision-guarded
`SimpleStateBackend.commit()` as structural writes, bumping `revision` and
invalidating any other command's in-flight snapshot. Give
`session.subagentSpawns` (and future telemetry-only session counters) a
write path that does not participate in the optimistic-concurrency
compare-and-swap, so bumping it can never invalidate a concurrent
structurally-guarded commit. Structural state (loop position, tasks,
drafts, decisions, `subagentBaselines`) keeps the existing revision-guarded
protection unchanged.

## Acceptance Criteria

### AC-1: false conflict is reproduced by a regression test
Given a caller has read `state.json` at revision N and is mid-flight on an
unrelated structural change
When another writer bumps only `session.subagentSpawns` and commits in
between (landing at revision N+1)
Then the first caller's structural commit currently throws
`StateConflictError` even though nothing it read or changed was touched by
the intervening telemetry-only write

### AC-2: subagentSpawns writes no longer trip the revision guard
Given `handleSubagentResult()`'s early-return paths (no `agentId`/baseline,
or no `activeDraft`/`activePhase`) whose only mutation is the spawn-count
increment
When they persist that increment
Then they do so through a path that does not compare or bump the shared
`revision` field, so a concurrent structurally-guarded `commit()` elsewhere
is never invalidated by it alone

### AC-3: structural optimistic concurrency is unchanged
Given two callers both mutate structural state (e.g. `loopPosition`,
`openDrafts`, `activeTask`) from the same on-disk revision
When the second one commits after the first
Then `commit()` still throws `StateConflictError` exactly as before —
`AC-1`/`AC-2` narrow the exemption to telemetry-only counters, they do not
weaken the existing guarantee

### AC-4: test suite passes
Given the fix and regression tests are in place
When `pnpm --filter @manehorizons/cadence-core test` runs
Then it exits successfully with no failing tests

- done: AC-1

### T2: Add a telemetry-exempt write path and route the spawn counter through it
- files: `packages/core/src/state/simple.ts`, `packages/core/src/state/backend.ts`, `packages/core/src/hooks/handlers.ts`
- action: add a `StateBackend` method (e.g. `bumpSessionCounter`) that
  re-reads on-disk state, applies only a telemetry-field patch (starting
  with `session.subagentSpawns`), and writes it back without comparing to
  or bumping `revision` — accepting the same narrow "last write wins" trade-off
  already documented for true-simultaneous-writes in
  `docs/superpowers/specs/2026-07-12-cadence-write-lock-design.md`, but now
  applied deliberately to informational counters instead of being an
  accidental side effect of the general path. Route
  `handleSubagentResult()`'s spawn-count increment through it instead of
  the general `backend.commit(state)` in the paths where that increment is
  the only mutation
- verify: the T1 regression test now passes; existing `commit.test.ts` and
  `hooks/dispatcher.test.ts`/`handlers` tests covering structural
  conflicts and the baseline/task-redundancy branches still pass unchanged
- done: AC-2

## Boundaries

- DO NOT touch `settle.ts`'s sequential five-gate execution or add a
  retry-on-conflict loop there — the chosen fix is exempting telemetry
  counters, not retrying settle. That direction was considered and
  explicitly not picked for this phase.
- DO NOT widen the telemetry exemption to `subagentBaselines` or any other
  structural/session field beyond `subagentSpawns` (and, if genuinely
  telemetry-only, `tokenUtilization`) without adding an explicit AC —
  `subagentBaselines` feeds real task-redundancy comparisons and must stay
  revision-guarded.
- DO NOT relitigate or rewrite the "Accepted limitation: true simultaneous
  writes" section of `docs/superpowers/specs/2026-07-12-cadence-write-lock-design.md`
  — this phase narrows what counts as telemetry, it doesn't reopen that
  LOCKED trade-off.
- DO NOT remove or weaken existing structural-conflict tests to make the
  new regression test pass.
