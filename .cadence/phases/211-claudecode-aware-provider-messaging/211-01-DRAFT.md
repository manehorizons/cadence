# 211-01 — CLAUDECODE-aware messaging for anthropic provider + host-cli suggestion

## Objective

When `deep-verify`'s provider is `anthropic`, its credential is missing, and the process is running inside a live Claude Code session (`CLAUDECODE=1`), `cadence doctor`'s verification-readiness check and `cadence activate`'s key-missing message should name the Claude-Code-login-doesn't-satisfy-this confusion directly and proactively suggest `host-cli`, instead of printing the same generic "key missing, export it" text as any other case.

## Acceptance Criteria

### AC-1: `cadence doctor`'s verification-readiness check is CLAUDECODE-aware
Given `deep-verify`'s effective provider is `anthropic`, its credentials are missing, and `env.CLAUDECODE === '1'`, so `checkVerificationReadiness` (`packages/core/src/doctor/run.ts` ~707-714) takes the real-provider-missing-key branch,
When `checkVerificationReadiness` builds the `warning` `DoctorCheck`,
Then its detail/remediation text additionally states that a Claude Code login does not supply `ANTHROPIC_API_KEY` and suggests `cadence activate --provider host-cli`, while remaining byte-identical to today when `CLAUDECODE` is unset or the provider isn't `anthropic`.

### AC-2: `cadence activate`'s key-missing message is CLAUDECODE-aware
Given `cadence activate` resolves to `provider: anthropic` with a missing key and `env.CLAUDECODE === '1'`,
When `renderText`/`renderJson` (`packages/core/src/activate/render.ts`) render the `keyMissing` branch,
Then the human text additionally states the same distinction and suggests `cadence activate --provider host-cli`, `renderJson`'s output carries a `claudeCodeHostCliSuggested: true` field, and both are byte-identical to today when the session flag is absent/false or the provider isn't `anthropic`.
