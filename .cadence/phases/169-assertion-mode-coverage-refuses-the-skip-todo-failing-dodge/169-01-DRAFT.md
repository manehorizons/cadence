# 169-01 — Assertion-mode coverage refuses the .skip/.todo/.failing dodge

## Objective

Close the '.skip dodge': in assertion-mode coverage, an AC whose only linked test sits inside a test.skip/.todo/.failing block must not count as qualifying, even when the assertion token is intact inside it. Add a distinct settle refusal ('AC-N's only linked test is skipped') separate from the existing 'no linked test' and 'mentioned but not asserting' messages, per docs/DEMO.md's documented Finding. Root cause: packages/core/src/verify/test-spans.ts's OPENER_AT regex admits .skip/.todo/.failing modifiers and only checks assertion-token presence, not skip status.

## Acceptance Criteria

### AC-1: failing test proves today's gap before any fix lands
Given an AC linked only to a test.skip(...) (or .todo/.failing) block containing an intact assert/expect call
When assertion-mode coverage scans it today, on the current unfixed code
Then a new regression test demonstrates the AC is wrongly treated as qualifying (weaklyLinkedAcs returns empty / the gate does not refuse) — this test must fail red against pre-fix code, proving the gap exists

### AC-2: .skip/.todo/.failing openers are treated as non-asserting spans
Given a test span whose opener is it.skip/test.skip/.todo/.failing, with or without an assertion token inside
When findTestSpans classifies the span and scanTestCoverage maps an AC-N ref onto it
Then the span is marked non-qualifying for assertion-mode coverage regardless of whether an assertion token is present inside it, distinguishable from the plain 'weak/mention-only' case

### AC-3: distinct refusal message for the skip-only case
Given an AC whose every linked ref sits inside a skip/todo/failing span (none qualify)
When cadence settle run --auto runs the test-coverage gate in assertion mode
Then it refuses with a message distinct from both 'has no linked test' and 'mentioned but not inside an asserting it()/test() block' — naming the AC and that its only linked test is skipped — and exits non-zero

### AC-4: existing absent/weak/qualifying cases are unchanged
Given the three pre-existing assertion-mode cases: zero refs anywhere, a ref outside any span or inside a non-asserting non-skip span, and a fully qualifying ref
When the fix lands
Then their gate outcomes and exact refusal messages are byte-for-byte unchanged, proven by regression tests covering each case

- DO NOT change the existing "no linked test" (absent) or "mentioned but not asserting" (weak) messages/behavior for non-skip cases — regression-test them to prove byte-for-byte stability.
- DO NOT weaken or remove the regression test added in T1 to make it pass.
- DO NOT add real per-language (non-JS/TS) skip-detection — this stays scoped to the existing JS/TS `findTestSpans` parser.
