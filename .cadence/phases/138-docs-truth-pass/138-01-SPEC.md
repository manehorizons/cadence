# 138-01 — Docs truth pass: slash-command counts + start menu completeness

## Objective

rec-20260701-011's audit evidence (R-11/F9-F10) named two things. Investigation
found one claim doesn't reproduce: the README flagship walkthrough (`init` →
`draft new --template bugfix` → approve → `build task T1 --status=DONE` →
`settle run --auto`) was live-tested and genuinely refuses on the coverage
gate ("AC-1 has no linked test") exactly as the README says — no fix needed
there. The other claim is real and verified: the Claude Code slash-command
count is published inconsistently — README.md says "eleven", docs/quickstart.md
says "nine" (and its table only lists 9 of the 12), and docs/claude-code.md's
own table of contents says "The 9 slash commands" while its actual section
header two paragraphs later says "The 12 slash commands" (a broken TOC
anchor). Code truth, verified directly: `COMMANDS` in
`packages/host-claude-code/src/install-commands.ts` has exactly 12 entries.
Separately, `cadence start`'s guided menu never offers `cadence activate` even
though the mock-verifier banner it can lead a user past explicitly recommends
running it — the front door doesn't reach its own remedy. Fix both.

## Acceptance Criteria

### AC-1: slash-command count is 12 everywhere, consistently
Given the code truth of 12 entries in `install-commands.ts`'s `COMMANDS` array
When README.md, docs/quickstart.md, and docs/claude-code.md are read
Then all three name 12 slash commands, docs/claude-code.md's TOC entry and
section header agree (anchor no longer broken), and no stale "nine"/"eleven"
count remains

### AC-2: docs/quickstart.md's slash-command table is complete
Given the table under "install writes N slash commands"
When the table is read
Then it lists all 12 commands (adds the 3 missing: `/cadence-handoff`,
`/cadence-resume`, `/cadence-scout`), matching docs/claude-code.md's
already-complete table

### AC-3: cadence start offers the verification-activation remedy
Given a user runs `cadence start` (or `--json`/non-TTY prints the menu)
When the option list is shown
Then it includes an option that runs `cadence activate`, so a user who saw
the mock-verifier banner can reach the recommended remedy through the guided
front door without already knowing the command exists

## Constraints

- No new infrastructure (no generated/doc-sync-gate machinery) — this is a
  content correction + one static test asserting the count stays truthful,
  not a build step.
- `cadence start`'s existing 6 options keep their numbers 1-6 unchanged (new
  entry appends, not inserts) — `packages/core/tests/start/menu.test.ts`,
  `tests/start/render.test.ts`, and `tests/cli/start.test.ts`'s
  count-dependent assertions are updated to match, but every existing
  `resolvePick(n)` for n ≤ 6 still resolves to the same option.

## Open Questions

- None. The README-flow claim was investigated and found already-accurate
  (verified by live-running the exact walkthrough); scoped out. Adding
  `cadence explain` to the start menu was in the rec's summary but is
  deferred — `activate` is the one concretely evidenced gap (the banner
  names it by name); `explain` has no equivalent forcing function and can be
  a follow-on if wanted.
