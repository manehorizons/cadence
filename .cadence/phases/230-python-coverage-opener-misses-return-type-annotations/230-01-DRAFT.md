# 230-01 — python coverage opener misses return-type annotations

## Objective

Fix the built-in python coverage profile's opener regex so def/async def test functions with a return-type annotation (-> None:, -> bool:, etc.) are recognized as spans instead of silently producing zero coverage for the whole file.

## Acceptance Criteria

### AC-1: return-annotated test functions are recognized as coverage spans
Given a Python test file where test functions declare a return-type annotation, e.g. def test_foo(x: Path) -> None:
When cadence verify coverage scans that file with the built-in python profile
Then the opener still matches and the function's assert-bearing body is included as a qualifying span, exactly as it would be without the annotation

## Tasks

### T1: widen the python opener regex to accept an optional return-type annotation
- files: `packages/core/src/verify/coverage-profiles/python.ts`, `packages/core/tests/verify/coverage-profiles-python.test.ts`
- action: Add an optional non-capturing return-annotation group between the closing paren and the trailing colon in OPENER (matches -> None:, -> bool:, -> Optional[str]:, etc.); add tests for a plain annotated function, an async annotated function, and an annotated method under a class, plus a regression check that the existing no-annotation cases still match
- verify: pnpm --filter @manehorizons/cadence-core test -- coverage-profiles-python
- done: AC-1

## Boundaries

- Do NOT touch the js-ts, go, rust, or php coverage profiles — audited during
  triage; js-ts's opener matches on the `it(`/`test(` call itself, not the
  callback's signature, so it has no analogous blind spot and is out of
  scope here.
- Do NOT change the `indentation-delimited` strategy engine or `mask.ts` —
  this is a single opener-pattern fix, not a strategy change.
