# 277-01 — recommendation-archive-currency doctor check

## Objective

Add `cadence doctor`'s `recommendation-archive-currency` check: a deterministic,
warning-only signal that no recommendation in the active ledger array carries a
terminal `shipped`/`rejected` status without being archived — the invariant phase
276's backfill restored, following the `roadmap-currency`/`release-currency` house
pattern with the `indeterminate` severity rung (`dec-20260810-005`) handled
explicitly.

## Acceptance Criteria

### AC-1: Terminal, unarchived records are flagged
Given one or more recommendations in the active `.cadence/intelligence/recommendations.json` `recommendations[]` array with `status` `shipped` or `rejected`
When `checkRecommendationArchiveCurrency` runs
Then it returns severity `warning` naming each offending record's id and status, with remediation pointing at `cadence recommendation archive <id>`

### AC-2: Non-terminal and already-archived records are never flagged
Given records with `status` `candidate`, `accepted`, `deferred`, `converted`, or `settle-pending` in the active array, and records of any status already present in the `archived[]` array
When `checkRecommendationArchiveCurrency` runs
Then none of them appear in the check's finding — `converted` in particular is excluded deliberately: its schema-documented successor is `settle-pending` (reached only via the settle hook), not `archived`, so flagging it would emit wrong remediation (phase 276's `rec-20260701-001` finding is the evidence for this exclusion)

### AC-3: Malformed ledger is indeterminate, not ok
Given `.cadence/intelligence/recommendations.json` exists but fails to parse as JSON or fails `RecommendationLedgerZ` schema validation
When `checkRecommendationArchiveCurrency` runs
Then it returns severity `indeterminate`, never silently `ok` — diverging from the older best-effort-pass convention on the adjacent `checkRecommendationShippedDrift`/`checkOrphanedEvidence` checks, per `dec-20260810-005`'s later, more correct rung

### AC-4: Wired into `cadence doctor` and documented
Given `cadence doctor` runs
When the check set is assembled
Then `recommendation-archive-currency` appears in `runDoctor`'s `DoctorReport.checks`, in `docs/reference/commands.md`'s v1 check-set table, and in the `--fix` manual-classification list

### AC-5: No auto-repair
Given any `warning` or `indeterminate` result from this check
When the `DoctorCheck` is constructed
Then `fixId` is always `null` — archiving is evidence-gated per record (phase 276), so it is never a safe blind auto-repair even though the remediation command itself is mechanical

## As-built

AC-3's original wording ("missing or fails schema validation") was corrected during
T1's implementation: `readRecommendationLedger` → `readLedger`
(`../intelligence/store/ledger.ts`) does not throw when `recommendations.json` is
simply absent — it returns an empty ledger by design, since a brand-new `cadence init`
has no `intelligence/` directory at all. Forcing `indeterminate` on a missing file
would make every fresh repo report a false anomaly. AC-3 now correctly scopes to
"exists but fails to parse/validate," matching `checkConductionDriftStreak`'s own
precedent (corpus absent entirely → `ok`; corpus present but unassessable →
`indeterminate`). A missing file legitimately falls through to AC-2's zero-offenders
`ok` path, covered by a deliberately untagged test (not an AC-3 case).

The whole-branch review (post-T1/T2) found one Important gap: AC-4's "appears in
`runDoctor`'s `DoctorReport.checks`" clause had no regression test exercising
`runDoctor` itself — only the doc-content assertion existed, so deleting the wiring
line would have passed the suite. Fixed by adding a `runDoctor`-level test to
`recommendation-archive-currency.test.ts` (still T1's declared file), verified to
actually fail when the wiring line is removed. Also corrected a Minor inaccuracy in
`run.ts`'s doc comment ("this file's other two ledger-reading checks" undercounted —
`checkLedgerRemoteCollision` shares the same best-effort convention too).

## Boundaries

- DO NOT include `converted` or `settle-pending` in the flagged-status set — see AC-2's rationale.
- DO NOT add a `--fix` auto-repair for this check — see AC-5.
- DO NOT touch `checkRecommendationShippedDrift` or `checkOrphanedEvidence`'s own error-handling convention (best-effort `pass`) — this check's `indeterminate`-on-error divergence is deliberate and local to itself, not a refactor of its neighbors.
- DO NOT run `cadence recommendation archive` against the live repo's own ledger from this phase — this phase adds a read-only check, it does not perform another backfill pass.
