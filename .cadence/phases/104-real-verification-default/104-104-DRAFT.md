# 104-104 — Make real verification the felt default

## Objective

Stop the wedge from diverging from the default experience: name the `mock`
verifier honestly as a structural test-linkage **placeholder** (not real
verification) everywhere a user meets it — at settle, in `doctor`, in
`quickstart`/`config explain`, at `init`, and in the docs — and nudge the
operator toward `cadence activate`, all from one shared source-of-truth message,
without breaking the zero-config offline default.

## Acceptance Criteria

### AC-1: One source-of-truth "mock ≠ real verification" message
A single exported constant in `cadence-types` (alongside `COMMAND_GUIDANCE`)
holds the canonical phrasing — `mock` is a deterministic, offline structural
test-linkage **placeholder** that does **not** perform real verification — and
every surface in AC-2…AC-5 (incl. the v1.22 all-mock warning per Q3) renders
from it, no duplicated literals.

### AC-2: Settle states the verdict came from the mock placeholder
When `verifier.provider` resolves to `mock` and a settle fires a verification
gate (`--deep` **or** gate-set membership), the output explicitly states the
verdict is from the mock placeholder (structural test-linkage only), **not** real
verification — sourced from the AC-1 constant. `deepVerifyMeta`/SUMMARY still
records `provider: mock`.

### AC-3: `doctor` verification-readiness names the gap loudly and points to activate
On all-mock config, `cadence doctor`'s `verification-readiness` check (reusing the
v1.22 pure `assessReadiness` — not a fork) emits a `warning` using AC-1 wording
and points at `cadence activate`; best-effort, degrades to `ok` on error.

### AC-4: `init` nudges activation as the path to real verification
`cadence init` output surfaces `cadence activate` on its own dedicated "Turn on
real verification" line (Q2), naming the default `mock` a placeholder (AC-1
wording) — discoverable, not buried in the first-loop block.

### AC-5: Docs name mock as a placeholder, not a verifier
`README.md`, `docs/concepts.md`, `docs/providers.md`, and
`docs/reference/config.md` each frame `mock` as a deterministic, offline
**placeholder** / structural test-linkage check that is **not** real verification
— enforced by a pure doc-scan test (mirroring the doc-sync checker test).

## Boundaries

- **DO NOT** change `mock`'s status as the zero-config default or its
  deterministic, offline behavior — no config field renamed/removed.
- **DO NOT** make any surface refuse a settle or exit non-zero (warning-only —
  Q1 RESOLVED). A strict refuse-mock mode is out of scope.
- **DO NOT** break the `deepVerifyMeta`/SUMMARY `provider: mock` provenance in
  `packages/core/src/gates/deep-verify.ts` — it must still record the provider.
- **DO NOT** fork `assessReadiness` — reuse the v1.22 pure function.
- Tests must run fully offline — never depend on the `anthropic` or `local`
  providers.
- No new DESIGN.md D-number expected (deepens the verifier-provider model
  additively); confirm during BUILD and update D11-adjacent prose only if the
  framing changes.
