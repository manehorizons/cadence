# 104-104 — Make real verification the felt default

## Objective

Stop the wedge from diverging from the default experience: name the `mock`
verifier honestly as a structural test-linkage **placeholder** (not real
verification) everywhere a user meets it — at settle, in `doctor`, in
`quickstart`, at `init`, and in the docs — and nudge the operator toward
`cadence activate`, all from one shared source-of-truth message, without
breaking the zero-config offline default.

## Acceptance Criteria

### AC-1: One source-of-truth "mock ≠ real verification" message
Given the honesty wording is today scattered (the v1.14 mock-fallback banner, the
v1.22 all-mock `doctor`/`quickstart`/`config explain` warnings)
When a surface needs to tell the user that `mock` is not real verification
Then a single exported constant (in `cadence-types`, alongside `COMMAND_GUIDANCE`)
holds the canonical phrasing — naming `mock` a deterministic, offline structural
test-linkage **placeholder** that does **not** perform real verification — and
every surface in AC-2…AC-5 renders from it (no duplicated literals).

### AC-2: Settle states the verdict came from the mock placeholder
Given `verifier.provider` resolves to `mock` and a settle fires a verification
gate (`--deep` **or** gate-set membership, matching the v1.14 banner firing rule)
When the gate runs
Then the settle output explicitly states the verdict is from the mock placeholder
(structural test-linkage only), **not** real verification, sourced from the AC-1
constant — and the existing run-level `deepVerifyMeta`/SUMMARY provenance still
records `provider: mock`.

### AC-3: `doctor` verification-readiness names the gap loudly and points to activate
Given the active config uses `mock` for the deep-verify seam (all-mock)
When `cadence doctor` runs its `verification-readiness` check (reusing the v1.22
pure `assessReadiness` — not a fork)
Then it emits a `warning` whose message uses the AC-1 wording ("mock = not real
verification") and points at `cadence activate`; the check stays best-effort and
degrades to `ok` on any error.

### AC-4: `init` nudges activation as the path to real verification
Given a fresh `cadence init`
When init prints its onboarding output
Then it surfaces `cadence activate` as the recommended step to turn on real
verification, stating that the default `mock` is a placeholder (AC-1 wording) —
discoverable, not buried.

### AC-5: Docs name mock as a placeholder, not a verifier
Given `README.md`, `docs/concepts.md`, and `docs/reference/config.md` describe the
`mock` provider
When they introduce `mock`
Then each explicitly frames it as a deterministic, offline **placeholder** /
structural test-linkage check that is **not** real verification — enforced by a
doc-scan test (pure: *(doc text) → pass/fail*, in the spirit of the doc-sync
checker) so the framing can't silently rot.

## Constraints

- **Additive + backward-compatible.** `mock` stays the zero-config default and
  keeps its current deterministic, offline behavior; no config field is renamed
  or removed; no settle that passes today starts failing.
- **Warning-only, never a hard gate.** Surfacing "mock ≠ real verification" must
  not refuse a settle or exit non-zero — activation stays opt-in (see Open
  Question 1). This preserves the first-run / CI-offline experience.
- **mock stays test-safe.** Tests must never depend on `anthropic` or `local`;
  the new doc-scan + CLI-output assertions run fully offline.
- **One source of truth.** No duplicated message literals — AC-2…AC-5 import the
  AC-1 constant. Reuse the v1.22 `assessReadiness`; do not fork readiness logic.
- **DESIGN.md.** Expected to deepen the existing verifier-provider model
  additively (no new D-number); confirm during BUILD and update §/D11-adjacent
  prose if the framing changes.

## Open Questions

_All resolved at SPEC approval (2026-06-12); recorded here as locked decisions._

- **Q1 (scope-defining) — RESOLVED: warning-only.** The loud mock state is
  warning-only this phase; it never refuses a settle or exits non-zero. A strict
  refuse-mock mode (`settle --strict` / interactive confirm) is explicitly a
  separate, deferrable slice — out of scope for 104.
- **Q2 — RESOLVED: dedicated line.** The `init` activation nudge (AC-4) is its own
  "Turn on real verification" line, not folded into the phase-62 "Your first loop"
  block, so it survives independent edits to that block.
- **Q3 — RESOLVED: route through the constant.** `quickstart`'s existing v1.22
  all-mock warning is moved behind the AC-1 shared constant too, so all surfaces
  share one source of truth.
