# 127-01 — Add guided first-phase drafting

## Objective

Add `cadence draft new --brief "<what to build>"` so a new user can create a usable first DRAFT with Objective, Acceptance Criteria, Tasks, and Boundaries without hand-editing an empty template from scratch.

## Acceptance Criteria

### AC-1: brief seeds a usable DRAFT
Given an initialized CADENCE repo in IDLE
When the user runs `cadence draft new --title "Add greeting module" --brief "Add a greet(name) helper with one test"`
Then the created DRAFT contains a non-placeholder Objective, one structured AC, one T1 task, and a concrete Boundaries entry derived from the brief/title.

### AC-2: brief works with inferred phase ids
Given an initialized CADENCE repo in IDLE
When the user runs `cadence draft new --title "Add greeting module" --brief "Add a greet(name) helper with one test"` without positional phase arguments
Then CADENCE infers the next phase slug from the title and stores that phase/draft in state as today.

### AC-3: empty brief refuses before writes
Given an initialized CADENCE repo in IDLE
When the user runs `cadence draft new 127-guided-first-phase-drafting 01 --title "Empty" --brief "   "`
Then the command exits non-zero, prints an actionable error, and does not create a DRAFT file.

### AC-4: docs show the guided first-phase path
Given a new user reading quickstart or command reference docs
When they reach the draft step
Then they see `--brief` as the fast way to produce an editable first DRAFT, while the manual template path remains documented.

## Constraints

- Keep `draft new` behavior byte-compatible when `--brief` is absent.
- Do not add network calls, AI generation, or an interactive wizard in this slice.
- If an approved SPEC exists for the same id, existing SPEC seeding remains authoritative over `--brief`.

## Open Questions

- Should a future wizard prompt for multiple ACs/tasks interactively, or should it remain a deterministic `--brief` expansion?
