# 213-01 — Add test-coverage reporting with enforced minimum thresholds to CI

## Objective

Enforce a minimum test-coverage floor that actually gates `pnpm test` / CI,
so a coverage regression fails the build instead of passing silently.

## Acceptance Criteria

### AC-1: Coverage thresholds are wired into the command CI actually runs
Given `pnpm test` (`turbo run test` → each package's own `vitest run`)
currently collects no coverage and enforces no threshold
When `pnpm test` is run after this change
Then vitest collects coverage for each package's `src/**` and exits non-zero
if measured coverage drops below the configured threshold.

### AC-2: Thresholds reflect measured coverage, not a guess
Given thresholds must not turn CI red the moment this change merges
When the thresholds are chosen
Then they are derived from each package's actual measured coverage at time
of writing, with a small safety margin below current, and the derivation is
recorded (PR description / changeset), not hardcoded from assumption.

### AC-3: The existing dead root-level coverage block is reconciled, not duplicated
Given root `vitest.config.ts` already declares a `coverage.reporter`/`include`
block that no per-package CI test run actually exercises
When the fix lands
Then there is exactly one source of truth for coverage config, following the
`vitest.shared.ts` single-source-of-truth pattern already used for
timeouts/pool options — the stale root-only block is removed or folded in.

## Tasks

### T1: Measure current per-package coverage and add the coverage provider
- files: `package.json`, `pnpm-lock.yaml`
- action: add `@vitest/coverage-v8` as a workspace devDependency (matching
  where `vitest` itself is already declared); run `vitest run --coverage`
  per package to record each package's actual current line/branch coverage
  (no config changes yet — this is a measurement pass)
- verify: `pnpm install` succeeds; recorded coverage numbers exist for every
  package with a `tests/` dir (paste into the task/PR notes)
- done: AC-2

### T2: Wire enforced thresholds into the single source of truth
- files: `vitest.shared.ts`, `vitest.config.ts`
- action: add `test.coverage` (provider `v8`, `include: ['src/**']`,
  `thresholds: { ... }`) to `vitest.shared.ts` so every package's
  `vitest.config.ts` inherits it via the existing `mergeConfig(shared, ...)`
  pattern; set each threshold below its T1-measured value with real
  headroom; remove or fold the now-redundant root-only `coverage` block in
  `vitest.config.ts` so there is exactly one coverage config, not two
- verify: `pnpm test` still passes (thresholds are below measured coverage,
  not above it)
- done: AC-1, AC-3
- depends: T1

### T3: Prove the gate actually fails on regression, then confirm it's green
- files: `packages/core/tests/**` (temporary/scratch only, reverted before
  done)
- action: temporarily skip or gut an existing test (or otherwise drop
  measured coverage below the new threshold) and confirm `pnpm test` exits
  non-zero with a coverage-threshold failure message; revert the temporary
  change; run `pnpm test` clean and confirm it passes
- verify: both runs' actual output — the intentional failure and the
  clean pass — are captured, not asserted from memory
- done: AC-1
- depends: T2

## Boundaries

- DO NOT touch `packages/core/src/gates/engine.ts` or add a new CADENCE gate
  — this is CI/vitest-level enforcement, not a new quality gate in the
  DRAFT→BUILD→SETTLE loop.
- DO NOT modify the `typecheck`, `lint`, or `build` CI steps.
- DO NOT change test timeout/pool settings in `vitest.shared.ts` — coverage
  config only.
- DO NOT set any package's threshold above its actually-measured current
  coverage — this PR must not turn CI red.
