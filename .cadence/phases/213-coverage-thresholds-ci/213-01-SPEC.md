# 213-01 — Add test-coverage reporting with enforced minimum thresholds to CI

## Objective

Enforce a minimum test-coverage floor that actually gates `pnpm test` / CI, so
a coverage regression fails the build instead of passing silently.

## Acceptance Criteria

### AC-1: Coverage thresholds are wired into the command CI actually runs
Given `pnpm test` (`turbo run test` → each package's own `vitest run`)
currently collects no coverage and enforces no threshold
When `pnpm test` is run after this change
Then vitest collects coverage for each package's `src/**` and exits non-zero
if measured coverage drops below the configured threshold — demonstrated by
a scratch/temporary regression that intentionally drops coverage and confirms
the run fails, then is reverted.

### AC-2: Thresholds reflect measured coverage, not a guess
Given thresholds must not turn CI red the moment this change merges
When the thresholds are chosen
Then they are derived from each package's actual measured coverage at time
of writing (with a small safety margin below current), and the chosen
numbers + how they were derived are recorded in the PR description /
changeset — not hardcoded from assumption.

### AC-3: The existing dead root-level coverage block is reconciled, not duplicated
Given root `vitest.config.ts` already declares a `coverage.reporter`/`include`
block that no per-package CI test run actually exercises (each package runs
its own `vitest.config.ts`, not the root one)
When the fix lands
Then there is exactly one source of truth for coverage config, following the
existing `vitest.shared.ts` single-source-of-truth pattern used for
timeouts/pool options — the stale root-only block is removed or folded in,
not left as an orphaned second config.

## Constraints

- Follow the existing `vitest.shared.ts` single-source-of-truth convention
  (per CLAUDE.md Code conventions) rather than repeating coverage config in
  every package's `vitest.config.ts`.
- Leave real headroom below current coverage so ordinary unrelated PRs don't
  start failing CI on minor coverage churn.
- Any new coverage-provider package (e.g. `@vitest/coverage-v8`) is a
  devDependency only — does not touch the zero-runtime-dependency bias.
- `pnpm test` remains the single command CI and contributors run; do not
  rename or fork it into a separate coverage-only script.

## Boundaries

- Do NOT touch `packages/core/src/gates/engine.ts` or add a new CADENCE gate
  — this is CI/vitest-level enforcement, not a new quality gate in the
  DRAFT→BUILD→SETTLE loop.
- Do NOT modify the other CI steps (`typecheck`, `lint`, `build`) beyond
  whatever the `test` step needs.
- Do NOT change test timeout/pool settings in `vitest.shared.ts` — coverage
  config only.
