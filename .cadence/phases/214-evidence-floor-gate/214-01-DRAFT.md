# 214-01 — Minimum-evidence floor gate: refuse settle below a configured AC evidence level

## Objective

Add a configurable `gates.evidenceFloor` gate that refuses settle when any AC's PASS verdict rests on evidence below a per-preset floor, closing the enforcement gap in the visibility-only Phase 140 evidence ladder (`ai-verified` > `executed` > `assertion` > `mention` > `unverified`). Decided defaults (2026-07-24, superseding the original audit proposal after independent review found `mention` indefensible as any preset's default — see `ev-20260724-010` on rec-20260724-001): solo → `assertion`, team → `executed`, production → `executed` + a refusal/warning when the active verifier is not a real (non-mock) provider. `mention` remains reachable only via explicit config override or a named, per-AC, reason-required bypass recorded in `gateBypasses` — never as a preset default.

## Acceptance Criteria

### AC-1: Evidence floor refuses settle when an AC's evidence ranks below the configured floor
Given a phase with an effective `gates.evidenceFloor` (explicit config or preset default) and at least one AC whose `deriveAcEvidence` result ranks below that floor
When `cadence settle run --auto` is invoked
Then settle refuses, names the offending AC id(s) and their actual evidence level vs. the required floor, and does not record a passing SUMMARY for that AC

### AC-2: Per-preset defaults match the decided tiers
Given no explicit `gates.evidenceFloor` override in config
When the active preset is solo, team, or production
Then the effective floor is `assertion`, `executed`, or `executed` respectively

### AC-3: An `ai-verified` floor under the default mock provider fails loud and specific, not silently
Given `gates.evidenceFloor` is explicitly configured to `ai-verified` (only reachable via explicit override — no preset defaults to it) and the active deep-verify provider is `mock`
When settle evaluates the evidence-floor gate
Then the refusal names the structural reason (`ai-verified` evidence is unreachable under the mock provider per `deriveAcEvidence`'s existing mock exclusion) instead of a generic "AC below floor" message, so the operator isn't left guessing why every phase permanently refuses

### AC-4: Named per-AC bypass is possible and recorded
Given an operator genuinely needs to settle below the configured floor for one specific AC
When they invoke the bypass with a required reason for that AC
Then settle proceeds for that AC only, and the bypass (AC id + reason) is recorded in `SUMMARY.gateBypasses` — never a blanket, phase-wide bypass

## Boundaries

- Do NOT change `deriveAcEvidence`'s ranking or definitions (Phase 140) — this phase only consumes its output via a new gate.
- Do NOT retroactively re-evaluate already-settled phases against the new floor.
- Do NOT allow a blanket/phase-wide evidence-floor bypass — bypass must be per-AC with a required reason string.
- Do NOT touch `verifier-factory.ts`'s existing mock-fallback banner logic — separate concern already covered by phases 209-211.
