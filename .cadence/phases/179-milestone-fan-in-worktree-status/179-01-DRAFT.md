# 179-01 — Milestone fan-in: worktree status/reconciliation command

## Objective

Add `cadence milestone status <id>` — a read-only reconciliation command that
maps a milestone's converted recommendations to their phases, resolves each
phase's owning worktree (local or sibling) via phase 142's
`gatherHandoffCandidates`, and reports that worktree's live loop position —
replacing N manual `cadence status` round-trips with one. Fan-out (automated
worktree provisioning) stays out of scope (see SPEC).

## Acceptance Criteria

### AC-1: Reconciliation command reports live loop position per milestone phase
Given a milestone whose recommendations have been converted to phases
(`Recommendation.convertedToPhaseId` set), each phase currently active in a
local or sibling worktree
When the operator runs `cadence milestone status <id>`
Then it lists each of the milestone's phases with its owning worktree
(source `local`/`sibling`, path, branch) and that worktree's live loop
position, marking a phase `settled` when its `liveLoopPosition` is `IDLE`
and not settled otherwise — without the operator manually `cd`-ing into
each worktree.

### AC-2: Unconverted recs and missing worktrees are reported, not dropped
Given a milestone recommendation whose `convertedToPhaseId` is unset (never
turned into a phase), or a resolved phase with no matching local/sibling
worktree currently reporting it as `activePhase`
When `cadence milestone status <id>` runs
Then the recommendation/phase still appears in the output — marked
`not-yet-converted` or `no-worktree-found` respectively — rather than being
silently omitted; and `cadence milestone status <unknown-id>` refuses
(exit 1) with a clear "not found" message, matching the existing
`accept`/`defer`/`close` refusal shape.

### AC-3: Implementation is covered by tests
Given the feature implementation is complete
When `pnpm --filter @manehorizons/cadence-core test` runs
Then the resolution logic (converted + unconverted recs, matched +
unmatched phases, unknown milestone id) and the CLI wiring (text +
`--json`) are covered and passing.

## Boundaries

- DO NOT implement fan-out (automated `git worktree add` provisioning or
  `agent-prompt`-shaped prompt generation) — that is Option A from the
  source proposal, explicitly deferred to a future milestone.
- DO NOT add a `phaseIds` field to the `Milestone` schema — reuse the
  existing `recommendationIds` → `convertedToPhaseId` link; a schema change
  was considered and rejected during design (see SPEC).
- DO NOT write to `state.json`, transition the loop, or create/modify any
  worktree from this command — it is read-only.
- DO NOT touch `cadence doctor` — a milestone-scoped query doesn't fit its
  global/zero-arg check pattern (confirmed during design).
