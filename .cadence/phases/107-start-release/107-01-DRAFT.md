# 107-01 — release v1.26.0 (guided-onboarding · cadence start)

## Objective

Cut the v1.26.0 release for the `cadence start` guided-onboarding milestone:
document the command, record the milestone narrative, and bump all four
published packages `1.25.0 → 1.26.0` via a changeset with CLAUDE.md doc-sync.

## Acceptance Criteria

### AC-1: All four published packages bump to 1.26.0
Given the four published packages are at `1.25.0`
When a `minor` changeset listing all four is applied via `pnpm changeset version`
Then `core`, `types`, `host-claude-code`, and `host-codex` all read `1.26.0`.

### AC-2: CLAUDE.md narrates v1.26 and satisfies the doc-sync gate
Given the canonical version in `packages/core/package.json` changes to `1.26.0`
When CLAUDE.md is updated to lead with v1.26.0 (the `cadence start` guided-onboarding
milestone) and the new version string
Then `.githooks/check-doc-sync.sh` passes (CLAUDE.md mentions `1.26.0`).

### AC-3: `cadence start` is documented and the milestone is recorded
Given the release
When the docs + planning records are updated
Then `docs/reference/commands.md` documents `cadence start` (flags + routing),
the README points newcomers at it, and `.cadence/MILESTONES.md` + `.cadence/ROADMAP.md`
record v1.26.0 guided-onboarding.

## Tasks

### T1: Document `cadence start`
- files: `docs/reference/commands.md`, `README.md`, `docs/concepts.md`
- action: add a `cadence start` reference entry (flags `--pick`/`--yes`/`--json`,
  the six routes, non-TTY behavior); add a README quickstart line; add a concepts
  onboarding pointer iff an onboarding area exists.
- verify: `grep -q "cadence start" docs/reference/commands.md README.md`
- done: AC-3

### T2: Record the milestone narrative
- files: `.cadence/MILESTONES.md`, `.cadence/ROADMAP.md`
- action: add a §v1.26.0 guided-onboarding entry and the phases 105–107 roadmap line.
- verify: `grep -q "1.26.0" .cadence/MILESTONES.md`
- done: AC-3

### T3: Add the release changeset
- files: `.changeset/v1-26-0-cadence-start.md`
- action: write a changeset with `minor` bumps for all four published packages.
- verify: file lists all four packages at `minor`
- done: AC-1

### T4: Version the packages
- files: `packages/*/package.json`, `pnpm-lock.yaml`, `packages/*/CHANGELOG.md`
- action: run `pnpm changeset version`
- verify: `node -p "require('./packages/core/package.json').version"` → `1.26.0`
- done: AC-1

### T5: Update CLAUDE.md narrative + version
- files: `CLAUDE.md`
- action: lead the version narrative with v1.26.0 (cadence start guided-onboarding)
  and the `1.26.0` version string (doc-sync gate).
- verify: `bash .githooks/check-doc-sync.sh` passes; `grep -q 1.26.0 CLAUDE.md`
- done: AC-2

## Boundaries

- DO NOT trigger the manual `Release` workflow / publish to npm — user-triggered.
- DO NOT change any source under `packages/*/src/` — release is version + docs only.
- DO NOT bump `cadence-testkit` (private, unpublished).
