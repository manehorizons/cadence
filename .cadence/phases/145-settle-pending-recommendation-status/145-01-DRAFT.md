# 145-01 — settle-pending recommendation status

## Objective

When a phase with a converted-linked recommendation settles, transition that recommendation to a
new settle-pending status (visible, not archived) instead of silently archiving it; surface
pending-ship recommendations via cadence doctor and cadence progress.

## Acceptance Criteria

### AC-1: settle moves a converted rec to settle-pending, not archived
Given a `converted` recommendation whose `convertedToPhaseId` matches a phase
When that phase settles (`recommendations.autoArchive` on)
Then the recommendation's `status` becomes `settle-pending` and it is NOT present in `ledger.archived`

### AC-2: settle-pending -> shipped is the sanctioned promotion path
Given a recommendation with `status: 'settle-pending'`
When `applyRecommendationPromotion` is called with `{ status: 'shipped' }`
Then the promotion succeeds, and any other target status (or promoting directly TO settle-pending from any status) is refused

### AC-3: settle-pending is not a manual CLI promote target
Given any recommendation
When `cadence recommendation promote <id> --status settle-pending` is run
Then it is refused with an "invalid --status" error

### AC-4: doctor surfaces settle-pending drift
Given zero or more recommendations in `settle-pending`
When `cadence doctor` runs
Then it reports `ok` with none, or a `warning` naming each one's id, title, and phase, plus the exact promote command to run

### AC-5: progress surfaces a settle-pending note
Given one or more recommendations in `settle-pending`
When `cadence progress` runs (text or `--json`)
Then it prints an extra `Note:` line (or JSON `note` field) naming the count; it is omitted when there are none
