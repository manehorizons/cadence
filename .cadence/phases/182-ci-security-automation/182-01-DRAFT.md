# 182-01 — CI security automation

## Objective

Add the CI security automation layers confirmed missing by rec-20260712-013:
a CodeQL static-analysis workflow, a secret-scanning job, a documented npm
audit policy with an exceptions allowlist, SBOM + license-inventory
generation, and a scheduled (cron) run so these checks execute independent of
push/PR activity. Dependabot (`.github/dependabot.yml`) and npm
provenance/OIDC (`release.yml`) already exist and are out of scope here.

## Acceptance Criteria

### AC-1: CodeQL analysis runs on push, PR, and a weekly schedule
Given no `.github/workflows/codeql.yml` exists today
When the CodeQL workflow is added for the javascript-typescript language
Then it triggers on push to main, on pull_request, and on a weekly cron
schedule

### AC-2: Secret scanning runs on every push and pull request
Given no secret-scanning/gitleaks/trufflehog workflow exists today
When a secret-scanning job is added to a new consolidated security workflow
Then it scans the repository/diff for leaked credentials on push and
pull_request

### AC-3: npm audit policy fails CI on undocumented high/critical advisories
Given no documented audit policy or exceptions file exists today
When an audit job plus a `docs/security/audit-exceptions.md` allowlist
(advisory id, justification, expiry) is added
Then the job fails on a high/critical advisory that is not listed in the
exceptions file, and passes when every high/critical advisory present is
listed with a justification and an expiry date

### AC-4: SBOM and license inventory are generated and uploaded as artifacts
Given no SBOM/CycloneDX/SPDX generation exists anywhere in `.github/workflows`
When an SBOM job is added to the consolidated security workflow
Then it generates a CycloneDX SBOM and a license inventory and uploads both
as workflow artifacts

### AC-5: The security checks also run on a schedule independent of pushes
Given secret-scan, audit, and SBOM currently would only run on push/PR
When a weekly `schedule:` cron trigger is added to the consolidated security
workflow
Then secret-scan, audit, and SBOM all execute on that schedule as well as on
push/PR (CodeQL's own weekly schedule from AC-1 covers static analysis)

## Tasks

### T1: Add the CodeQL workflow
- files: `.github/workflows/codeql.yml`, `packages/core/tests/docs/security-ci.test.ts`
- action: add a CodeQL workflow analyzing the javascript-typescript language,
  triggered on push to main, pull_request, and a weekly `schedule:` cron;
  add an asserting test reading the workflow file and checking the language,
  triggers, and schedule
- verify: `pnpm --filter @manehorizons/cadence-core test -- security-ci`
- done: AC-1

### T2: Add the consolidated security workflow with secret scanning
- files: `.github/workflows/security.yml`, `packages/core/tests/docs/security-ci.test.ts`
- action: create `security.yml` with a secret-scanning job (gitleaks) and
  triggers for push to main, pull_request, and a weekly `schedule:` cron;
  extend the test file with asserting checks for the job and triggers
- verify: `pnpm --filter @manehorizons/cadence-core test -- security-ci`
- done: AC-2, AC-5
- depends: T1

### T3: Add the npm audit policy and exceptions file
- files: `.github/workflows/security.yml`, `docs/security/audit-exceptions.md`, `scripts/check-audit-exceptions.mjs`, `packages/core/tests/docs/security-ci.test.ts`
- action: add an audit job (`pnpm audit --audit-level=high` or equivalent)
  to `security.yml` that cross-checks findings against a new
  `docs/security/audit-exceptions.md` allowlist (columns: advisory id,
  package, justification, expiry date) and fails on any high/critical
  advisory not listed or past its expiry; extend the tests. As-built note:
  `pnpm audit` under this repo's pinned pnpm@9.12.0 hits npm's retired
  legacy audit endpoint (410 Gone — pnpm/pnpm#11265), so the cross-check
  needed a dedicated script (`scripts/check-audit-exceptions.mjs`) that
  runs the audit via a pinned modern pnpm (corepack + Node 22), not a plain
  inline workflow step — this file was not anticipated when T3 was drafted.
- verify: `pnpm --filter @manehorizons/cadence-core test -- security-ci`
- done: AC-3
- depends: T2

### T4: Add SBOM + license inventory generation
- files: `.github/workflows/security.yml`, `packages/core/tests/docs/security-ci.test.ts`
- action: add a job to `security.yml` generating a CycloneDX SBOM and a
  license inventory, uploaded via `actions/upload-artifact`; extend the tests
- verify: `pnpm --filter @manehorizons/cadence-core test -- security-ci`
- done: AC-4
- depends: T3

## Boundaries

- DO NOT modify `.github/workflows/ci.yml` or `release.yml`.
- DO NOT modify `.github/dependabot.yml` — Dependabot coverage is already
  confirmed sufficient by the source recommendation's evidence.
- DO NOT attempt to toggle GitHub's repo-setting-level "secret scanning" /
  "push protection" UI features from code — those are account/plan-gated
  admin settings, not something a workflow file can enable. A gitleaks-based
  scanning job is the in-repo equivalent and satisfies AC-2.
- DO NOT add SBOM signing/attestation or publish the SBOM externally —
  artifact upload only, out of scope for this phase.
- DO NOT add new runtime dependencies to any published package; security
  tooling (gitleaks action, cyclonedx generator, etc.) runs only inside
  GitHub Actions steps.
