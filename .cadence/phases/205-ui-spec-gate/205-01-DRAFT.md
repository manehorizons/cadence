# 205-01 — UI-SPEC gate (spec new --ui / ui-spec-review)

## Objective

Add an opt-in UI-SPEC.md artifact and ui-spec-review gate to CADENCE's existing SPEC stage so a UI-heavy phase can lock down concrete per-component layout/token/responsive detail before DRAFT tasks are written, closing rec-20260711-004.

## Acceptance Criteria

### AC-1: spec new --ui scaffolds both files
Given a slice at loopPosition SPEC or about to enter it
When cadence spec new is run with --ui
Then both id-SPEC.md and id-UI-SPEC.md are scaffolded, the latter with the fixed Components/Layout and Tokens/Precedent References/Responsive and Interaction shape and status PENDING

### AC-2: spec approve unchanged with no UI-SPEC
Given a slice with only id-SPEC.md present
When cadence spec approve is run
Then behavior is byte-identical to today: no ui-spec-review runs and no id-UI-SPEC-REVIEW.json sidecar is written

### AC-3: ui-spec-review flags an under-specified component
Given a slice with id-UI-SPEC.md present whose only content for a component is a Precedent Reference with an empty Layout and Tokens list
When cadence spec approve runs ui-spec-review after spec-review passes
Then the gate fails with a HIGH finding naming that specific component

### AC-4: spec-review and ui-spec-review reachable control-flow cells
Given a slice with both SPEC.md and UI-SPEC.md present
When spec-review fails un-bypassed, or passes with ui-spec-review failing, or spec-review is bypassed with ui-spec-review failing, or both are bypassed
Then spec approve refuses in the first three cases (ui-spec-review never even runs in the first) and proceeds to APPROVED only in the fourth

### AC-5: ui-spec-review convergence and escalation
Given ui-spec-review keeps failing across repeated spec approve attempts
When attempts reach config.convergence.maxAttempts
Then the gate hard-escalates with an unconditional ui-spec-review-unconverged anomaly and spec approve refuses unless --allow-ui-spec-review-failure is passed

### AC-6: draft new seeds a UI Contract section
Given a slice with an APPROVED sibling id-UI-SPEC.md
When cadence draft new scaffolds the DRAFT
Then a UI Contract section using bold text not nested headings is inserted between Acceptance Criteria and Tasks, and parseDraftMd still extracts Objective/Acceptance Criteria/Tasks/Boundaries identically to a DRAFT with no UI Contract

### AC-7: draft new skips UI Contract when UI-SPEC not approved
Given a slice with a present but PENDING id-UI-SPEC.md
When cadence draft new scaffolds the DRAFT
Then the DRAFT is scaffolded without a UI Contract section and a non-fatal stderr notice is printed

### AC-8: spec new --ui clobber guard
Given id-UI-SPEC.md already exists on disk
When cadence spec new --ui is re-run for the same id
Then the command refuses with a nonzero exit and does not overwrite the existing file

### AC-9: orphaned sidecar quiet-fallback guard
Given id-UI-SPEC-REVIEW.json exists but id-UI-SPEC.md does not
When cadence spec approve is run
Then a loud stderr notice is printed identifying the skip and spec approve proceeds using spec-review's result alone, never silently
