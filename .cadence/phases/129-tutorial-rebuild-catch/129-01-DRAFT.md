# 129-01 — Rebuild tutorial around the catch (refuse→fix→pass)

## Objective

Rebuild `cadence tutorial` so it stages a lie, lets settle catch it (refusing to
close because no real test backs AC-1), then fixes it and genuinely passes —
making the refusal the demo's money moment, with zero engine changes.

## Acceptance Criteria

### AC-1: settle refuses the unbacked claim, naming AC-1
Given a sandbox where T1 is marked DONE and `sum.mjs` exists but no test references AC-1
When the tutorial runs `cadence settle run --auto` (attempt 1)
Then settle exits non-zero, the `test-coverage` gate prints a reason naming AC-1, and the loop stays in BUILD (nothing settled).

### AC-2: the pass is backed by a real executed test
Given the tutorial then writes a real `sum.test.mjs` referencing AC-1
When it runs `cadence settle run --auto` (attempt 2)
Then `build-test-must-pass` executes `node --test` (real exit 0), `test-coverage` passes, the loop reaches IDLE and a SUMMARY is written — and a failing or absent test would instead refuse.

### AC-3: no manual assertion or coverage bypass anywhere in the tutorial path
Given the rebuilt tutorial source, its sandbox config, and its docs/copy
When the path is inspected
Then it contains no `--ac` manual AC assertion and no `allowMissingCoverage`/`--allow-missing-coverage` bypass.

### AC-4: the refusal is visually distinct and unmistakable
Given attempt 1 refuses
When the user reads the output
Then the refusal is rendered as a distinct block (not styled like the pass), echoes the AC-1 reason line, and states explicitly that the loop will not close.

### AC-5: the sandbox is ephemeral, isolated, and offline
Given any tutorial run (including one where a step throws)
When the run finishes
Then the temp sandbox is removed, the user's cwd is never scaffolded, and the run completes deterministically with no ANTHROPIC_API_KEY set.
