# 276-01 — Pre-phase-102 recommendation archive backfill

## Objective

Backfill the pre-phase-102 recommendations that already carry terminal status into the archived bucket via the existing CLI (zero new code), and record the archiveReason-fidelity decision for the backfill.

## Acceptance Criteria

### AC-1: Discrepancy verification
Given the 22 candidates named by CMD-1 (terminal status still in the active recommendations array)
When each is independently verified against its phase directory and SUMMARY.json for status/shippedRef/convertedToPhaseId consistency
Then any record whose evidence does not hold up is excluded from the archive action and documented as a discrepancy instead of being archived

### AC-2: Backfill archived, invariant restored for the clean subset
Given the verified-clean subset of the 22 candidates
When each is archived via the existing cadence recommendation archive command
Then CMD-1's terminal-but-unarchived count drops to exactly the count of documented exceptions, and archived[] grows by exactly the number archived

### AC-3: Evidence preserved verbatim through the move
Given three sampled records archived during the backfill
When their pre- and post-move ledger entries are compared
Then status, shippedRef, and convertedToPhaseId are byte-identical

### AC-4: Open population unaffected
Given the pre-backfill CMD-2 baseline (open 78, medium 38 low 31 high 9)
When CMD-2 is re-run after the backfill
Then the open count and priority split are unchanged

### AC-5: Archive-reason fidelity decision recorded
Given D-M's choice between accepting archiveReason=manual, adding a --reason flag, or accepting manual with a recorded decision
When the backfill runs
Then a decision is recorded choosing one option, referenced by id
