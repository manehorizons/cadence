# 260-01 — vitest 2->4 major upgrade

## Objective

Upgrade `vitest` from `2.1.9` to `^4.1.10` (the proven-sufficient floor, not
the `>=3.2.6` advisory floor) across the root workspace, all six
`packages/*` workspaces, and `website/`, fixing the two known Vitest-4
breakages along the way, so the three deferred audit exceptions
(`docs/security/audit-exceptions.md`: vitest, vite, postcss) can be removed
and dependabot PRs #370/#244 (which only reach `3.2.6` and are both CI-red)
can be closed as superseded.

## Acceptance Criteria

### AC-1: vitest and its vite floor resolve to a single instance via proper overrides
Given the root `package.json` and all six `packages/*/package.json` plus
`website/package.json` declare `vitest ^4.1.10`
When `pnpm install` resolves `pnpm-lock.yaml`
Then exactly one `vitest@4.x` instance and one `vite@7.x`-or-later instance
are resolved repo-wide, enforced via a `pnpm.overrides` entry (the mechanism
phase 253 proved works) for the `vite` transitive floor — not a direct
`vite` devDependency added to root `package.json` (the workaround PR #235
used and that phase 253/`audit-exceptions.md` explicitly reject) — and
`scripts/check-lockfile-overrides.mjs`'s drift detector passes.

### AC-2: vitest.shared.ts uses Vitest 4's flattened pool config
Given `vitest.shared.ts` currently sets
`poolOptions: { forks: { minForks: 1, maxForks: 12 } }`
When the upgrade lands
Then it is replaced with Vitest 4's flattened top-level `maxWorkers: 12`
(pool rework — `poolOptions.<pool>.{minForks,maxForks}` no longer exists),
preserving the existing 12-worker CI cap and the timeout/coverage config
already in that file unchanged.

### AC-3: constructor-style vi.fn() mocks use function expressions, not arrows
Given `packages/core/tests/cli/hook.test.ts` mocks `HookDispatcher` via
`vi.fn().mockImplementation(() => ({ dispatch: dispatchSpy }))`, which Vitest
4 rejects (arrow functions can never satisfy `new`, and Vitest 4 tightened
constructor-mock semantics to real JS rules)
When the upgrade lands
Then that mock (and any other constructor-style `vi.fn().mockImplementation`
mock found by a repo-wide grep across all six `packages/*` — including
`host-toolkit`, which did not exist when reference PR #235 was written) uses
a real `function` expression, and the affected test(s) pass.

### AC-4: full CI pipeline is green on all three OSes at the new version
Given `vitest ^4.1.10` is installed everywhere
When `pnpm turbo run lint typecheck test build` runs
Then it exits 0 locally and the `ci.yml` matrix (ubuntu-latest, macos-latest,
windows-latest × Node 22) is green on the phase's PR, with no test
regressions vs. the pre-upgrade baseline (same pass/fail set minus the two
known breakages above, which are fixed rather than skipped).

### AC-5: the three deferred audit exceptions are removed as resolved
Given `docs/security/audit-exceptions.md`'s "Exceptions" table currently
carries three rows tracing to this upgrade (`GHSA-5xrq-8626-4rwp` vitest,
`GHSA-fx2h-pf6j-xcff` vite, `GHSA-r28c-9q8g-f849` postcss, all expiring
2026-11-02) plus the "Deferred: vitest major-version upgrade" section
explaining why they were deferred
When `scripts/check-audit-exceptions.mjs`'s audit is re-run post-upgrade
Then none of the three advisory IDs are reported (confirmed, not assumed),
and both the three table rows and the "Deferred" section are removed from
`docs/security/audit-exceptions.md`.

### AC-6: dependabot PRs #370 and #244 are closed as superseded
Given #370 and #244 both only bump `vitest` to `3.2.6` (a floor
`audit-exceptions.md` already proved insufficient for the vite/postcss
chain) and are both CI-red
When this phase's PR merges
Then #370 and #244 are closed with a comment pointing to this phase's PR as
the real fix.

## Constraints

- Do not reopen, cherry-pick, or rebase closed PR #235
(`chore/security-vitest-and-transitive-bump`); its version targets and the
two concrete breakage fixes (AC-2, AC-3) are valid reference evidence
(already extracted into this SPEC), but its vite-as-direct-devDependency
workaround must **not** be reused — replace it with a `pnpm.overrides` entry
per AC-1.
- `website/` is a separate pnpm workspace/lockfile
(`website/pnpm-workspace.yaml`) already running `vitest ^4.1.8` successfully
— only bump its floor to `^4.1.10` for consistency; do not touch its
`astro`/`typedoc`/other dependency versions as part of this phase (out of
scope; those are tracked by the website-lockfile-audit-gap recommendation,
not this one).
- Dependency/config/test-fixture changes only. No unrelated refactors, no
speculative fixes for breakage that a repo-wide grep + full test run doesn't
actually surface.
- Single-commit settle: source + tests + docs + phase artifacts land
together, per house convention.
