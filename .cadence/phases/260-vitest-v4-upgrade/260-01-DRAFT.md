# 260-01 — vitest 2->4 major upgrade

## Objective

Upgrade vitest 2.1.9 -> ^4.1.10 (proven-sufficient floor per docs/security/audit-exceptions.md, not the >=3.2.6 advisory floor) across root + all 6 packages/* workspaces + website, fixing the two known Vitest-4 breakages, closing the 3 deferred audit exceptions, and superseding dependabot PRs #370/#244.

## Acceptance Criteria

### AC-1: vitest and its vite floor resolve to a single instance via proper overrides
Given root package.json and all 6 packages/*/package.json plus website/package.json declare vitest ^4.1.10
When pnpm install resolves pnpm-lock.yaml
Then exactly one vitest@4.x instance and one vite@7.x-or-later instance are resolved repo-wide, enforced via a pnpm.overrides entry for the vite transitive floor (not a direct vite devDependency), and scripts/check-lockfile-overrides.mjs's drift detector passes

### AC-2: vitest.shared.ts uses Vitest 4's flattened pool config
Given vitest.shared.ts currently sets poolOptions: { forks: { minForks: 1, maxForks: 12 } }
When the upgrade lands
Then it is replaced with Vitest 4's flattened top-level maxWorkers: 12, preserving the existing 12-worker cap and the rest of the file unchanged

### AC-3: constructor-style vi.fn() mocks use function expressions, not arrows
Given packages/core/tests/cli/hook.test.ts mocks HookDispatcher via an arrow-function mockImplementation, which Vitest 4 rejects for constructor use
When the upgrade lands
Then that mock and any other constructor-style vi.fn().mockImplementation mock found by a repo-wide grep (including host-toolkit) use a real function expression, and the affected tests pass

### AC-4: full CI pipeline is green on all three OSes at the new version
Given vitest ^4.1.10 is installed everywhere
When pnpm turbo run lint typecheck test build runs
Then it exits 0 locally and the ci.yml matrix (ubuntu/macos/windows-latest x Node 22) is green on the phase's PR, with no test regressions vs. the pre-upgrade baseline

### AC-5: the three deferred audit exceptions are removed as resolved
Given docs/security/audit-exceptions.md carries 3 rows (vitest/vite/postcss GHSA ids) plus a Deferred section explaining why they were deferred
When scripts/check-audit-exceptions.mjs's audit is re-run post-upgrade
Then none of the 3 advisory IDs are reported, and both the 3 rows and the Deferred section are removed from docs/security/audit-exceptions.md

## As-built amendment (2026-08-07)

The original DRAFT gated closing dependabot PRs #370/#244 behind a 6th AC
(AC-6) with an explicit `When this phase's PR merges` precondition. That
precondition cannot be satisfied at settle time -- settle happens *before*
this phase's own PR even exists, let alone merges -- so AC-6 could never
honestly be marked pass during this phase's own settle. Modeling it as a
gated AC was a DRAFT authoring mistake, caught before settle rather than
worked around with a premature pass. Demoted to a non-gated post-merge
follow-up (T6 below, `done:` no longer maps to an AC) rather than removed
outright, since the work itself is still real and still owed. Settling this
phase requires `--allow-open-tasks` for T6's PENDING status, with this note
as the recorded reason.
