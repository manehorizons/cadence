# 238-01 — Drop Node 20 support; raise engine floor to Node >=22

## Objective

Retire the Node 20 CI leg and the engines.node floor across all five published packages plus host-toolkit, landing before Phase 0's kernel/assurance work begins as unrelated pre-staging work. Raise the floor to Node >=22 in CI, package.json engines fields, the node-guard runtime check, @types/node, dependabot's ignore rule, and current-state docs — without touching frozen historical records (CHANGELOG.md, ROADMAP.md/MILESTONES.md, past phase artifacts).

## Acceptance Criteria



### AC-1: CI runs only Node 22
Given the CI workflow matrix currently tests Node 20 and 22 across ubuntu/macos/windows
When the matrix is collapsed to Node 22 only
Then all three OS legs still run and the required ci-success check still passes

### AC-2: engines.node floor raised, changeset filed
Given all six package.json files declare engines.node >=20
When the floor is raised to >=22
Then all six read >=22 and a changeset documents the breaking-change semver call

### AC-3: node-guard reflects the new floor
Given checkNodeMajor defaults to min=20 with tests asserting the Node-20 floor
When the default and its tests are updated
Then checkNodeMajor defaults to min=22 and its test assertions/descriptions match

### AC-4: dependabot ignore rule matches the new floor
Given dependabot.yml's @types/node major-bump ignore rule and comment cite the Node-20 floor as their rationale
When the floor moves to Node 22
Then the rule and its comment are reworded to match, and root @types/node is bumped toward the Node-22 line

### AC-5: current-state docs no longer say Node 20
Given CLAUDE.md, README.md, and website/src/content/docs/start/install.md say Node 20 + 22
When the manual doc-prose sweep runs, since no doc test gates this string
Then those current-state docs read Node 22 only, while CHANGELOG.md, ROADMAP.md/MILESTONES.md, and past phase artifacts are left untouched

### AC-6: full verification green
Given all the above changes are applied
When pnpm turbo run lint typecheck test build runs
Then it passes clean

### AC-7: doctor's node-floor reporting and fixtures reflect the new floor
Given doctor/run.ts hardcodes >=20 in two user-facing messages, and six test fixtures hardcode nodeVersion v20.11.0 as their healthy baseline, both now stale after T3 raised the floor to 22
When the messages are updated to reflect the real floor and the fixtures are bumped to a Node >=22 value
Then cadence doctor reports the correct >=22 floor and the previously-passing tests in those six files pass again

### AC-8: whole-branch review completeness: repo-wide sweep
Given the whole-branch review found five more current-state docs (README.md's own second mention, docs/cli.md, docs/quickstart.md, packages/core/README.md, docs/reference/commands.md) plus a stale rationale comment in scripts/check-audit-exceptions.mjs that the original T5 file list missed
When a repo-wide grep-based sweep (excluding frozen historical records) is run and each finding fixed
Then no current-state file references the Node 20 floor, and CHANGELOG.md/ROADMAP.md/MILESTONES.md/past phase artifacts remain untouched
