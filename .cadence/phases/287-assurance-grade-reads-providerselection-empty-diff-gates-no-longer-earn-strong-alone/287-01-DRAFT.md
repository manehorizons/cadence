# 287-01 — Assurance grade reads providerSelection: empty-diff gates no longer earn strong alone

## Objective

Fix deriveAssuranceRecord so a settle whose only non-mock verifier signal is providerSelection:'empty-diff' -- a provider call that structurally could not judge anything because its diff was empty -- cannot earn assurance.overall:'strong' alone, while a settle with a genuinely-configured non-mock gate present alongside an empty-diff one still can. Closes the gap between phase 263 (gates learned to tag empty-diff) and phase 283 (the grade learned to read bypasses) that HANDOFF-verifier-honesty-verify-premises.md identified and AC-J3 proved real via a direct fixture call to deriveAssuranceRecord.

## Acceptance Criteria

### AC-1: an all-empty-diff settle no longer grades strong
Given gate provenance where every non-mock gate entry carries `providerSelection:'empty-diff'`, and AC evidence would otherwise clear the `strong` threshold (>=50% `ai-verified`/`executed`)
When `deriveAssuranceRecord` derives the record
Then `overall` is not `'strong'`

### AC-2: a mixed set is not punished
Given gate provenance with one providerSelection:'empty-diff' gate and one genuinely providerSelection:'configured' (or untagged) non-mock gate, alongside AC evidence clearing the strong threshold
When deriveAssuranceRecord derives the record
Then overall can still reach 'strong' on the configured gate's evidence -- the empty-diff gate does not drag it down

### AC-3: byte-identical for provenance with no providerSelection at all
Given gate provenance carrying no providerSelection field anywhere (the historical majority), captured as a pre-change fixture
When deriveAssuranceRecord derives the record before and after this phase's change
Then the output (verifierRollup, evidenceTally, overall) is byte-identical

### AC-4: stays pure and gate-agnostic
Given the dec-20260728-001 gate-agnostic tripwire test (deriveAssuranceRecord never reads gate.gate)
When this phase's change lands
Then the tripwire test passes unmodified, deriveAssuranceRecord remains a pure function of its arguments with no gate-name branching, and the new predicate is itself gate-agnostic (two gate sets identical except .gate must produce byte-identical results)

### AC-5: zero grade changes across the historical corpus
Given the full corpus of .cadence/phases/**/*-SUMMARY.json records
When the fix is applied and the existing corpus-drift test (tests/gates/assurance-record-corpus.test.ts, phase 283-01/AC-5) is re-run
Then it reports 0 new drift beyond its committed whitelist, and no SUMMARY.json file is modified
