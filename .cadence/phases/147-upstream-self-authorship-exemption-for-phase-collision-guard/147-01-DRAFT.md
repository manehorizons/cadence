# 147-01 — Upstream self-authorship exemption for phase-collision guard

Source: GitHub issue #129. Design doc:
`docs/superpowers/specs/2026-07-03-upstream-self-collision-design.md` (local
scratch, gitignored — not in the repo history).

## Objective

The phase-collision guard (`packages/core/src/phases/collision.ts` +
`occupancy.ts`) matches purely on the leading numeric token of a phase
directory name. Once a phase's SPEC/DRAFT is committed and pushed,
`origin/<integrationRef>` carries the same phase directory, so the very next
`spec new`/`draft new`/`settle run` for that same phase sees its own,
already-pushed work reflected back as an `upstream` conflict and refuses.
Fix: exempt an `upstream` occupancy from conflicting only when its full
directory name (number + slug) exactly matches a `local` occupancy's name at
the same number — this preserves the guard's actual guarantee (two genuinely
different phases can't silently share a number) instead of blanket-exempting
upstream whenever local owns the number. Scope is upstream-only; sibling
matching is intentionally untouched (see design doc's Scope decision).

## Acceptance Criteria

### AC-1: exact-slug self-match exempts upstream
Given a local occupancy named `30-auth` at number 30 and an `upstream`
occupancy also named `30-auth` at number 30
When `detectPhaseCollision(30, occupancies)` runs
Then the upstream occupancy is NOT included in `conflicts`

### AC-2: same-number different-slug upstream still conflicts
Given a local occupancy named `30-auth` at number 30 and an `upstream`
occupancy named `30-cache` (a different, foreign phase) also at number 30
When `detectPhaseCollision(30, occupancies)` runs
Then the upstream occupancy IS included in `conflicts`

### AC-3: sibling matching is unchanged
Given a `sibling` occupancy at the same number and same name as a local
occupancy
When `detectPhaseCollision` runs
Then the sibling occupancy is still reported as a conflict (no exemption
applied to the `sibling` source)

### AC-4: full directory name is threaded through occupancy gathering
Given local, sibling, and upstream phase directories on disk / origin
When `gatherOccupancy` runs
Then every returned `Occupancy` carries its full directory `name` (not just
the parsed leading number) for all three sources

### AC-5: the issue's exact repro no longer refuses
Given a phase SPEC is created locally, approved, committed, and pushed to
`origin/<integrationRef>`
When `draft new` (or `settle run`) is run afterward for that same phase
Then the phase-collision guard does not refuse, and a genuinely different
upstream phase at the same number still does refuse

## Boundaries

- DO NOT apply the self-match exemption to the `sibling` source (out of scope
  per the design doc's Scope decision — file a separate issue/phase if that's
  wanted later).
- DO NOT change `nextFree` numbering logic (locked, DESIGN.md §13).
- DO NOT change the three call sites (`spec-new.ts`, `draft-new.ts`,
  `settle.ts`) — the fix must live entirely in `collision.ts`/`occupancy.ts`
  so all call sites inherit it without modification.
- DO NOT weaken or remove existing collision-guard tests to make new ones pass.
