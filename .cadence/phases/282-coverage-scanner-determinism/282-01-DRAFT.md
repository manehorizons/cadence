# 282-01 — Coverage scanner determinism

## Objective

Make the coverage scanner (`packages/core/src/verify/coverage.ts`) return the
same answer for the same input every time, fix the per-file dedup so a
qualifying occurrence is never shadowed by an earlier non-qualifying one, and
make `verify coverage --explain` agree with the gate it explains — reproducing
the reported non-determinism empirically before any fix is written.

## Acceptance Criteria

### AC-1: Dedup ordering fix — a qualifying occurrence is never shadowed (D-O, option 1)
Given a fixture file where an AC token appears in a `describe()` title (or a comment, outside any asserting span) before it appears in ≥1 qualifying `it()`/`test()` block later in the same file — built and proven to fail against the pre-fix scanner before the fix is written
When `scanTestCoverage` scans that file in assertion mode after the fix
Then the qualifying `it()`/`test()` occurrence displaces the earlier non-qualifying occurrence for the same `(id, file)` slot, the recorded entry is `qualifying: true`, and mention mode's mirrored dedup (~coverage.ts 177-179) receives the same treatment or this SPEC's Constraints record why not.

### AC-2: Cross-file walk-order determinism
Given a multi-file fixture with no code changes between runs — proven to produce a non-deep-equal map across repeated runs against the pre-fix scanner before the fix is written
When `scanTestCoverage` runs 10 consecutive times against that identical fixture after the fix (sorting `listAllFiles`'s output)
Then the returned map is deep-equal, including array order, across all 10 runs.

### AC-3: Reconcile `--explain` with the gate
Given any fixture exercising both paths
When `explainAcCoverage` and the real `test-coverage` gate evaluate the same AC
Then their satisfied/refused verdicts agree — proved by a shared fixture, not by inspection.

### AC-4: Corpus impact, enumerated not absorbed
Given the full historical `.cadence/phases/**` corpus (293 SUMMARY records at time of writing)
When `cadence summary verify-all` runs after AC-1/AC-2/AC-3 land
Then it passes, and any phase whose coverage verdict changed as a result of the fix is enumerated by phase id in the settle summary — never silently absorbed.

**As-built amendment (T1, per AC-1's Then-clause disjunction — reviewer-flagged):** mention mode's mirrored per-file dedup (`coverage.ts`'s `seenInFile` loop) did **not** receive the qualifying-displaces-non-qualifying treatment. This is deliberate: mention-mode `TestRef`s carry no `qualifying`/`skipped` concept at all (`TestRef`'s own JSDoc: those fields are "assertion mode only"), and `weaklyLinkedAcs`/`skippedOnlyLinkedAcs` — the only consumers that branch on `qualifying` — can never fire when it's `undefined`. A mention-mode AC's verdict is decided solely by `uncoveredAcs`'s `refs.length === 0` check, so which specific same-file occurrence gets recorded is cosmetic display detail only, never a verdict difference. Do NOT retrofit this fix onto mention mode — there is no bug there to fix.

**As-built amendment (T2, per independent-reviewer finding — corrects AC-2's Given/action wording):** AC-2 and T2's `action:` claimed the pre-fix scanner would produce "a non-deep-equal map across repeated runs" / array order that "varies run-to-run." Independent reproduction (reverting the fix, running the fixture 10× in-process) showed this is not what actually happens: `readdir` on an unmutated directory returns a stable order *within a single process* — all 10 pre-fix runs returned the identical (but reversed-from-canonical) `[gamma, beta, alpha]` order, so a naive mutual 10-run deep-equal loop passes vacuously even on unfixed code. The real, demonstrated defect is that `listAllFiles`'s pre-fix order is an artifact of unsorted `readdir` + LIFO-stack DFS traversal — deterministic-per-process but not canonical, and with no cross-process/cross-filesystem stability guarantee — not observable run-to-run variance within one test invocation. `coverage-determinism.test.ts`'s pinned-order assertion (asserting the exact `[alpha, beta, gamma]` order, not just mutual equality across 10 runs) is what actually catches the defect, and is a stronger, more honest regression guard than AC-2's literal wording asked for. The fix itself (sort `listAllFiles`'s output) is correct and root-cause regardless of this wording correction.
