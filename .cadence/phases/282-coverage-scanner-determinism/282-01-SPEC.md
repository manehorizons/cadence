# 282-01 — Coverage scanner determinism

## Objective

Make the coverage scanner (`packages/core/src/verify/coverage.ts`) return the
same answer for the same input every time, fix the per-file dedup so a
qualifying occurrence is never shadowed by an earlier non-qualifying one, and
make `verify coverage --explain` agree with the gate it explains — reproducing
the reported non-determinism empirically before any fix is written.

## Acceptance Criteria

### AC-1: Dedup ordering fix — a qualifying occurrence is never shadowed (D-O, option 1)
Given a fixture file where an AC token appears in a `describe()` title (or a comment, outside any asserting span) before it appears in ≥1 qualifying `it()`/`test()` block later in the same file — built and proven to fail against the pre-fix scanner before the fix is written
When `scanTestCoverage` scans that file in assertion mode after the fix
Then the qualifying `it()`/`test()` occurrence displaces the earlier non-qualifying occurrence for the same `(id, file)` slot, the recorded entry is `qualifying: true`, and mention mode's mirrored dedup (~coverage.ts 177-179) receives the same treatment or this SPEC's Constraints record why not.

### AC-2: Cross-file walk-order determinism
Given a multi-file fixture with no code changes between runs — proven to produce a non-deep-equal map across repeated runs against the pre-fix scanner before the fix is written
When `scanTestCoverage` runs 10 consecutive times against that identical fixture after the fix (sorting `listAllFiles`'s output)
Then the returned map is deep-equal, including array order, across all 10 runs.

### AC-3: Reconcile `--explain` with the gate
Given any fixture exercising both paths
When `explainAcCoverage` and the real `test-coverage` gate evaluate the same AC
Then their satisfied/refused verdicts agree — proved by a shared fixture, not by inspection.

### AC-4: Corpus impact, enumerated not absorbed
Given the full historical `.cadence/phases/**` corpus (293 SUMMARY records at time of writing)
When `cadence summary verify-all` runs after AC-1/AC-2/AC-3 land
Then it passes, and any phase whose coverage verdict changed as a result of the fix is enumerated by phase id in the settle summary — never silently absorbed.

## Constraints

- **Two independent defects, not one** (established by code reading + AC-1/
  AC-2's reproduction, corrects the source plan doc's single-cause framing):
  (a) the per-file dedup drop is deterministic — same wrong answer every time,
  driven by in-file regex match order, not filesystem state; (b)
  `listAllFiles`'s unsorted LIFO-stack `readdir` walk makes cross-file array
  order in `out.get(id)` unstable across invocations. AC-1 fixes (a); AC-2
  fixes (b) by sorting the file list — this is in scope for AC-2, not
  scope creep, because deep-equal comparison is order-sensitive and (a) alone
  cannot make it pass.
- **"Proven red first" is a task-execution discipline, not a separate AC.**
  AC-1 and AC-2 each name a fixture that must be built and run against the
  pre-fix scanner first, with the failing output captured in the task's
  verify report — the same fixture and test then becomes the fix's
  regression test once the code is corrected. Do not write a permanently-red
  test asserting broken behavior; the committed test asserts the CORRECT
  (post-fix) outcome, and the red run is process evidence, not a contract.
- **The `ev-20260815-003` disjoint deep-verify offender-set symptom is NOT
  fully explained by this phase and this SPEC does not claim to.** That
  evidence's two runs differed by a real code edit (an AC-5 title fix in the
  *evidence's own* phase 280, unrelated to this phase's own AC numbering),
  and `deep-verify`'s verdicts come from an AI provider whose own sampling
  variance cannot be ruled out by this repo's mock-only test suite. AC-1/AC-2
  prove and fix scanner-level determinism; whether the deep-verify symptom was
  scanner-caused, provider-caused, or both stays an open, explicitly narrowed
  finding — report it as "hypothesis partially confirmed; downstream symptom
  unattributed," not as solved.
- **D-P (four filings, one phase):** `rec-20260807-001` (needs-decision,
  `--from-rec` primary), `rec-20260730-002` (2026-07-30, the true earliest
  filing — the source doc's "original filing" attribution to
  `rec-20260807-001` is corrected here, `dec-20260816-002`), `rec-20260809-001`,
  and `rec-20260814-002` are one root cause in `verify/coverage.ts` +

- **Not this bug — explicitly out of scope:** `rec-20260730-001`

- **Also out of scope:** `coverageScheme` default changes (owned by
  `rec-20260807-005` / `dec-20260813-005`); `rec-20260815-003` (recordable
  independent review, `needs-decision`, deserves its own design pass).
- **Dispatch-driven exercise (D-Q amendment / Phase D, `dec-20260816-004`):**
  this phase folds Phase D's live-escalation exercise in rather than deferring
  it again. Every task in the DRAFT declares an explicit `stop:` condition
  from authoring, and at least one task is recorded via
  `cadence build task <id> --execution dispatch`, flipping `anyTaskDispatched`
  true and escalating `boundaryEnforcement` to `block` for the remainder of
  the phase. Friction (stray-file refusals during review fix rounds) is
  expected and is itself the data this exercise exists to produce.
- **Additive only.** No `schemaVersion` bump; historical `SUMMARY.json`
  content hashes preserved (prove with `summary verify-all`, not assertion).
- **AC-1's disjunction resolves to "record why not": mention mode is exempt,
  by construction, not by omission.** `TestRef`'s `qualifying`/`skipped`
  fields are documented (the type's own JSDoc) as assertion-mode only;
  mention-mode `TestRef`s never carry them. The only consumers that branch on
  `qualifying` — `weaklyLinkedAcs` and `skippedOnlyLinkedAcs` — can therefore
  never fire on a mention-mode ref (the predicate reads `undefined`, not
  `false`). A mention-mode AC's verdict is decided solely by `uncoveredAcs`'s
  `refs.length === 0` check, which same-file occurrence gets recorded is
  cosmetic display detail only, and can never change that verdict. Retrofitting
  the qualifying-displaces-non-qualifying fix onto mention mode's mirrored
  dedup (`coverage.ts`'s `seenInFile` loop) would therefore fix nothing — there
  is no verdict-level bug there to fix. AC-1's committed regression test
  (`coverage-dedup-ordering.test.ts`) exercises assertion mode only, matching
  this scope.
- **Corpus before code** (house rule): AC-1 and AC-2's reproduction fixtures
  must be proven red before their fixes exist.
