# 168-01 — Land test-gutting demo as a committed example

## Objective

Commit the test-gutting demo (docs/demo-test-gutting.zip) as a runnable, offline, deterministic example under examples/demo-test-gutting/, verified end-to-end against a locally built v1.43.0 CLI, with docs/DEMO.md's transcripts corrected to match real output wherever v1.43 has drifted from the 2026-07-07/v1.42.0 capture.

## Acceptance Criteria

### AC-1: run-demo.sh executes end-to-end against the current CLI
Given the demo assets from docs/demo-test-gutting.zip extracted under examples/demo-test-gutting/
When examples/demo-test-gutting/run-demo.sh is run non-interactively against a locally built v1.43.0 cadence CLI (the four beats: honest failure, gutted-green, refused settle, fixed+settled)
Then it completes with exit 0 overall, Beat 3's settle refusal exits 1 as documented, and no step requires network access or an API key

### AC-2: docs/DEMO.md transcripts match real v1.43.0 output
Given the captured transcripts in docs/DEMO.md (Beats 1-4, captured 2026-07-07 against v1.42.0)
When each transcript is diffed against live output captured from the same run-demo.sh execution on the current v1.43.0 build
Then every drifted line is corrected to the real wording (e.g. Beat 3's refusal message, which changed under phase 166's language-aware coverage diagnostics) -- never edited to fake a match, and non-drifted transcripts are left untouched

### AC-3: demo is deterministic and reproducible from a clean checkout
Given a clean checkout of examples/demo-test-gutting/ with cadence built locally
When run-demo.sh is executed twice in separate throwaway directories
Then both runs produce the same beat-by-beat output (modulo the mktemp path) using only the mock verifier, with zero npm dependencies beyond node:test/node:assert
