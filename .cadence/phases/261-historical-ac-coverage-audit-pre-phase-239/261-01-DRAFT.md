# 261-01 — Historical AC-coverage audit (pre-phase-239)

## Objective

Build a read-only, reproducible audit that answers `rec-20260729-006`'s
question — how many of the 255 pre-phase-239 settled `SUMMARY.json` records
(no `coverageScheme` recorded) have genuine per-phase test coverage behind
their recorded AC PASS — using a design corrected against two dead ends a
prior draft of this phase ran into and verified against real repo data:

1. **A repo-wide bare-`AC-N` token scan is not usable signal.** 395 of 448
   test files in this repo contain a bare `AC-N` token, most as fixture data
   inside this repo's own SUMMARY/coverage/DRAFT meta-tests (e.g.
   `writeSummary(..., [{ id: 'AC-1' }])`), not real coverage evidence. Any
   bucket built on "does this token appear anywhere else in the repo" is
   noise-dominated. This design never performs that scan.
2. **Same-file self-attestation is not automatically trustworthy either.**
   `packages/core/tests/cli/init.test.ts` is declared as a literal path by
   11 different phases' DRAFTs across this repo's history, each contributing
   their own
   `AC-1`/`AC-2`/etc. — the collision problem recurs *inside* a single
   shared file, not just across separate files. A token match only counts as
   high-confidence self-attestation when it lands in a file that phase's
   DRAFT is the *only* DRAFT in the whole corpus to declare.
3. **The declaration index cannot be built from glob-pattern `files:`
   entries.** A first pass at this design tried to key the
   dedicated-vs-shared index by resolving every declared glob (including a
   handful of repo-wide globs like `packages/**/tests/**/*.ts`, declared by
   phases such as `12-rename-cadence` and `260-vitest-v4-upgrade`) to
   concrete files. That requires glob-matching internals
   (`toMatcher`/`globToRegExp` in `coverage.ts`) that are module-private,
   and — worse — a repo-wide glob declaration makes nearly every test file
   in the corpus "shared," collapsing `self-attested` to empty regardless of
   the real answer. This design instead considers **only literal (no `*`,
   `?`, or `[`), `{a,b,c}`-brace-expanded `.test.ts`/`.test.tsx` paths that
   exist on disk** for both reachability and the declaration index. A
   wildcard-glob-only declaration is deliberately not evidence of ownership
   here (see the Boundaries) — this needs no new export from `coverage.ts`
   and matches how a hand-verified pass over this repo's own corpus was
   already computed (see the ballpark numbers below).

The resulting per-AC classification (computed via file-scoped scanning of
only each phase's own literal, existing declared test-file paths, using
`scanTestCoverage` + `uncoveredAcs`/`weaklyLinkedAcs`/`skippedOnlyLinkedAcs`
— the same public functions `phase-replay.ts`'s existing `bare` branch
already uses, so no new exports from `coverage.ts` are needed):

- **`self-attested`** — token found, in an asserting block, inside a
  literal declared test-file path that only this one phase's DRAFT declares
  (as a literal path) anywhere in the corpus. High confidence.
- **`self-attested-shared`** — token found, but only inside a literal
  declared test-file path that 2+ phases' DRAFTs also declare literally.
  Cannot rule out the match belonging to a different phase's
  identically-numbered AC.
- **`not-found-in-declared-files`** — the phase declares at least one
  literal, existing test-file path, it was scanned, but the token isn't
  found there in an asserting way. No repo-wide fallback scan is performed
  (see point 1 above) — this bucket does not claim to know whether the AC
  is covered elsewhere.
- **`unreachable`** — the phase's DRAFT declares no literal, existing
  `.test.ts`/`.test.tsx` path at all (whether because it declares no task
  files, only non-test files, only wildcard globs, or only paths that no
  longer exist). No evidence exists to classify these ACs at all.

A hand-verified pass over this repo's own corpus (literal-path-only, same
rule as above) already estimated the phase-level split as roughly 112
phases with a dedicated file (self-attested reachable), 79 with only
shared-file matches, 64 unreachable — this phase codifies that reproducibly
and derives the real per-AC numbers, which the manual pass did not fully
compute. `phase-replay.ts`'s existing `indeterminate` contract for the live
`cadence verify phase` command is untouched throughout.

## Acceptance Criteria

### AC-1: dedicated self-attestation is correctly detected
Given a pre-239 phase whose DRAFT declares, as a literal (non-wildcard) path,
at least one existing `.test.ts`/`.test.tsx` file containing an asserting
`AC-N` match for one of its own ACs, and no other phase's DRAFT in the
corpus declares that same literal path
When the audit classifies that AC
Then it is classified `self-attested`

### AC-2: shared-file matches are classified separately from dedicated matches
Given the same setup as AC-1, except every literal declared test-file path
containing the asserting match is also declared literally by at least one
other phase's DRAFT
When the audit classifies that AC
Then it is classified `self-attested-shared`, and the audit's report
explicitly documents that this bucket cannot distinguish a genuine match
from another phase's identically-numbered AC sharing the same file

### AC-3: unreachable and not-found phases are distinguished by cause
Given a pre-239 phase whose DRAFT declares no literal, existing
`.test.ts`/`.test.tsx` path at all (no task files declared, only non-test
files declared, only wildcard-glob paths declared, or the declared literal
path(s) no longer exist on disk)
When the audit classifies its ACs
Then every AC in that phase is classified `unreachable`; and given instead a
phase that declares at least one literal, existing test-file path which was
scanned but a specific AC's token isn't found there, that AC is classified
`not-found-in-declared-files` — the two are never conflated, and neither
claims coverage exists elsewhere in the repo

### AC-4: aggregate counts are internally consistent and derived, not hardcoded
Given every `SUMMARY.json` under `.cadence/phases/**` with `coverageScheme`
absent
When the audit walks the corpus and classifies every recorded AC
Then `self-attested + self-attested-shared + not-found-in-declared-files +
unreachable` sums exactly to the total number of `acResults` entries across
every successfully-parsed scheme-absent `SUMMARY.json` (no literal count is
hardcoded anywhere in the implementation or its tests), and any
`SUMMARY.json`/`DRAFT.md` pair that fails to parse is counted in a separate,
phase-level `unreadable-records` bucket rather than silently dropped

### AC-5: `replayPhaseCoverage`'s existing behavior is unchanged
Given the existing `indeterminate` contract in
`packages/core/src/verify/phase-replay.ts` used by the live
`cadence verify phase` command
When the new audit capability is added
Then `replayPhaseCoverage` and its callers are not modified, and
`packages/core/tests/verify/phase-replay.test.ts`,
`phase-replay-indeterminate.test.ts`, and `phase-replay-qualified.test.ts`
continue to pass unmodified

### AC-6: the automated test suite uses fixtures, not this repo's live corpus
Given the audit implementation is complete
When the automated test suite runs (`pnpm test`)
Then all four classification buckets and the aggregate/invariant logic are
each covered by tests using constructed fixture DRAFT/SUMMARY pairs and a
constructed fixture file-declaration index — not this repo's own
`.cadence/phases/` corpus — for offline determinism; and because this
repo's own `.cadence/config.json` runs `coverageScheme: "phase-qualified"`,
every new test's assertion carries the `261-01/AC-N` qualifier prefix (e.g.
`it('261-01/AC-1: ...', ...)`) so phase 261's own settle coverage gate can
attest to it. AC-7's run against the real corpus is a separate phase
deliverable via the CLI command, not part of the test suite.

### AC-7: the audit is run against this repo's real history and findings are recorded
Given the audit tool built under AC-1 through AC-6
When it is run against this repo's actual pre-239 `SUMMARY.json` records
Then the real aggregate and per-phase findings are written to a findings
artifact under this phase's directory, satisfy AC-4's invariant, and are
referenced from the phase's own SUMMARY; the hand-estimated ~112/79/64
split in the Objective is treated as a ballpark to sanity-check against, not
a target the tool's real output must match

- files: `packages/core/src/verify/historical-coverage-audit.ts`
- action: implement a function that, given one phase's parsed DRAFT +
  SUMMARY and a corpus-wide file-declaration index (see T2), first derives
  that phase's own literal declared test-file set — from `draft.tasks[].files`,

## Boundaries

- DO NOT modify `replayPhaseCoverage`'s `indeterminate` contract or any
  behavior of the live `cadence verify phase` command — this phase is
  read-only and additive only.
- DO NOT modify the live coverage gate (`packages/core/src/gates/coverage.ts`)
  or `scanTestCoverage`'s default (repo-wide, unqualified) scan behavior.
- DO NOT add a repo-wide bare-`AC-N` scan as a fallback signal for
  `not-found-in-declared-files` — the Objective's point 1 established that
  signal is noise-dominated; do not reintroduce it.
- DO NOT rewrite, "correct," or delete any historical `SUMMARY.json` file —
  the audit reports on history, it does not alter it.
- DO NOT edit any historical `DRAFT.md`'s `files:` declarations — doing so
  would directly move that phase between `unreachable` /
  `self-attested-shared` / `self-attested` buckets and is exactly the kind
  of self-serving drift this repo's own "Convenient Bypass" / verification-
  honesty conventions exist to catch.
- DO NOT classify `self-attested-shared` as a confirmed genuine match, or
  `not-found-in-declared-files` as a confirmed false positive — neither
  bucket's evidence supports that strength of claim.
- DO NOT resolve wildcard-glob `files:` entries (containing `*`, `?`, or
  `[`) to concrete files for either the reachability check or the
  declaration index, and do not add a glob-matching export to
  `coverage.ts` to make that possible. A phase whose only declared test
  evidence is a wildcard glob classifies `unreachable` — this is a
  deliberate, documented limitation (see Objective point 3), not a bug to
  fix by widening the match.
- DO NOT address `rec-20260807-005` (whether `phase-qualified` should
  become the default scheme) in this phase — that is a separate decision,
  tracked separately.
