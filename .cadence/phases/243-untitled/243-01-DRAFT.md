# 243-01 — createVerifierFactory: loud banner on every seam's credential-missing downgrade

## Objective

Close issue #331's 'Related, lower priority' item 1 (rec-20260731-002): createVerifierFactory's three selection-time credential/prerequisite-missing degrade branches (anthropic missing ANTHROPIC_API_KEY, local missing CADENCE_LOCAL_BASE_URL/model, host-cli builder not wired for a family) currently emit only a bare single-line stderr warning for all 7 verifier seams (specReview, uiSpecReview, verifier/deep-verify, perTaskVerifier, codeReview, planReview, securityAudit) -- unlike deep-verify's separate, disjoint settle.ts pre-check, which prints the loud MOCK_FALLBACK_BANNER only when the configured provider resolves to mock (default or explicit), never on a credential-missing downgrade from an explicitly-requested real provider. Elevate the three degrade branches inside createVerifierFactory to the same loud banner treatment, naming the seam and the specific missing prerequisite, without touching the silent default-mock fallthrough or wrapWithFallback's separate per-call runtime path.

## Acceptance Criteria

### AC-1: a credential/prerequisite-missing degrade prints the loud banner, naming seam + reason
Given any of the three `createVerifierFactory` selection-time degrade branches fires (anthropic configured with no `ANTHROPIC_API_KEY`; `local` configured with no `CADENCE_LOCAL_BASE_URL`/model; `host-cli` requested but `spec.hostCli` unset for that family)
When the factory resolves a verifier for that seam
Then the emitted warning is the loud multi-line banner (reusing `MOCK_VERIFIER_NOTICE`'s wording, matching `MOCK_FALLBACK_BANNER`'s existing "not real verification" framing), and it names both the seam's `label` and the specific missing prerequisite — for every one of the 7 `VERIFIER_SEAMS` families, since all route through this one shared function

### AC-2: the default and explicit-mock paths stay silent
Given a seam left unconfigured (defaults to mock) or explicitly configured to `provider: 'mock'`
When the factory resolves a verifier for that seam
Then no banner and no warning of any kind fires — the existing silent `return spec.mock()` fallthrough is untouched

### AC-3: the new banner and settle.ts's deep-verify pre-check never both fire, and never both stay silent, for the same condition
Given a config-matrix test exercising deep-verify (`verifier` seam) across `{unset, explicit mock, anthropic-no-key, local-unset, host-cli-unwired}`
When both the new factory-level banner and the existing `settle.ts` `MOCK_FALLBACK_BANNER` pre-check (fires iff the *configured* provider itself resolves to `'mock'`) are evaluated for each case
Then `unset`/`explicit mock` trip settle.ts's pre-check only (zero factory-level banners), `anthropic-no-key`/`local-unset`/`host-cli-unwired` trip the new factory-level banner only (settle.ts's pre-check does not fire, since the configured provider name is not `'mock'`), and no case produces zero or two banner-shaped emissions

### AC-4: existing coverage updated, full suite green
Given the old bare one-line wording was pinned by exact-equality assertions in `verifier-factory.test.ts` (and possibly `config-explain/warnings.test.ts` / `doctor/verification-readiness.test.ts`)
When this phase's changes land
Then every such assertion is updated to the new wording (not deleted or loosened), and `pnpm turbo run lint typecheck test build` is fully green

## Boundaries

- DO NOT touch `wrapWithFallback`'s per-call runtime warn (the async host-cli-binary-fails-mid-call path) — that fires potentially many times per settle run (once per verify call, not once per factory build), a different noise/frequency profile from the three selection-time branches in scope here. Left as a possible follow-up, not silently dropped.
- DO NOT touch the silent default-mock `return spec.mock()` fallthrough at the end of `createVerifierFactory` — no configured provider, nothing to warn about.
- DO NOT touch `settle.ts`'s existing `MOCK_FALLBACK_BANNER` pre-check call site or its trigger condition (`resolveEffectiveProvider(...).provider === 'mock'`) — it is disjoint from this phase's scope by construction (AC-3) and out of scope to refactor.
- DO NOT change `resolveEffectiveProvider`'s signature or the `VerifierSelectOptions`/`VerifierFactorySpec` public shape — this is a wording/emission-site change inside the existing branches, not an API change.
