# 123-01 — Draft templates for first real work

## Objective

Add first-real-task templates to `cadence draft new` so a newcomer can create a
useful bugfix, feature, or refactor DRAFT from a title without hand-authoring the
Objective, Acceptance Criteria, Tasks, and Boundaries from scratch.

## Acceptance Criteria

### AC-1: Template flag is discoverable and validated
Given the user runs `cadence draft new --help`
When they inspect the options
Then the help lists a `--template <name>` option with the supported template
names `bugfix`, `feature`, and `refactor`

Given the user passes an unknown template name
When `cadence draft new` runs
Then it refuses without writing a DRAFT and prints the supported template names

### AC-2: Bugfix template creates a testable first DRAFT
Given an initialized repo in IDLE
When the user runs `cadence draft new --title "Fix login timeout" --template bugfix`
Then Cadence derives the next free phase/task id and writes a DRAFT whose
Objective, ACs, Tasks, and Boundaries are specific enough to guide a small bugfix
without placeholder-only sections

### AC-3: Feature template creates a useful feature DRAFT
Given an initialized repo in IDLE
When the user runs `cadence draft new --title "Add CSV export" --template feature`
Then Cadence writes a DRAFT with feature-oriented ACs, implementation/test tasks,
and boundaries that are distinct from the bugfix template

### AC-4: Refactor template creates a safe refactor DRAFT
Given an initialized repo in IDLE
When the user runs `cadence draft new --title "Split billing service" --template refactor`
Then Cadence writes a DRAFT with behavior-preservation ACs, verification tasks,
and boundaries that emphasize no behavior change unless explicitly stated

### AC-5: Existing draft-new behavior stays compatible
Given callers omit `--template`
When they use existing explicit `phase num --title` arguments
Then the current scaffold format and file path behavior remain compatible

Given callers combine `--template` with explicit `phase num`
When `cadence draft new` runs
Then the requested phase/task id is honored while the selected template controls
the DRAFT body

### AC-6: Docs teach the first-real-DRAFT path
Given a newcomer finishes `cadence tutorial` or `cadence init --demo`
When they read README and quickstart next steps
Then the docs show a copy-paste template command for the first real phase and
make clear that templates are scaffolds to edit, not proof of correctness

## Constraints

- Keep templates deterministic and offline; no model calls.
- Keep template output honest: include editable prompts where specificity belongs,
  but avoid empty placeholder-only sections.
- Preserve existing `draft new` command compatibility and current auto-id behavior.
- Keep this milestone focused on draft templates and the docs needed to teach
  them. Do not expand into `doctor --fix`, `init --dry-run`, or team rollout.

## Open Questions

- Should the template flag be accepted for `cadence spec new` too, or stay scoped
  to DRAFT creation for this milestone?
- Should templates infer tier, or should they leave the existing/default tier
  behavior untouched?
