# 279-01 — DP-A: Dispatch policy engine

## Objective

Give config.subagentPolicy and config.modelPerClass — fully schema'd, defaulted, and live in .cadence/config.json, but with zero consumers anywhere in packages/core/src — their first reader: a pure classifier that computes { execution, modelClass, model, reasons[] } per task and threads it, read-only/advisory, through cadence dispatch plan's JSON output and the dispatch packet.

## Acceptance Criteria

### AC-1: Batch trigger
Given a wave (per computeWaves) containing at least subagentPolicy.mechanicalBatchMin tasks whose resolved execution class is mechanical, each declaring mutually disjoint files:
When cadence dispatch plan --json runs
Then each of those mechanical tasks carries execution: "dispatch" and a reasons[] entry naming mechanicalBatchMin, the wave's measured mechanical count, and the configured threshold; a complex-classified task sharing that same wave does not inherit that reason and, absent any other trigger, remains execution: "inline"

### AC-2: Size trigger
Given two otherwise-identical tasks: one declares a files: entry backed by a real on-disk file large enough that the estimated weight (packetChars/4 + declaredFileBytes/4, each file's byte contribution capped at FILE_BYTES_CAP) exceeds subagentPolicy.largeTaskTokens; the other's estimate stays at or below threshold
When the plan runs
Then the large task carries execution: "dispatch" with a reasons[] entry naming largeTaskTokens, the measured estimate, and the threshold; the small/missing-file task carries execution: "inline"; a declared file that does not exist on disk contributes 0 bytes (a documented estimator limitation, never a silent guess)

### AC-3: Budget signal stays honestly inert (D-DQ3)
Given config.telemetry.tokenUtilization populates only a synthetic +0.01-per-UserPromptSubmit counter (hooks/handlers.ts:73-74) and no real context-utilization reading is wired into dispatch planning
When cadence dispatch plan --json runs, for any DRAFT and any config including subagentPolicy.contextBudgetThreshold at its minimum (0.3)
Then the top-level JSON always carries signals.contextUtilization: null, and no task's reasons[] ever contains a contextBudgetThreshold entry

### AC-4: Class-mismatch coherence warn, precedence-aware (D-DQ1)
Given a task whose declared class: disagrees with heuristicTaskClass's result, including the corpus-derived precedence case where depends.length >= 2 overrides the file-count mechanical rule (e.g. 1 file, 2 depends: entries, class: mechanical, heuristic says complex)
When cadence draft check runs
Then a coherence issue with severity: "warn" and code: "CLASS_MISMATCH" names the task id, the declared class, and the heuristic class, and states the declared value wins; it is never severity: "block" (D-DQ4 precedent: warn now, no evidence-gated promotion this phase)

### AC-5: Non-regression
Given a DRAFT with no class: lines and default subagentPolicy/modelPerClass config, and a dispatch plan --json fixture captured from the pre-change CLI
When the same scripted scenario runs against the post-change CLI
Then waves[].wave and tasks[].id/name/recommendedIsolation are byte-identical to the fixture; each tasks[].packet, with every line matching /^\*\*Execution:\*\* / or /^\*\*Model:\*\* / removed, is byte-identical to the corresponding fixture packet; and the new fields are purely additive (appended, never reordering or replacing a pre-existing field)
