# 161-01 — Portfolio readiness doc sync

## Objective

Align the repo's documentation (README, docs/, DESIGN.md, package READMEs) on
one consistent surface-model vocabulary, correct stale "Claude Code only" /
slash-command-count claims, and add a concise technical-reviewer/portfolio
overview so the public repo reads clearly and accurately for a CTO or senior
engineer evaluating it — per `Claude-Handoff-Doc-Sync.md`.

## Acceptance Criteria

### AC-1: Consistent surface vocabulary
Given README.md, docs/README.md, docs/concepts.md, docs/mcp.md, and
docs/reference/commands.md currently mix "three-surface model" / "one engine,
four entry points" / bare "third surface" phrasing
When the terminology sweep is applied
Then all current-facing docs describe "one engine, three surface categories
(CLI, host adapters, MCP server), four current entry points" consistently, and
docs/concepts.md's link to README's surface-model anchor still resolves

### AC-2: No stale "Claude Code only" claims
Given DESIGN.md §2 says "v1 is Claude Code only" and CONTEXT.md's glossary
says "a host is the tool CADENCE drives (v1 = Claude Code only)"
When DESIGN.md and CONTEXT.md are refreshed
Then neither current-facing doc claims Cadence is Claude-Code-only, DESIGN.md's
historical D-decisions are preserved (marked historical, not deleted), and
Codex is described as a shipped host-adapter/conformance consumer

### AC-3: MCP described accurately as imperative-loop-only
Given docs/mcp.md and docs/reference/commands.md call MCP a bare "third
surface" without restating its scope
When those docs are updated
Then MCP is described as one of the three surface categories, exposing the
imperative loop only (command-boundary gates run; ambient edit-time gates are
unavailable over MCP and require host hooks)

### AC-4: Claude Code ambient-gate claim corrected
Given docs/claude-code.md currently claims Claude Code is "the only" surface
delivering ambient edit-time gates, which is stale now that the Codex adapter
also declares `pre-tool-edit` in its blocking hooks
When docs/claude-code.md is corrected
Then it describes Claude Code as the **reference** adapter for ambient
edit-time gates without claiming exclusivity

### AC-5: Technical-reviewer overview + architecture diagram
Given the README has no CTO-facing summary or architecture diagram
When a "For technical reviewers" section and a Mermaid architecture diagram are
added to README.md
Then a technical reviewer can find problem/solution/why-it-matters and a
diagram of engine + surfaces + gates within the first screen of the README

### AC-6: Mock-verifier warning stays prominent + release credibility surfaced
Given the mock-verifier heads-up already exists in README.md and GitHub
Releases already carries changelogs/provenance notes
When the README is reviewed
Then the mock-verifier warning remains clear and prominent and a line pointing
to GitHub Releases for changelogs/npm status/verification notes is present

### AC-7: Portfolio-ready project summary present
Given there is no single portfolio-style summary paragraph
When a short summary is added to README.md
Then a two-to-three-sentence summary describing Cadence as a DRAFT→BUILD→SETTLE
verification framework driven from CLI/Claude Code/Codex/MCP is present
