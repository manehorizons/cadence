# 278-01 — cadence demo: refuse-then-succeed command + progressive disclosure onboarding stages

## Objective

Ship a non-interactive 'cadence demo' refuse-then-succeed command reachable from a bare npx invocation, plus a minimal progressive-disclosure onboarding-stage system gating cadence help/start visibility, while keeping cadence tutorial working via a redirect notice.

## Acceptance Criteria

### AC-1: Gutted fixture refuses
Given the demo's assertion-mode gutted-but-green fixture staged in a sandbox (AC-1 mentioned in a test that calls the function but never asserts on it)
When settle run --auto executes
Then it refuses, citing the test-coverage gate's 'mentioned but not inside a recognized asserting test block' message

### AC-2: Honest fixture settles
Given the demo's honest fixture staged after the fix beat (a real assertion added)
When settle run --auto executes again
Then it succeeds with exit code 0 and the loop closes

### AC-3: Default run is fully non-interactive
Given cadence demo invoked with no flags
When it runs to completion
Then it completes the refuse-then-succeed narrative with no pauses, exits 0, and removes its temp sandbox afterward

### AC-4: --keep preserves the playground
Given cadence demo --keep
When the run completes
Then the sandbox is left on disk at a reported path instead of being deleted

### AC-5: --interactive pauses between beats
Given cadence demo --interactive (or -i) run in a TTY
When advancing between beats
Then it pauses for input before continuing

### AC-6: --in-place runs in the current directory
Given cadence demo --in-place
When it runs
Then it operates inside the current working directory instead of a temp directory

### AC-7: Bare invocation dispatches to demo
Given the CLI invoked with zero arguments (bare npx or bare cadence)
When it is dispatched
Then it runs the same command as cadence demo

### AC-8: tutorial keeps working and points at demo
Given cadence tutorial invoked
When it starts
Then it still completes its existing refuse-then-succeed walkthrough unchanged, plus prints one stderr line pointing at cadence demo

### AC-9: Demo completion advances onboarding stage
Given a fresh environment with no ~/.cadence/onboarding.json (or $CADENCE_HOME/onboarding.json)
When cadence demo completes successfully
Then the onboarding stage file is created/updated recording stage >= 1

### AC-10: help hides advanced commands below stage 2
Given onboarding stage 0 or 1 with no --advanced flag
When cadence help is run
Then doctor and other stage-2+ commands are absent from the printed output, while cadence help --advanced (or stage >= 2) shows the full command surface

### AC-11: start menu hides doctor below stage 2
Given onboarding stage 0 or 1
When cadence start renders its menu
Then the 'Check my setup is healthy' (doctor) entry is hidden unless --advanced is passed or stage >= 2
