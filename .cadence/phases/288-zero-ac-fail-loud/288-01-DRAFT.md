# 288-01 — Zero-AC drafts must fail loud

## Objective

A DRAFT whose `## Acceptance Criteria` section is non-empty but yields zero
parsed `### AC-N` blocks (e.g. a non-numeric heading like `### AC-K1:`) must
produce a loud, actionable failure instead of silently parsing to an empty AC
array that structural-verifier, test-coverage, evidence-floor, and
`settle --auto`'s completeness check then all pass vacuously.

## Acceptance Criteria

### AC-1: Unparseable AC heading is a loud, named error
Given a DRAFT with a non-empty `## Acceptance Criteria` section containing
only non-numeric headings (e.g. `### AC-K1:`)
When the draft is parsed
Then parsing reports an error naming the numeric-id requirement and the
offending heading text, and never silently returns an empty AC array for
that block.

### AC-2: `draft check` surfaces the problem, not `coherence: OK`
Given the same malformed DRAFT
When `cadence draft check` runs
Then it reports the problem — the parse failure from AC-1 surfaces as a
`draft check failed: ...` error naming the offending heading, exit code 1 —
rather than printing `coherence: OK`. The pre-change behavior (`coherence:
OK` on this exact fixture) is pinned as a red test before the fix lands.

### AC-3: Well-formed numeric drafts are byte-identical
Given a DRAFT with a well-formed numeric AC set
When it is parsed and checked
Then behavior (parsed AC array, `draft check` output) is byte-identical to
pre-change. A fixture is captured before the parser or coherence check are
touched.

### AC-4: Settle never reports vacuous success on an empty AC set
Given a zero-AC draft that reaches settle (i.e., the AC set is genuinely
empty, not merely malformed)
When `settle run --auto` executes
Then the outcome explicitly names the empty AC set rather than reporting all
gates passing.

### AC-5: Historical corpus is unaffected; report-only
Given the historical DRAFT corpus under `.cadence/phases/**`
When the new rule is applied read-only against every historical DRAFT
Then any draft that would now fail is enumerated by phase id, no historical
artifact is modified, and `cadence summary verify-all` reports the same
MATCH/NO_HASH/failed counts as the pre-change baseline (299 checked, 62
MATCH, 237 NO_HASH, 0 failed).

## Boundaries

- Do NOT widen `AC_TOKEN_RE` in `packages/core/src/verify/coverage.ts` or any coverage-token/qualifier logic (D-AE; phases 239/285 own that surface).
- Do NOT add a `.min(1)` or any other restriction to `DraftZ.acceptanceCriteria` in `packages/types/src/plan.ts` (D-AD) — an empty array stays schema-valid.
- Do NOT edit any historical `.cadence/phases/**/*-DRAFT.md` or `*-SUMMARY.*` file — AC-5 is report-only.
- Do NOT touch `packages/core/src/gates/coherence.ts` or `packages/core/src/coherence/check.ts` — the fix lives at parse time (CadenceError), not as a new CoherenceIssue; that keeps the change confined to draft-parser.ts and avoids widening `coherenceCheck`'s signature to thread raw draft markdown through `draft-context.ts` and every gate-context caller.
- Do NOT change `parseAcceptanceCriteria`'s exported surface or the `Draft` type — the malformed-heading detection is an internal side-channel inside `draft-parser.ts` only.
