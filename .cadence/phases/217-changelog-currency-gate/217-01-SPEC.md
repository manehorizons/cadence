# 217-01 — Gate CHANGELOG.md currency the same way CLAUDE.md's version string is gated

## Objective

`CLAUDE.md`'s version line is already gated at commit- and push-time
(`.githooks/check-doc-sync.sh`, wired into `pre-commit`/`pre-push`, backed by
`packages/core/tests/docs/doc-sync-hook.test.ts`): when a commit changes
`packages/core/package.json`'s version, `CLAUDE.md` must mention the new
version or the commit/push is refused. Root `CHANGELOG.md` has no equivalent
mechanism — it silently stopped tracking releases at `1.6.0` while
`packages/core/package.json` climbed to `1.50.0` (44 versions, closed
2026-07-24 via PR #297's manual backfill). Extend the exact same checker to
`CHANGELOG.md`'s newest `## [x.y.z]` heading, reusing
`check-doc-sync.sh` as-is (per `dec-20260724-002`, scoped to gate-only —
auto-generating changelog prose from `SUMMARY.json` is deferred).

## Acceptance Criteria

### AC-1: A version bump without a matching CHANGELOG.md entry is refused at commit- and push-time, and in CI
Given a commit changes `packages/core/package.json`'s `version` field
When the commit is staged (`pre-commit`) or being pushed to `main`
(`pre-push`), or the corresponding CI check runs
And `CHANGELOG.md`'s newest `## [x.y.z]` heading does not mention the new
version
Then the commit/push/CI run is refused with a message naming the missing
version and `CHANGELOG.md` (reusing `check-doc-sync.sh`'s existing message
shape), exactly mirroring the current `CLAUDE.md` behavior; When
`CHANGELOG.md` does mention the new version, the check passes and behavior
is unchanged from today.

## Constraints

- Reuse `.githooks/check-doc-sync.sh` unmodified — it is already generic
  (doc text on stdin, expected version, optional label) and already proven
  correct (`doc-sync-hook.test.ts`). Do not fork a parallel checker.
- Extend `.githooks/pre-commit` and `.githooks/pre-push` to run the SAME
  check against `CHANGELOG.md` that they already run against `CLAUDE.md` —
  both docs must pass for a version-bump commit to be accepted, not just one.
- Add a cross-platform (non-bash) doc-content test mirroring
  `doc-sync-hook.test.ts`'s existing "CLAUDE.md tracks the canonical package
  version" test, but scoped to `CHANGELOG.md`'s newest heading specifically
  (not just "the version appears somewhere in the file" — extract the first
  `## [x.y.z]` heading and compare it directly, since that is the actual
  invariant this gate protects).
- Update `docs/agents/release.md` / the `release-cut` skill's existing
  "Doc-sync verification" step to name this new automated check explicitly,
  and update `CLAUDE.md`'s "Enforcement layers" section to document the new
  gate (paired-doc-update discipline, `CLAUDE.md`'s own "The Doc Drift"
  failure mode).
- Do NOT implement the auto-generation-from-`SUMMARY.json` half of
  `rec-20260724-003` — out of scope per `dec-20260724-002`.
- Do NOT change `check-doc-sync.sh`'s matching semantics (whole-token,
  not-flanked-by-digit-or-dot) — reuse exactly as-is.
