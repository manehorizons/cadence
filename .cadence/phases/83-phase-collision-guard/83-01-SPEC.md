# 83-01 — Phase-collision guard (worktree safety)

## Objective

Make phase-number collisions across sibling git worktrees (and already-merged upstream phases)
fail loud *before* wasted work — by observing ground truth (`git worktree list` + `origin/<ref>`)
at scaffold time and as a settle backstop, refusing with a named conflict and the next free number,
while degrading to today's behavior on any non-git/offline/single-worktree path.

## Acceptance Criteria

### AC-1: Pure detector identifies collisions and the next free number
Given a target phase number and a list of occupancies `{ number, source, location }`
When `detectPhaseCollision(target, occupancies, opts?)` runs (no I/O)
Then it returns `collides` true iff some occupancy's `number === target` (minus `opts.excludeNumbers`),
`conflicts` listing exactly those matches, and `nextFree = max(target, ...allOccupancyNumbers) + 1`;
collision key is the leading numeric token (`^(\d+)`) so `30-auth` and `30-cache` both normalize to
`30` and collide, and non-numeric/unparseable dir names are ignored.

### AC-2: Collector gathers occupancy from local, siblings, and upstream
Given a repo with sibling worktrees and an `origin` remote
When `gatherOccupancy(repoRoot, { integrationRef })` runs
Then it returns occupancies for: local `.cadence/phases/` dirs; every sibling worktree path
(`git worktree list --porcelain`, path `!== repoRoot`) tagged `source: 'sibling'` with the worktree
path as `location`; and `origin/<integrationRef>` phase dirs (`git ls-tree`) tagged
`source: 'upstream'` with `location: 'origin/<ref>'`.

### AC-3: Graceful degradation — best-effort, never throws
Given no git binary / not a repo / no `origin` / a sibling with no `.cadence/` / an `integrationRef`
absent on origin
When `gatherOccupancy` runs
Then each failing source contributes nothing (the collector never throws), so a non-git or offline
single-worktree run yields local-only occupancy and scaffolds exactly as it does today — the only
hard failure in the whole feature is an actual detected collision.

### AC-4: Scaffold guard refuses colliding phase numbers
Given a target phase number already in use by a sibling worktree or upstream
When `cadence spec new <phase> <num>` or `cadence draft new <phase> <num>` runs
Then scaffolding is refused before any file is created, with a message naming each conflict
(`phase N is in use by worktree <path>` / `on origin/<ref>`) and the suggested next free number;
the local-only `existsSync` collision continues to refuse as before.

### AC-5: `--allow-phase-collision` bypasses the guard
Given a detected cross-worktree/upstream collision
When the same `spec new` / `draft new` (and `settle run`) command is run with `--allow-phase-collision`
Then the guard is bypassed and the command proceeds (the local same-dir `existsSync` guard is
unaffected by the flag).

### AC-6: Settle backstop catches the scaffold-race
Given `state.activePhase` whose number collides with a sibling worktree or upstream
When `cadence settle run` runs
Then an early precondition in `settleService` (excluding self via `excludeNumbers`) refuses with the
same named-conflict message before the gates run, honoring `--allow-phase-collision`; this is a
cross-cutting precondition, not a profile×tier gate-matrix cell.

### AC-7: `phaseGuard` config with back-compat defaults
Given a `.cadence/config.json` with or without a `phaseGuard` block
When config is loaded
Then `phaseGuard: { enabled: boolean (default true), integrationRef: string (default "main") }`
validates; omitting the block applies defaults; `enabled: false` disables the guard entirely; and
`integrationRef` retargets the upstream check.

## Constraints

- Two-unit split: pure `phases/collision.ts` (no I/O, trivially unit-tested — matches
  `buildAnthropicClientConfig` / `resolveLogLevel` seam style) + impure `phases/occupancy.ts`
  built on the existing read-only `git()` exec wrapper (`handoff/git-facts.ts` pattern).
- Observe ground truth (Approach A) — the worktree list IS the registry, phase dirs ARE the claims.
  No reservation/allocation registry, no auto-renumber, no proactive next-free in `progress`/`recommend`.
- Best-effort collector: any git/fs failure on a source yields no data, never an exception.
- Settle backstop is a `settleService` precondition, NOT a new gate in the 13-gate matrix.
- TDD house style: each AC referenced by `AC-N` token in a test under `packages/core/tests/`; the
  collector test uses a real multi-worktree testkit fixture (sibling worktree + local bare remote).

## Open Questions

- Whether `cadence doctor` also surfaces a read-only cross-worktree phase-usage line (cheap,

- `nextFree` = strict `max(observed) + 1` (leaning this — monotonic, readable-roadmap intent) vs
  lowest-free-gap. Pin during planning.
