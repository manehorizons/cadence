# 142-01 — Extract worktree discovery + cross-worktree handoff candidates

## Objective

Extract the existing git-worktree-discovery plumbing out of the phase-collision guard into a shared module, then build a new best-effort `gatherHandoffCandidates` primitive that discovers one resumable handoff candidate per worktree (local + siblings) — the pure/core foundation for a future cross-worktree `cadence resume` picker, with zero behavior change to phase-collision guarding or today's `cadence resume`.

## Acceptance Criteria

### AC-1: worktree-discovery extraction is behavior-preserving
Given `packages/core/src/phases/occupancy.ts`'s existing `git worktree list --porcelain` discovery + self-exclusion plumbing
When it is extracted into a new shared module `packages/core/src/git/worktrees.ts` and `occupancy.ts` is rewired to import from it
Then `packages/core/tests/phases/occupancy.test.ts` passes unmodified — the extraction changes structure, not behavior

### AC-2: listSiblingWorktrees discovers siblings, excludes self, never throws
Given a repo with zero or more sibling git worktrees
When `listSiblingWorktrees(repoRoot)` runs (real `git worktree add` fixtures, not mocks)
Then it returns each sibling's absolute path + branch, excludes the calling worktree itself (realpath-normalized comparison), and resolves to `[]` on any git/fs failure rather than throwing

### AC-3: HandoffCandidate schema is additive
Given the current `ResumeResultZ` discriminated union in `packages/types/src/handoff.ts`
When `HandoffCandidateZ` is added and `ResumeResultZ`'s `found:true` branch gains optional `candidates`/`pickedSource`/`pickedWorktree` fields
Then existing `ResumeResultZ` values without those fields still parse successfully (additive, non-breaking)

### AC-4: gatherHandoffCandidates returns one enriched candidate per worktree
Given a repo with a local handoff doc and one or more sibling worktrees that also have handoff docs (real `git worktree add` fixtures)
When `gatherHandoffCandidates(repoRoot)` runs
Then it returns one candidate per worktree (its freshest doc via the existing `locateFreshestHandoff`), each carrying frontmatter metadata (`generatedAt`, `label`, `loopPosition`, `activePhase`, `gitBranch`) plus — for siblings — that worktree's own live `state.json` loop position, ranked freshest-first

### AC-5: gatherHandoffCandidates degrades gracefully per source
Given a sibling worktree with no `.cadence/handoff/` directory, a corrupt or missing `state.json`, or a worktree path that `git worktree list` still reports but no longer exists on disk
When `gatherHandoffCandidates(repoRoot)` runs
Then that sibling contributes nothing to the result and the call never throws — one bad source never breaks discovery of the others
