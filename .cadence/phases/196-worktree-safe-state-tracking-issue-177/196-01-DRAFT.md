# 196-01 — Worktree-safe state tracking (issue #177)

## Objective

Fix issue #177 (`.cadence/state.json`/`STATE.md` tracked-file cross-worktree
merge conflicts) by making the four CADENCE-owned ephemeral paths
(`state.json`, `STATE.md`, `mcp-trust.json`, `intelligence/context/`)
gitignored by default with a `doctor --fix` migration path; preserving the
audit-trail value a tracked `state.json` used to carry incidentally via a new
`stateAtSettle` snapshot in `SUMMARY`; sharpening diagnosis and adding a
guided repair path for the conflict-marker corruption case the issue
actually hit in production; and self-migrating this repo's own tracked
`.cadence/` state onto the new convention.

## Acceptance Criteria

### AC-1: gitignore scaffolding
Given a fresh repo initialized with `cadence init`
When init completes
Then the repo's root `.gitignore` contains entries for
`.cadence/state.json`, `.cadence/STATE.md`, `.cadence/mcp-trust.json`, and
`.cadence/intelligence/context/`, and re-running the entry-writer is
idempotent (no duplicate lines)

### AC-2: doctor detects tracked ephemeral state
Given a repo where any of the four CADENCE-owned ephemeral paths is tracked
by git
When `cadence doctor` runs
Then it reports a failing `state-tracked` check naming the tracked paths,
and reports passing when none are tracked (including degrading to a
pass/no-info outside a git repo, never throwing)

### AC-3: doctor --fix untracks state
Given `cadence doctor` reports the `state-tracked` check failing
When `cadence doctor --fix` runs
Then the missing `.gitignore` entries are written and the tracked paths are
staged for removal via `git rm --cached`, with nothing committed
automatically

### AC-4: stateAtSettle snapshot
Given a settle run completes
When `SUMMARY.json`/`SUMMARY.md` are written
Then they contain a `stateAtSettle` block reflecting the loop state as of
immediately before the reset to IDLE

### AC-5: conflict-marker diagnosis and repair
Given `.cadence/state.json` contains unresolved git conflict markers
When `cadence doctor` runs
Then it reports a field-by-field local/incoming diff instead of the old
generic "restore from VCS" text, and `cadence doctor --fix
--resolve-state-conflict=local` (or `=incoming`) writes the chosen side
through the normal state-commit path, regenerating `STATE.md` correctly

### AC-6: CLI surfaces a repair pointer on corrupt state
Given any `cadence` command that reads `state.json` encounters a
`StateCorruptError`
When the CLI's top-level error handler catches it
Then the printed error includes a pointer to `cadence doctor --fix`

### AC-7: this repo self-migrates
Given phase 196 has shipped the untracking mechanism
When `cadence doctor --fix` runs on this repo (the CADENCE repo itself)
Then this repo's own `.cadence/state.json`, `STATE.md`,
`.cadence/mcp-trust.json`, and `.cadence/intelligence/context/` become
untracked, and `docs/concepts.md` + `CLAUDE.md` are updated to describe the
new gitignored convention

### T4: Conflict-marker diagnosis in checkState
- files: `packages/core/src/doctor/run.ts`, `packages/core/tests/doctor/run.test.ts`
- action: In `checkState`'s existing corrupt-JSON catch branch
  (`doctor/run.ts`, ~line 69-78), before falling back to the generic
  "state.json is not valid JSON" message, test the raw file content against
  a conflict-marker shape (`<<<<<<<` / `=======` / `>>>>>>>` each on their
  own line). If it matches, split into the section between `<<<<<<<` and
  `=======` (label it `local`) and the section between `=======` and
  `>>>>>>>` (label it `incoming`) — never `ours`/`theirs`, since that
  labeling flips between `git merge` and `git rebase` and the check can't
  know which produced the conflict. `JSON.parse` + `CadenceStateZ.safeParse`
  each side independently, and build the failing check's detail as a
  field-by-field diff over `activePhase`, `loopPosition`, `activeDraft`,
  `revision`, `session` (only fields that differ between the two sides),
  tagged `fixId: 'resolve-state-conflict'`. Non-conflict-marker corruption
  (or a conflict block where either side fails to parse/validate) keeps
  today's generic message and `fixId: null` — never guess.
- verify: `pnpm --filter @manehorizons/cadence-core test -- doctor` passes
  with new fixtures: clean conflict markers with two valid JSON sides
  (diff reported, `fixId` set), and non-conflict-marker garbage (message
  unchanged, `fixId: null`).

## Boundaries

- DO NOT touch `resolveStateDir()`, `SimpleStateBackend`'s write paths, the
  Phase-173 `revision` optimistic-concurrency check, or the Phase-194
  telemetry-exempt write path — this phase is a git-tracking change only,
  never a state I/O behavior change.
- DO NOT relocate `state.json`/`STATE.md` outside `.cadence/` (a possible
  future escalation, explicitly deferred, not this phase).
- DO NOT add a new top-level `cadence state`/`cadence repair` command —
  repair stays under `doctor --fix`.
- DO NOT attempt to re-derive loop position from phase artifacts for
  non-conflict-marker corruption — `checkState` keeps its existing "restore
  from VCS, or re-init" guidance for that case, unchanged.
- DO NOT make `doctor --fix`'s `untrack-state` or `--resolve-state-conflict`
  actions auto-commit anything — they stage/write only; the operator (or,
  for T7's self-migration, this phase's own feature commit) commits
  deliberately.
- DO NOT change read/write behavior for `mcp-trust.json` or
  `intelligence/context/` — only their git-tracking status.
