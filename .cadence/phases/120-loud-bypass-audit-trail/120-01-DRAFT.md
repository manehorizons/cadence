# 120-01 — Loud bypass audit trail

## Objective

Make settle gate bypasses visibly and durably auditable by recording them in SUMMARY artifacts and printing a clear settle-time warning whenever a bypassed verification path is accepted.

## Acceptance Criteria

### AC-1: SUMMARY JSON records gate bypasses
Given a BUILD draft that settles only because a verification bypass flag was used
When `cadence settle run` writes `SUMMARY.json`
Then the summary includes a `gateBypasses` array naming the gate, flag, and reason.

### AC-2: SUMMARY Markdown renders a bypass audit section
Given a summary with bypass records
When `SUMMARY.md` is rendered
Then it includes a `## Gate bypasses` section with each bypass called out.

### AC-3: settle emits a loud stderr warning for bypasses
Given a settle run proceeds with a bypass record
When the command completes
Then stderr contains a `settle bypass` warning for each recorded bypass.

### AC-4: clean settles remain unchanged
Given a settle run has no bypass records
When `SUMMARY.json` and `SUMMARY.md` are written
Then `gateBypasses` is absent and the Markdown omits the bypass section.

## Tasks

### T1: Add durable bypass records to summaries
- files: `packages/types/src/summary.ts`, `packages/core/src/parse/summary-writer.ts`, `packages/core/src/services/settle.ts`
- action: Define an optional summary `gateBypasses` array, derive records from settle anomaly/bypass signals, and render them in Markdown.
- verify: `pnpm --filter @manehorizons/cadence-core test -- settle-anomaly settle-deep settle-coverage summary-writer`
- done: AC-1, AC-2, AC-4

### T2: Print settle-time bypass warnings
- files: `packages/core/src/services/settle.ts`, `packages/core/tests/cli/settle-anomaly.test.ts`
- action: Emit a visible `settle bypass [...]` stderr line for each durable bypass record.
- verify: `pnpm --filter @manehorizons/cadence-core test -- settle-anomaly`
- done: AC-3

## Boundaries

- Do not change which bypass flags are allowed or refused.
- Do not make anomaly-notify required for SUMMARY bypass records.
- Do not change the existing anomaly event schema.
