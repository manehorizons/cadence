# 135-01 — init --demo: suppress conflicting next-step blocks

## Objective

`cadence init --demo` seeds a phase and leaves the loop in DRAFT, but still
prints the generic "Your first loop" block (whose step 1 is `cadence draft
new`) and the "Hand it to your AI agent" block/agent prompt — both of which
immediately refuse (`loopPosition is DRAFT`) if followed, because a phase is
already open. Suppress both generic blocks when `--demo` seeded a phase, so
the only next-step instructions shown are the correct ones: approve → done
→ settle. Closes rec-20260701-005 / audit finding F5.

## Acceptance Criteria

### AC-1: --demo suppresses the generic "Your first loop" block
Given `cadence init --demo` successfully seeds a demo phase
When init prints its output
Then the "Your first loop" block (and its `cadence draft new ...` step) is
not printed

### AC-2: --demo suppresses the "Hand it to your AI agent" block
Given `cadence init --demo` successfully seeds a demo phase
When init prints its output
Then the "Hand it to your AI agent" block and the rendered agent prompt are
not printed

### AC-3: the demo-specific instructions still print, unchanged
Given `cadence init --demo` successfully seeds a demo phase
When init prints its output
Then the "Demo phase ready" block (approve → done → settle) is still printed
exactly as before

### AC-4: init without --demo is unchanged
Given `cadence init` runs without `--demo`
When init prints its output
Then the "Your first loop" block and the "Hand it to your AI agent" block are
still printed exactly as before

## Constraints

- Only touches the output branch already guarded by `demoSeeded` in
  `packages/core/src/cli/commands/init.ts` — no change to `draftNewService`,
  `renderDemoDraft`, or any other init behavior.
- Non-instructional summary lines (project/preset/gate-profile/verification
  status/host-wire notice) are unaffected either way — only the two
  step-by-step "what to run next" blocks are conditional on `demoSeeded`.
