# 190-01 — doctor --fix: auto-remediate handoff-retention

## Objective

`cadence doctor --fix` (phase 131) already auto-remediates `git-hooks`, `state-md`,
`agents-md` (auto) and `host-install`/`codex-host-install` (behind `--wire-host`).
Extend it to also auto-remediate the `handoff-retention` check: when
`handoff.retain` is unset and the SESSION-doc archive has grown past the
existing warn threshold (10), `--fix` should set `handoff.retain` to that
default and immediately prune the archive down to budget, reusing the
existing `pruneHandoffDir`/`selectPrunable` primitives (already used by
`run-handoff` on every handoff write) rather than reimplementing pruning.
This is a deliberately narrowed slice of `rec-20260709-002` — the other four
checks that currently fall through to `manual` (`worktree-phases`,
`verification-readiness`, `recommendation-shipped-drift`,
`coverage-mode-language-support`) stay manual; each requires a genuine
judgment call (who renumbers, real credentials, human ship-confirmation,
weakening a verification gate) that doctor cannot safely auto-decide. Do not
widen scope to those checks in this phase.

## Acceptance Criteria

### AC-1: a failing handoff-retention check classifies as auto-fixable
Given a report where the `handoff-retention` check has failed (severity
`warning`, i.e. `handoff.retain` is unset and doc count is at/above the
existing threshold)
When `planFixes` classifies that report
Then the resulting action has `fixId: 'handoff-retention'` and `kind: 'auto'`
(not `manual`) — mirroring how `checkGitHooks`/`checkState` already attach a
`fixId` to their failing branch

### AC-2: applying the fix sets handoff.retain and prunes the archive to budget
Given a repo with `handoff.retain` unset and more `SESSION-*.md` docs under
`.cadence/handoff/` than the default retain budget
When `cadence doctor --fix` (no `--dry-run`) applies the plan
Then `.cadence/config.json` has `handoff.retain` set to the default, the
`.cadence/handoff/` directory contains at most that many `SESSION-*.md`
files afterward, the current `state.session.lastHandoff` file is always
retained even if it would otherwise fall outside the newest N (matching
`selectPrunable`'s existing invariant), and a follow-up `runDoctor` reports
`handoff-retention` as `ok`

### AC-3: the fix is not offered when the check already passes
Given `handoff.retain` is already set, or the doc count is below the warn
threshold (i.e. `checkHandoffRetention` reports `ok`, unchanged from today)
When `cadence doctor --fix` runs
Then no `handoff-retention` action appears in the fix plan and nothing under
`.cadence/handoff/` or `.cadence/config.json` is touched by this repair

  from `packages/core/src/handoff/retention.ts` as-is.
- DO NOT add a new runtime dependency.
- DO NOT change the CLI surface (`--fix`/`--wire-host`/`--dry-run` flags) —
  this is purely a new classified repair inside the existing fix pipeline.
