# 188-01 — cadence quickstart: single mega-command for full setup

## Objective

Collapse `cadence init`'s three opt-in setup flags (`--wire-host`, `--demo`, `--activate`) into one new `--full` flag, so a newcomer with a supported host present and `ANTHROPIC_API_KEY` in env can run a single command and land fully wired — host installed, a demo phase seeded, real verification activated — with a clear summary of what ran and what was skipped (and why). Zero-flag `cadence init` behavior is unchanged.

## Acceptance Criteria

### AC-1: --full composes all three existing behaviors
Given a repo with a `.claude/` workspace present and `ANTHROPIC_API_KEY` set in the environment
When the user runs `cadence init --full`
Then the Claude Code host is wired (no prompt), a demo phase (`01-demo`) is seeded in DRAFT, and real verification is activated (`verifier.provider=anthropic`) — matching what `--wire-host --demo --activate` together already produce today.

### AC-2: --full degrades safely when preconditions are missing
Given a repo with no `.claude/`/`.codex` workspace and no `ANTHROPIC_API_KEY` in the environment
When the user runs `cadence init --full`
Then init completes successfully (exit 0), skips host-wire and activation without hanging or erroring, still seeds the demo phase, and the summary explains what was skipped and why.

### AC-3: consolidated "what I did/skipped" summary
Given `cadence init --full` has finished running (any precondition combination)
When the output is inspected
Then a single summary section lists each of host-wire / demo-seed / activation as done or skipped-with-reason, instead of the three separate scattered blocks the individual flags print today.

> **As built:** the summary is printed *in addition to* the existing
> per-feature messages, not in place of them — replacing them turned out to
> be unnecessary friction (users still benefit from seeing each block as it
> happens) and would have meant suppressing output that `--wire-host`/
> `--demo`/`--activate` already print on their own when passed without
> `--full`. `docs/reference/commands.md`'s behavior note reflects this.

### AC-4: --full is purely additive — no behavior change without it
Given a repo with `.claude/` present and `ANTHROPIC_API_KEY` set
When the user runs bare `cadence init` (no `--full`, no other flags)
Then behavior is byte-for-byte identical to current `main` — interactive host-wire prompt on TTY, no demo phase, no activation, current messaging blocks unchanged.

### AC-5: --full composes with explicit conflicting flags predictably
Given the user passes both `--full` and `--skip-host-wire`
When `cadence init --full --skip-host-wire` runs
Then the explicit `--skip-host-wire` wins (host is not wired) while demo-seed and activation from `--full` still apply — i.e. `--full` sets defaults for the three flags but explicit flags override it, not the reverse.

## Boundaries

- DO NOT name anything from this phase `quickstart` — `cadence quickstart` already exists as a separate, intentionally read-only orientation command (`packages/core/src/cli/commands/quickstart.ts`); do not rename, extend, or duplicate it.
- DO NOT add `.cursor/`/`.mcp.json`/generic-MCP host auto-detection — no adapter exists for these hosts; out of scope (a third-host proposal was already evaluated and rejected for the same reason: gating can't be airtight for non-cadence hosts).
- DO NOT change bare `cadence init`'s (no flags) default behavior — `--full` is additive only.
- DO NOT touch `--wire-host`/`--demo`/`--activate`'s individual semantics when passed explicitly without `--full` — only change how `--full` composes them.
- DO NOT modify the internal logic of host-wiring, activation planning, demo-draft rendering, or test-command detection — reuse as-is; this phase is a composition/flag layer only.
