# 280-01 — DP-B: Dispatch contract

## Objective

Make the dispatch contract enforceable at the moment a task outcome is recorded, closing rec-20260718-003/-004/-005: stop-conditions as a machine-readable DRAFT field, boundary+redundancy checks with a real block path at record time (not just settle), and side-channel documentation for the AskUserQuestion gap.

## Acceptance Criteria

### AC-1: Stop-condition renders, byte-identical when absent
Given a task with a declared stop: field
When its packet renders
Then the line **Stop condition:** <stop text verbatim> appears in the packet body in the same bold-label style as **Recommended isolation:** (not a markdown heading); given a task with no stop: declared, the packet is byte-identical to a pre-DP-B fixture captured before packet.ts changes

### AC-2: Block mode refuses on a stray file; bypass records + flags it
Given effectiveBoundaryEnforcement resolves to 'block' for the active phase (via config, draft override, or the dispatch-scoped escalation when any task has been recorded with execution:dispatch), a draft is loaded, and a working-tree/committed file exists outside the union of all declared files: (excluding .cadence/** self-writes and files already attributed to a previously-recorded task -- first-sighting semantics)
When cadence build task T2 --status=DONE (or --status=DONE_WITH_CONCERNS) runs
Then it exits 1, PROGRESS.json gains no new/changed entry for T2, and stderr names each stray file and its nearest owning task. Given --allow-boundary-breach instead, T2 is recorded with its git-derived touchedFiles, and an error-severity files-outside-boundary anomaly is emitted per stray file carrying context.bypassed:true and context.taskId:'T2'

### AC-3: Warn mode is near-invisible except for the anomaly and ground-truth touchedFiles
Given effectiveBoundaryEnforcement resolves to 'warn' (default)
When cadence build task T2 --status=DONE or --status=DONE_WITH_CONCERNS runs with a stray file present
Then exit code and PROGRESS mutation are unchanged from pre-DP-B behavior except: progress.tasks.T2.touchedFiles is now the git-derived delta (not self-report), and one warn-severity files-outside-boundary anomaly per stray file is emitted via the notifier when anomaly-notify is in the active gate set. Given draft===undefined at record time, the boundary/redundancy step is skipped with a stated reason and touchedFiles falls back unchanged to the pre-DP-B self-report path -- never a silent blend. Given the declared-files union is empty, the step is skipped with a stated reason under the same rule

### AC-4: No git degrades gracefully
Given a repository with no .git directory or a failing git shell-out
When cadence build task T1 --status=DONE runs
Then collectUnscopedTouchedFiles returns an empty best-effort result without throwing, the boundary/redundancy step reports skipped: git unavailable (or equivalent) on stderr, and recording still succeeds (exit 0) using the existing self-report fallback for touchedFiles

### AC-5: Execution provenance survives to SUMMARY, additive-only
Given cadence build task T1 --status=DONE --execution dispatch --isolation worktree --model-class standard runs and the phase later settles (both a normal settle and a refused-settle path are exercised)
When PROGRESS.json and SUMMARY.json are inspected
Then progress.tasks.T1 and SUMMARY.json.taskResults's matching entry both carry {execution:'dispatch', isolation:'worktree', modelClass:'standard'}, schemaVersion is unchanged, and cadence summary verify-all reports MATCH for every historical SUMMARY in the corpus

### AC-6: Side-channel documentation lands where it's missing
Given docs/host-adapters.md's Declare capabilities section
When inspected
Then it carries a callout stating a dispatched agent's AskUserQuestion can be answered on a surface the orchestrator never sees, the packet forbids it at runtime, and human approval must flow through the orchestrating session; grep -rn AskUserQuestion docs/ matches in docs/host-adapters.md and/or docs/claude-code.md, not only in packages/core/src/dispatch/packet.ts; existing doc-content tests (docs-published.test.ts, both host packages) still pass unmodified

### AC-7: Missing stop: on a dispatch-shaped task warns, never blocks
Given a task that declares one or more files: and no stop:
When cadence draft check runs
Then a warn-severity coherence issue (code STOP_CONDITION_MISSING) names the task, and is never a block; a task with no files:, or with a declared stop:, produces no such warning

## Boundaries

- DO NOT enforce anything inside the dispatched agent itself -- the contract binds at the recording seam the orchestrator alone touches.
- DO NOT change settle's phase-level check logic -- only its enforcement input (via the dispatch-scoped escalation) may change; the gate's own mechanics stay untouched.
- DO NOT close the `cadence done <id>` unenforced-recording-path gap in this phase -- pre-existing (per-task-verify already skips it too), not introduced here. File a recommendation instead (T17).
- DO NOT add worktree lifecycle automation.
- DO NOT populate or touch `TaskZ.touchedFiles` (the DRAFT schema field) -- it stays genuinely unused. B2 populates the runtime `progress.tasks[id].touchedFiles` field instead. Do not conflate the two.
- DO NOT give the redundancy check at the record seam a block path -- warn-only, mirrors existing precedent. `--allow-boundary-breach` bypasses boundary only, never redundancy.
- DO NOT bump `schemaVersion` or add a `.default()` to any new `SummaryZ`/`ProgressJson` field -- additive/optional only (phase-239/263 precedent).
- DO NOT relitigate decisions dec-20260815-002 (D-DQ2) or dec-20260815-004 (D-DQ4) mid-build.
- DO NOT touch `packages/core/src/dispatch/policy.ts`, `packages/core/src/dispatch/wave-planner.ts`, or `packages/core/src/services/dispatch.ts` -- those are DP-A's territory (already shipped, phase 279); this phase only reads `TaskZ.class`/`heuristicTaskClass` where needed, never modifies them.
