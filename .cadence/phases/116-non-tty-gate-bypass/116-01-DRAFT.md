# 116-01 — non-TTY auto-bypass for the two loop gates

## Objective

Eliminate the `StdinPrompter: stdin is not a TTY` error class for AI agents and CI
by having the two loop-blocking interactive gates (approve, settle
interactive-verdict) detect non-TTY and auto-bypass with a loud, honest notice —
instead of hard-failing with a buried fix-flag hint. (rec-20260617-005)

## Design notes

A single pure decision seam both gates consult — `resolveInteractivity(env, isTTY)
→ 'interactive' | 'bypass' | 'require-tty'` — drives behavior. Env precedence:
`CADENCE_REQUIRE_TTY` (force the old throw/refuse) wins over
`CADENCE_NONINTERACTIVE` (force bypass even under a TTY, for pty-allocated agents);
with neither set, the mode follows `isTTY` (TTY → interactive, non-TTY → bypass).

A supplied `CADENCE_PROMPTER_SCRIPT` (the existing scripted-answers seam) wins
over all of them → `interactive`: explicit human-authored answers were provided,
so the prompt is honored, never bypassed (this also keeps every existing
non-TTY scripted CLI test running the real walker).

| `CADENCE_PROMPTER_SCRIPT` | `CADENCE_REQUIRE_TTY` | `CADENCE_NONINTERACTIVE` | `isTTY` | mode |
|---|---|---|---|---|
| set | * | * | * | `interactive` |
| unset | `1` | * | * | `require-tty` |
| unset | unset | `1` | * | `bypass` |
| unset | unset | unset | `true` | `interactive` |
| unset | unset | unset | `false` | `bypass` |

Honesty: every auto-pass is loud (stderr notice) and leaves provenance; no human
verdict is ever fabricated. The settle walker is **skipped** (not auto-confirmed) —
test-coverage + deep-verify still decide the outcome.

## Acceptance Criteria

### AC-1: pure interactivity resolver covers the full env/TTY table
Given the env vars `CADENCE_REQUIRE_TTY` / `CADENCE_NONINTERACTIVE` and an `isTTY`
flag in any combination
When `resolveInteractivity(env, isTTY)` is called
Then it returns `require-tty` whenever `CADENCE_REQUIRE_TTY=1` (regardless of the
others), else `bypass` when `CADENCE_NONINTERACTIVE=1`, else `interactive` when
`isTTY` is true, else `bypass` — with no I/O.

### AC-2: approve gate auto-passes in bypass mode
Given the approve gate fires and `resolveInteractivity` yields `bypass` (non-TTY,
no `CADENCE_REQUIRE_TTY`)
When the gate runs
Then it never constructs a `StdinPrompter`, emits the loud notice
`note: non-TTY; approve gate auto-passed (set CADENCE_REQUIRE_TTY=1 to restore the
prompt)` to stderr (the audit trail — the draft flow has no SUMMARY to persist
into), never throws, and returns `pass`.

### AC-3: approve gate still refuses under CADENCE_REQUIRE_TTY in non-TTY
Given the approve gate fires in a non-TTY with `CADENCE_REQUIRE_TTY=1`
When the gate runs
Then it behaves as today — the prompter throws and the gate refuses with the
existing `manual-approve: … Pass --no-approve to bypass …` hint.

### AC-4: settle interactive-verdict skips the walker in bypass mode
Given the settle interactive-verdict gate fires and `resolveInteractivity` yields
`bypass`
When settle runs
Then the per-AC walker does not run, the gate passes, and the SUMMARY records the
interactive verdict as skipped due to non-TTY (no fabricated per-AC confirmations).

### AC-5: settle interactive-verdict still refuses under CADENCE_REQUIRE_TTY in non-TTY
Given the settle interactive-verdict gate fires in a non-TTY with
`CADENCE_REQUIRE_TTY=1`
When settle runs
Then it behaves as today — the gate refuses rather than auto-bypassing.

## Boundaries

- DO NOT add an agent-mode preset or a new `config.json` knob — env-driven only.
- DO NOT change `cadence init` (already degrades to defaults in non-TTY) or the
  explicitly-interactive commands (`activate`, `config edit`, `start`).
- DO NOT auto-confirm settle ACs — skip the walker; never fabricate human verdicts.
- DO NOT alter `mention`-mode coverage or any gate's firing condition beyond the
  interactive prompt step.
