# 291-01 — Packs Slice 2: skillAudit.required contribution with provenance

## Objective

Make a pack's `skillAudit.required` a real, behavioral contributor to `runSkillAuditCheck`'s `effectiveRequired` set, with per-requirement provenance (`config`/`draft`/`pack:<id>`) recorded in `SUMMARY.json` (D-AS). This is the first slice where a resolved pack does anything — so `cadence doctor`'s `packs` check also escalates from warning to a hard settle-time refusal for an enabled-but-unresolvable pack, per `dec-20260822-025`'s two-phase D-AR plan reaching phase two. See `docs/packs-design.md` §7 Slice 2.

## Acceptance Criteria

### AC-1: a pack-declared required skill enforces exactly like a config-declared one
Given a pack enabled and successfully resolved with `skillAudit.required: [...]` in its manifest, and that required skill absent from `ctx.state.skillAudit.invoked`
When `cadence settle run --auto` runs the skill-audit check
Then the pack-declared skill is unioned into `effectiveRequired` alongside config's `skillAudit.required` and the DRAFT's `requiredSkills`, and settle refuses exactly as it would for a config-declared miss (same telemetry-off warn path, same `--allow-skill-audit-miss` bypass) — and on the null-config path (config failed to load), resolved packs contribute nothing and today's existing null-config behavior (compute the narrower set, skip enforcement, never false-refuse) is unchanged

### AC-2: SUMMARY.json attributes each required skill to its source(s), schema stays additive
Given the unioned `effectiveRequired` set drawn from config, the DRAFT, and zero or more resolved packs
When settle records the skill-audit result
Then `SUMMARY.json`'s skill-audit section carries a `provenance: {skill, source: 'config'|'draft'|'pack:<id>'}[]` entry per (skill, source) pair — a skill required by two sources yields two entries, never one collapsed row — and the new field is `.optional()` with NO `.default(...)` on both `CadenceStateZ.skillAudit` and `SummaryZ.skillAudit` (mirroring the `coverageScheme`/`providerSelection` precedent), so a pre-Slice-2 SUMMARY still parses with the key genuinely absent (not defaulted-in) and its content hash still verifies after a schema round-trip

### AC-3: settle resolves packs itself; the Slice-1 structural boundary is deliberately, narrowly moved
Given `services/settle.ts` must call `resolvePacks` to compute the set AC-1/AC-2 consume
When Slice 2 lands
Then `packages/core/tests/gates/engine.test.ts`'s structural no-coupling test (from phase 290) is amended in this same task: `packages/core/src/gates/**` remains asserted as fully free of any `packs/` import (Slice 3's boundary — untouched here), while `packages/core/src/services/**`'s prior blanket prohibition is replaced with a narrower, still-falsifiable assertion that only `services/settle.ts` imports from `packs/` (not scattered elsewhere in `services/`) — a deliberate, documented widening with an explanatory comment, never a silent deletion of the safeguard

### AC-4: an enabled-but-unresolvable pack refuses settle
Given a pack id listed in `config.packs.enabled` that fails to resolve (missing manifest, invalid JSON, or schema-validation failure)
When `cadence settle run` executes
Then settle refuses, naming the unresolvable pack id(s) and reason(s), bypassable only via a new dedicated `--allow-unresolvable-pack` flag that records the bypass in `SUMMARY.gateBypasses` (matching `--allow-skill-audit-miss`'s existing pattern) — this check is dispatched explicitly by settle outside the `Gate` enum/registry, the same way skill-audit already is (declaring/enabling a pack IS the opt-in), never added as a new `Gate` matrix member

### AC-5: `cadence doctor`'s `packs` check escalates from warning to error; docs stay in sync
Given the same enabled-but-unresolvable-pack condition AC-4 now refuses settle over
When `cadence doctor` runs
Then its `packs` check reports `error` severity (flipping `DoctorReport.ok` to false) instead of Slice 1's `warning`; `checkPacks`'s doc comment is rewritten to state the escalation has landed (it currently says "do not fix this into an error" — that instruction is superseded by this task, not silently ignored); `docs/reference/commands.md`'s `packs` doctor-check-table row and its settle-flags table (new `--allow-unresolvable-pack` row) both reflect the new behavior; `docs/packs-design.md`'s status banner and §7 Slice 2 marker are updated to record Slice 2 as shipped
