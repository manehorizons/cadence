# 259-01 — cadence doctor check: roadmap-currency

## Objective

Add a warning-only, non-blocking cadence doctor check comparing the highest phase number under .cadence/phases/ against the highest phase number referenced in ROADMAP.md/MILESTONES.md, warning when drift exceeds a threshold of 10 — closing the same gap that caused the 113-phase/6-week ROADMAP drift fixed in PR #321. fixId stays null deliberately: generating roadmap prose must never be automated.

## Acceptance Criteria

### AC-1: drift is reported using the lower of the two reference files
Given `.cadence/phases/` has at least one phase directory, and ROADMAP.md is not the fresh-init stub
When `cadence doctor` runs `roadmap-currency`
Then it reports `drift = highest_on_disk_phase_number - min(highest_phase_referenced_in_ROADMAP.md, highest_phase_referenced_in_MILESTONES.md)`, computed over **only the files that contain at least one `Phase N` heading** — using `min` across those (not either file alone) so a well-maintained ROADMAP.md cannot mask a MILESTONES.md that is genuinely lagging behind (has some phase entries, just fewer than ROADMAP.md's). A file with **zero** `Phase N` headings is excluded from the min entirely, not treated as `0` — nothing in the CLI ever writes MILESTONES.md's `- **Phase N** —` bullet convention (it's a hand-maintained prose file; `cadence init` only ever writes the one-line stub), so counting an all-zero MILESTONES.md as `0` would make every consumer repo warn permanently from the moment it scaffolds phase 11 onward, with a perfectly current ROADMAP.md. If *both* files have zero headings, fall through to AC-3's silent-pass path.

### AC-2: drift threshold — pass at ≤10, warning (never error) above it
Given the computed drift value
When drift is ≤ `ROADMAP_DRIFT_WARN_THRESHOLD` (10)
Then the check reports `severity: 'ok'`
And when drift is > 10, the check reports `severity: 'warning'` — never `'error'` — with `fixId: null` always (generating roadmap prose must never be automated; this is a human-only fix).

### AC-3: silent pass for a fresh consumer repo
Given `.cadence/phases/` contains no phase directories, OR ROADMAP.md contains no `### Phase N` headings (the freshly-`init`'d stub, or any hand-cleared equivalent)
When `cadence doctor` runs `roadmap-currency`
Then it reports `severity: 'ok'` silently — a brand-new consumer repo never sees this warning before it has phases to track.

### AC-4: best-effort — a read failure degrades to "not determinable", never throws
Given `.cadence/phases/`, `ROADMAP.md`, or `MILESTONES.md` cannot be read (missing, permissions, malformed) for any reason other than the fresh-init states covered by AC-3
When `cadence doctor` runs `roadmap-currency`
Then the check catches the failure and reports `severity: 'ok'` with a "not determinable (best-effort) — skipped" detail message, matching `checkPhaseFreshness`'s existing idiom (`packages/core/src/doctor/run.ts:1212`) — it never throws and never breaks the rest of the `doctor` report.

### AC-5: paired doc edit
Given `docs/reference/commands.md`'s `doctor` section
When a reader looks up the v1 check set table
Then it lists `roadmap-currency` alongside its severity (`warning`) and its `fixId: null` (manual-only) classification, mirroring how `conduction-reachability` is already documented there (`packages/core/tests/docs/cli-reference.test.ts:101`).
