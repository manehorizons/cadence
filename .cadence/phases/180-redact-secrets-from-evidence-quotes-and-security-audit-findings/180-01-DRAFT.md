# 180-01 — Redact secrets from evidence quotes and security-audit findings

## Objective

Prevent secrets/credentials from being persisted to disk verbatim by CADENCE's
own intelligence layer. Two known leak vectors: (1) `Evidence.summary` — a
free-text quote supplied via `addRecommendation`'s `evidenceSummary` and
written unmodified to `.cadence/intelligence/evidence.json`; (2)
`Finding.message` produced by the `security-audit` gate's verifiers
(mock/anthropic/local), written unmodified to `SUMMARY.securityAudit`. Add a
shared redaction utility, apply it at both write choke points, and restrict
the intelligence ledger JSON files to user-only file permissions on write.

## Acceptance Criteria

### AC-1: shared redaction utility recognizes common secret shapes
Given a string containing a credential-shaped substring (AWS access key
`AKIA[A-Z0-9]{16}`, GitHub token `gh[pousr]_[A-Za-z0-9]{20,}`, a bearer/basic
`Authorization:` header value, a JWT-shaped three-segment base64url string, a
PEM private-key block, or a generic `key=`/`token=`/`password=`/`secret=`
assignment with a non-trivial value) mixed with ordinary non-secret text
When `redactSecrets(text)` is called
Then every matched credential substring is replaced with a fixed redaction
placeholder and all non-matching text is returned unchanged

### AC-2: evidence summaries are redacted before persistence
Given `addRecommendation` is called with an `evidenceSummary` that contains a
credential-shaped substring
When the resulting `Evidence` record is written to
`.cadence/intelligence/evidence.json`
Then the persisted `Evidence.summary` has the credential substring redacted
(not the raw secret), while a plain non-secret `evidenceSummary` is persisted
unchanged

### AC-3: security-audit findings are redacted before landing on SUMMARY
Given the `security-audit` gate receives a `Finding.message` (from
mock/anthropic/local verifiers) that quotes a credential-shaped substring
from the diff
When the gate computes `summaryPatch.securityAudit`
Then the persisted finding's `message` has the credential substring
redacted, while `severity`/`line`/other fields and non-secret messages are
unchanged

### AC-4: intelligence ledger files are written user-only on POSIX
Given `writeIntelligenceLedgers`, `writeAssumptionLedger`, or
`writeIntelligenceDecisionLedger` writes a ledger JSON file to disk on a
POSIX platform
When the write completes
Then the resulting file mode is `0o600` (owner read/write only), and the
write never throws on a platform where the mode can't be fully honored
(best-effort, matching this repo's introspection/mutation convention)

## Tasks

- files: `packages/core/src/security/redact.ts`, `packages/core/tests/security/redact.test.ts`
- action: implement `redactSecrets(text: string): string` covering AWS
  access keys, GitHub tokens (`ghp_`/`gho_`/`ghu_`/`ghs_`/`ghr_`), bearer/basic
  Authorization header values, JWT-shaped strings, PEM private-key blocks,
  and generic `key=`/`token=`/`password=`/`secret=` assignments; replace each
  match with a fixed placeholder (e.g. `[REDACTED]`)
- verify: `pnpm --filter @manehorizons/cadence-core test -- packages/core/tests/security/redact.test.ts` passes, covering each pattern plus a non-matching-text-preserved case
- done: AC-1

  `redactSecrets` before constructing the `Evidence` record
- verify: test asserts a secret-bearing `evidenceSummary` persists redacted in the returned `Evidence` and in `.cadence/intelligence/evidence.json`; a non-secret summary is unchanged

- files: `packages/core/src/gates/security-audit.ts`, `packages/core/tests/gates/security-audit.test.ts`
- action: map `securityAuditFindings` through `redactSecrets` on `.message`
  when building `summaryPatch` (both the `pass` and `refuse` outcomes)
- verify: test asserts a `Finding.message` containing a credential-shaped string is redacted in the resulting `summaryPatch.securityAudit`; non-secret messages and other Finding fields are unchanged

- depends: T1

### T4: Restrict intelligence ledger file permissions to user-only
- files: `packages/core/src/state/atomic-write.ts`, `packages/core/src/intelligence/store/io.ts`, `packages/core/tests/state/atomic-write.test.ts`, `packages/core/tests/intelligence/store/io.test.ts`
- action: add an optional `mode` parameter to `atomicWriteJSON`/`atomicWriteText`
  (default behavior unchanged when omitted); pass `{ mode: 0o600 }` for the
  evidence/recommendations/assumptions/decisions JSON writes in
  `intelligence/store/io.ts`; wrap the mode-setting step so it never throws
  on platforms that don't fully honor POSIX file modes
- verify: test asserts `.cadence/intelligence/evidence.json` (and sibling ledger files) are written with mode `0o600` on POSIX; test is skipped/best-effort on `win32`
- done: AC-4

## Boundaries

- DO NOT redact `Recommendation.summary`/`Recommendation.title` or any other
  free-text field outside `Evidence.summary` and
  `SecurityAudit Finding.message` — out of scope for this recommendation.
- DO NOT change the default file mode for non-intelligence artifacts
  (`.cadence/state.json`, `STATE.md`, draft/build/summary files) — this
  phase only restricts the intelligence ledger JSON files named in AC-4.
- DO NOT add redaction to other `SUMMARY` finding arrays (`codeReview`,
  `planReview`, `specReview`) — not part of this recommendation's scope.
- DO NOT change the `.md` ledger renders beyond reflecting already-redacted
  underlying data (no new rendering logic).

## As built

- T3's implementer flagged, and this was fixed within T3's scope (same file,
  same `redactSecrets` import — no new task needed): the security-audit
  gate's stderr critical-finding log (`ctx.io.err` in
  `packages/core/src/gates/security-audit.ts`) was printing the raw,
  unredacted `Finding.message` even after `summaryPatch.securityAudit` was
  correctly redacted — a second leak channel via CI logs/terminal scrollback
  that AC-3's original wording didn't name. `criticals` is now derived from
  the already-redacted findings array instead of the raw verifier output, so
  the stderr line is redacted too.
