# 158-01 — Subagent task-redundancy monitoring

## Objective

Catch a subagent (or a human) touching a DRAFT task's declared files after that task is already marked DONE/DONE_WITH_CONCERNS -- live, at edit time and via a SubagentStop safety net -- closing the gap phase 155/156's file-boundary enforcement leaves open.

## Acceptance Criteria

### AC-1: Edit-time redundancy detection
Given an active DRAFT with a task already marked DONE or DONE_WITH_CONCERNS
When an edit touches a file owned by that task
Then handlePreToolEdit emits a redundant-task-work anomaly (warn mode) or refuses the edit naming the task and status (block mode), per the effective redundantWorkEnforcement

### AC-2: SubagentStart baseline + advisory nudge
Given a subagent is spawned while a DRAFT is active
When the SubagentStart hook fires
Then a per-agent baseline snapshot of every task's live status is stored and an advisory task-board nudge naming already-finished tasks is returned to the subagent

### AC-3: SubagentStop safety net
Given a subagent touched files owned by a task that was already terminal at its own baseline
When the subagent stops
Then the safety net emits a redundant-task-work anomaly (warn mode) or hard-blocks the stop naming the task and status (block mode), then prunes the baseline

### AC-4: Config and DRAFT frontmatter control
Given redundantWorkEnforcement is set to off, warn, or block at the config or DRAFT-frontmatter level
When effectiveRedundantWorkEnforcement resolves the mode for a phase
Then a DRAFT frontmatter override wins over the project config, which wins over the warn default

### AC-5: Documentation reflects real behavior
Given the feature is shipped
When docs/reference/config.md is read
Then it documents redundantWorkEnforcement and corrects the stale subagent-edits-are-invisible claim under boundaryEnforcement
