# 125-01 - Remove onboarding documentation drift

## Objective

Align onboarding-facing docs with current behavior for slash-command counts, `--preset` naming, and v1.29 non-TTY approve semantics.

## Acceptance Criteria

### AC-1: Slash-command counts are consistent
Given README, docs/README.md, and docs/claude-code.md describe the Claude Code adapter
When they mention installed slash commands
Then they agree on the current 12-command catalog.

### AC-2: Init docs prefer --preset over deprecated --profile
Given docs/cli.md and docs/reference/config.md explain init presets
When users copy example commands
Then the primary command uses `--preset`, and any `--profile` mention is clearly deprecated.

### AC-3: Non-TTY approve docs match v1.29 behavior
Given README and docs/cli.md explain `draft approve`
When they describe non-TTY behavior
Then they say the approve gate auto-passes loudly by default, with `CADENCE_REQUIRE_TTY=1` or `--no-approve` as explicit controls.

### AC-4: No runtime behavior changes
Given this phase is documentation drift cleanup
When it lands
Then runtime CLI, host adapter, MCP, and verifier source files remain unchanged.
