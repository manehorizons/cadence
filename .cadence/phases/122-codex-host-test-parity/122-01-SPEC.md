# 122-01 — Close Codex host adapter test parity

## Objective

Close the remaining Codex host-adapter parity gap with durable tests for local hook execution and prompt catalog parity.

## Acceptance Criteria

### AC-1: Codex local hook roundtrip
Given `installHooks(..., { local: true })` writes project `.codex/hooks.json`
When the generated `SessionStart` hook command is executed with a Codex hook payload
Then it invokes the local host shim and core CLI end-to-end and prints CADENCE session context.

### AC-2: Codex prompt catalog parity
Given Codex prompts are installed into a temporary `CODEX_HOME`
When generated prompt filenames are compared to the Claude command golden catalog
Then Codex exposes the same `cadence-*` command names, without missing or extra prompts.

### AC-3: Codex prompt format remains Codex-native
Given Codex prompts are installed
When prompt files are inspected
Then they use frontmatter plus terminal command blocks, include the managed marker, and never emit Claude-only `!` autorun or `allowed-tools` fields.

### AC-4: Existing Codex host tests remain green
Given the new parity tests are added
When `@manehorizons/cadence-host-codex` tests run
Then install, shim, adapter-conformance, CLI, and integration coverage all pass together.

## Constraints

- Prefer tests over production changes unless a parity test exposes real broken behavior.
- Do not touch global user Codex home; tests must use temp dirs.
- Do not weaken Codex prompt global-install warnings.

## Open Questions

- Should future work extract the host command catalog into a shared package to remove duplication?
