# 208-01 — Concurrent-session collision safety

## Objective

Add a `cadence doctor` check that warns when the active phase's `PROGRESS.json` shows very recent per-task activity (a possible live concurrent session), and fold the remaining concurrency-safety guidance from rec-20260722-001 into `CLAUDE.md` and the `phase-build`/`pr-land` skills as explicit operator/agent instructions.

## Acceptance Criteria

### AC-1: doctor warns on fresh task activity
Given an active phase/draft whose `PROGRESS.json` has a task `updatedAt` within the freshness threshold
When `cadence doctor` runs
Then it reports a `phase-freshness` check with `warning` severity, naming the task and how recently it was touched, with remediation to confirm no other session is live before continuing

### AC-2: doctor stays quiet otherwise
Given an active phase/draft whose `PROGRESS.json` has no task updated within the threshold, or there is no active phase/draft, or no `PROGRESS.json` has been written yet
When `cadence doctor` runs
Then the `phase-freshness` check reports `ok` severity, not `warning`

### AC-3: guidance for the remaining four rules is committed
Given CADENCE's own operator/skill documentation
When a session reads `CLAUDE.md`'s operator workflow or executes the `phase-build`/`pr-land` skills
Then it finds explicit, actionable guidance for: never running two sessions against the same phase/draft without confirming the old one is dead first, resuming in place rather than fresh elsewhere, isolating deliberately-parallel agent work to a worktree/branch from task 1 (not after noticing a conflict), and re-checking `git status` immediately before any shared-tree git operation (stash/reset/checkout on main)

## Tasks

### T1: pure freshness assessor
- files: `packages/core/src/phases/liveness.ts`, `packages/core/tests/phases/liveness.test.ts`
- action: add a pure `assessProgressFreshness(tasks, now, thresholdMs)` that, given a map of task id → `updatedAt` ISO string, a reference `now`, and a threshold in ms, returns whether any task is "fresh" and which one is freshest (task id, `updatedAt`, age in ms). No I/O.
- verify: `pnpm --filter @manehorizons/cadence-core test -- tests/phases/liveness.test.ts`
- done: AC-1, AC-2

### T2: doctor check wiring
- files: `packages/core/src/doctor/run.ts`, `packages/core/tests/doctor/phase-freshness.test.ts`
- action: add `checkPhaseFreshness(root, now)` following the existing `checkHandoffRetention`/`checkWorktreePhases` pattern (best-effort, never throws, `pass`/`fail` helpers). Reads `state.json` for `activePhase`/`activeDraft`; if absent, `pass` with "no active phase/draft". Otherwise reads `.cadence/phases/<activePhase>/<activeDraft>-PROGRESS.json` (missing file → `pass`), runs `assessProgressFreshness` against a documented constant threshold (10 minutes), and returns `fail('warning', ...)` naming the task + age when fresh, `pass` otherwise. Wire into the checks array that feeds `rollup()`.
- verify: `pnpm --filter @manehorizons/cadence-core test -- tests/doctor`
- done: AC-1, AC-2

### T3: doctor check reference doc
- files: `docs/reference/commands.md`
- action: add a `phase-freshness` row to the existing doctor-checks table, matching the format/tone of the `worktree-phases`/`handoff-retention` rows.
- verify: `pnpm --filter @manehorizons/cadence-core test -- tests/docs`
- done: AC-1

### T4: fold remaining guidance into docs/skills
- files: `CLAUDE.md`, `.claude/skills/phase-build/SKILL.md`, `.claude/skills/pr-land/SKILL.md`
- action: add the four behavioral rules (session-liveness confirmation before resume, resume-in-place, worktree isolation from task 1 for deliberate parallelism, immediate pre-op `git status` re-check) as explicit guidance — CLAUDE.md's "How the operator works" / "Named failure modes" sections, `phase-build`'s "Isolate" step, `pr-land`'s preflight/commit-hygiene steps.
- verify: manual read-through; `grep` confirms each rule has an explicit anchor in at least one of the three files
- done: AC-3

## Boundaries

- DO NOT wire this check into `cadence resume` — it is deliberately read-only/doc-scoped (D10); this phase adds it to `doctor` only.
- DO NOT add a config knob for the freshness threshold. Hardcode a documented constant; revisit only if a future need for tuning it is demonstrated.
- DO NOT touch `packages/core/src/phases/occupancy.ts` or `collision.ts` — this is a new, separate check (task-timestamp freshness), not a change to phase-number collision detection.
- DO NOT rewrite historical `.cadence/phases/*` records when adding the CLAUDE.md guidance.
