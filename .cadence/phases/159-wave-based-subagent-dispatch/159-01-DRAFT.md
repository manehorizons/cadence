# 159-01 — Wave-based subagent dispatch

## Objective

Give CADENCE's engine a `cadence dispatch plan` surface that computes wave-based subagent dispatch groups (dependency + file-boundary aware) from a BUILD draft's task list, and a `/cadence-dispatch` host slash command that drives the host agent's parallel Task-tool dispatch loop over it.

## Acceptance Criteria

### AC-1: Task.depends schema + parser round-trip
Given a DRAFT.md task block with an optional `- depends: T1, T2` line
When the file is parsed via `parseDraftMd`
Then `Task.depends` is populated as a string array (undefined when the line is absent), and `DraftZ` validates the field end-to-end

### AC-2: wave planner correctness
Given a DRAFT's task list plus PROGRESS.json task statuses
When `computeWaves(draft, progress)` runs
Then it topologically levels by `depends:` (a terminal dependency counts as satisfied), applies a `files:`-disjointness veto within each level (cascading a bumped task forward again if it still collides), excludes DONE/DONE_WITH_CONCERNS tasks from every wave, and throws a clean, clearly-worded error (never a crash) on a dependency cycle or an unknown depends id

### AC-3: packet renderer
Given a task and its parent draft
When `renderPacket(task, draft)` runs
Then the returned string contains the phase objective, the task's action/verify/done fields, its `files:` boundary stated explicitly, a reminder about Spec 1's redundant-work monitoring, and the exact `cadence build task <id>` command the subagent must run to record its own outcome

### AC-4: `cadence dispatch plan` CLI command
Given the active BUILD draft and its PROGRESS.json (missing or malformed PROGRESS.json included)
When `cadence dispatch plan [--json]` runs
Then it renders the wave breakdown (JSON: `{ waves: [{ wave, tasks: [{ id, name, packet }] }] }`; text: grouped by wave), reports "nothing to plan" outside BUILD and "nothing to dispatch" when every task is already finished (both exit 0), degrades a missing/unparseable PROGRESS.json to an empty map without crashing, and exits non-zero with a clear message on a dependency cycle

### AC-5: `/cadence-dispatch` host command
Given `cadence-host-claude-code install` runs
Then it writes a 14th managed slash command, `/cadence-dispatch`, whose body drives the host agent through: read the wave plan, dispatch one Task-tool call per task in the current wave in parallel seeded with that task's rendered packet, re-check status after the wave returns, treat DONE/DONE_WITH_CONCERNS as clean completion and anything else (including no status at all) as a run-halting failure, and never invoke `cadence settle run` itself

### AC-6: docs stay truthful about the new command
Given the slash-command count changes from 13 to 14
Then README.md, docs/quickstart.md, and docs/claude-code.md all name the new count, docs/quickstart.md's table and docs/claude-code.md's table each list `/cadence-dispatch`, docs/reference/commands.md documents `cadence dispatch plan` and stays in sync with its `<!-- cadence:commands:start -->` drift-guard marker, and docs/concepts.md's DRAFT section mentions the optional `depends:` field
