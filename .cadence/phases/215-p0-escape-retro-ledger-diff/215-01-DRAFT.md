# 215-01 — P0 escape retro: ledger-diff step at audit close

## Objective

The v1.47.0 audit's assurance-levels P0 finding never reached the recommendation ledger even though half of it later shipped under other names (`dec-20260724-001` chose a mechanical ledger-diff step over a standing rule or a scout-id requirement); document that step as a named failure mode in `CLAUDE.md` — the doc every agent session, including audit sessions, reads first — and back it with a doc-content test so the instruction can't silently drift from what the test enforces.

## Acceptance Criteria

### AC-1: CLAUDE.md documents the ledger-diff step as a named failure mode
Given an agent session identifies critical/P0 findings during a strategic audit of the codebase
When the session is about to close
Then `CLAUDE.md`'s "Verification honesty (the thesis, applied to you)" section contains a named-failure-mode entry instructing the agent to enumerate those findings, check each against `.cadence/intelligence/recommendations.json` (by title/area/evidence keyword), and refuse to close the session on any finding with no matching rec until it is filed via `cadence recommendation add` — matching the existing entries' rule/Why/How-to-apply structure

### AC-2: a doc-content test asserts the entry exists so it can't silently drift
Given `CLAUDE.md` is expected to carry the ledger-diff failure-mode entry
When the test suite runs
Then a test reads root `CLAUDE.md` and asserts it contains the entry's heading and the key phrases `ledger-diff` and `cadence recommendation add`, so removing or garbling the entry fails CI rather than silently going stale
