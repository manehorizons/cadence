# 110-01 — Fold activation into init when API key present

## Objective

Let `cadence init --activate` turn on real verification in the same step when an
`ANTHROPIC_API_KEY` is already in the environment — writing `verifier.provider =
anthropic` (deep-verify seam) via the existing activate seam, never persisting
the key — so a user who already has a key reaches a real-verification loop with
no separate `cadence activate` hop and no mock scolding.

## Acceptance Criteria

### AC-1: `--activate` with a key wires anthropic without persisting the key
Given `ANTHROPIC_API_KEY` is set in the environment
When the user runs `cadence init --activate`
Then `.cadence/config.json` has `verifier.provider = "anthropic"` and the file
does NOT contain the key value.

### AC-2: without a key (or without --activate) it stays mock + points at activate
Given no `ANTHROPIC_API_KEY` (or `--activate` not passed)
When the user runs `cadence init`
Then `verifier.provider` stays `mock` and the output points at `cadence activate`
for turning on real verification.

### AC-3: the provider write reuses the activate seam (no duplicated logic)
Given the activation decision is made
When the provider is written into config
Then it goes through the shared activate plan/apply seam (`planActivation` +
`setPath`), not a bespoke config mutation.

### AC-4: non-TTY safe
Given stdin is not a TTY
When `cadence init --activate` runs (key set) or `cadence init` runs (no flag)
Then it completes without prompting and without hanging.

### AC-5: the mock-not-real notice is suppressed when real verification was wired
Given `cadence init --activate` wired anthropic
When the post-init summary is printed
Then the "mock is NOT real verification" block is replaced by a confirmation that
real verification is on (provider + seam).

## Tasks

### T1: Decide + apply activation during init
- files: `packages/core/src/cli/commands/init.ts`
- action: Add a `--activate` flag. Resolve a decision: `--activate` + key present →
  anthropic; otherwise mock. Apply the provider via the shared activate seam
  (`planActivation({ provider, scope: 'deep-verify', currentConfig: cfg })` +
  `setPath`) onto the config object before it is written. Never write the key.
- verify: tests assert `verifier.provider` and key-absence in config.json.
- done: AC-1, AC-3, AC-4

### T2: Honest summary — confirm or point at activate
- files: `packages/core/src/cli/commands/init.ts`
- action: When anthropic was wired, replace the `MOCK_VERIFIER_NOTICE` block with a
  "real verification on: anthropic (deep-verify)" confirmation; otherwise keep the
  existing mock-placeholder block + `cadence activate` pointer. If `--activate` was
  passed but no key is present, print the missing-key `export …` hint.
- verify: tests assert suppressed notice when wired, present when mock.
- done: AC-2, AC-5

### T3: Tests
- files: `packages/core/tests/cli/init-activate.test.ts` (new)
- action: Cover AC-1..AC-5 with the env seam (`ANTHROPIC_API_KEY`), reading back
  config.json + stdout. Non-TTY (subprocess) is the default harness.
- verify: the test passes; full core suite green.
- done: AC-1, AC-2, AC-5

## Boundaries

- DO NOT persist the API key anywhere (only the provider name is written).
- DO NOT perform a live provider ping in init (key validation stays in
  `cadence activate`); init only records the selection.
- DO NOT change `cadence activate`'s own behavior.
- DO NOT alter phase 108 (zero-prompt/auto-wire) or 109 (`--demo`) behavior.
