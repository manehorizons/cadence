# 199-01 — recommendation evidence add CLI writer

## Objective

Add `cadence recommendation evidence add <recId> --note <text>`, a tied-record
writer that atomically appends a new evidence entry to `evidence.json` and
links its id into the matching recommendation's `evidenceIds` in
`recommendations.json`. Today the only path to attach evidence to an
*existing* recommendation is a manual hand-edit of both files in lockstep,
which is easy to get out of sync — `cadence intelligence reconcile` does not
help because `deriveRecommendationLinks` only re-derives `assumptionIds`/
`decisionIds` from the assumption/decision ledgers, never `evidenceIds` from
the evidence ledger.

## Acceptance Criteria

### AC-1: adding evidence to an existing recommendation writes both ledgers atomically
Given a recommendation `rec-X` already exists in `recommendations.json`
When `cadence recommendation evidence add rec-X --note "<text>"` runs
Then a new `Evidence` record is appended to `evidence.json` with
`recommendationId: rec-X`, and `rec-X`'s `evidenceIds` in
`recommendations.json` includes the new evidence id, and `cadence
recommendation show rec-X` immediately reflects the new evidence without
requiring `cadence intelligence reconcile`

### AC-2: unknown recommendation id is refused, not silently created
Given no recommendation with id `rec-does-not-exist` exists
When `cadence recommendation evidence add rec-does-not-exist --note "<text>"` runs
Then the command exits non-zero with a `recommendation evidence add refused:
recommendation rec-does-not-exist not found` message and neither ledger file
is modified

### AC-3: evidence note text is redacted the same way `recommendation add --evidence` is
Given a `--note` value that contains a secret-shaped substring (e.g. an API
key pattern)
When `cadence recommendation evidence add <recId> --note "<text-with-secret>"` runs
Then the persisted `Evidence.summary` has the secret redacted via the same
`redactSecrets` choke point `addRecommendation` already uses

## Boundaries

- DO NOT touch `cadence intelligence reconcile` / `deriveRecommendationLinks` — this phase adds a direct writer, it does not change reconcile's assumption/decision-only re-derivation contract (that's `rec-20260719-001`'s own scope, not a separate follow-on to fold in here).
- DO NOT add a way to edit or remove existing evidence entries — append-only, matching `assumption add` / `decision add`'s existing tied-record shape.
- DO NOT change the shape or semantics of `recommendation add --evidence` (creation-time evidence) — this is strictly a new subcommand for the post-creation case.
