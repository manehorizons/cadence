# 119-01 — Auto-derive phase id and collapse --ac syntax

## Objective

Make the common CADENCE happy path less error-prone by letting `draft new` derive its phase/task identifiers, adding pass-oriented settle shorthands, and printing the new simpler next command from `cadence progress`.

## Acceptance Criteria

### AC-1: draft new derives phase and task id when positionals are omitted
Given an IDLE repo with existing phase occupancy
When the operator runs `cadence draft new --title "Auto Phase Id"`
Then CADENCE creates the next-free `N-auto-phase-id` phase with task id `N-01` and enters DRAFT.

### AC-2: draft new remains backward compatible with explicit positionals
Given an IDLE repo
When the operator runs `cadence draft new 01-foundation 01 --title=Demo`
Then CADENCE keeps creating `01-foundation/01-01-DRAFT.md` exactly as before.

### AC-3: settle pass shorthands produce AC pass verdicts
Given a BUILD draft with acceptance criteria
When the operator runs `cadence settle run --pass-all` or `cadence settle run --ac-pass AC-1`
Then the SUMMARY records the requested ACs as PASS without requiring `AC-1=pass` syntax.

### AC-4: progress prints the simplified next command
Given an IDLE repo
When the operator runs `cadence progress`
Then the next command is `cadence draft new --title "..."` instead of a phase/num positional template.

## Tasks

### T1: Derive draft identifiers and update progress guidance
- files: `packages/core/src/services/draft-new.ts`, `packages/core/src/cli/commands/draft-new.ts`, `packages/core/src/progress.ts`
- action: Make draft positionals optional, derive the phase slug from next-free occupancy + title when omitted, default task num to 1, and update IDLE progress output.
- verify: `pnpm --filter @manehorizons/cadence-core test -- draft-new progress next-free`
- done: AC-1, AC-2, AC-4

### T2: Add settle pass shorthands
- files: `packages/core/src/services/settle.ts`, `packages/core/src/cli/commands/settle.ts`
- action: Add `--pass-all` and `--ac-pass <id...>` and merge them with existing explicit AC verdict handling.
- verify: `pnpm --filter @manehorizons/cadence-core test -- settle`
- done: AC-3

## Boundaries

- Do not remove existing `draft new <phase> <num>` or `settle run --ac AC-1=pass` compatibility.
- Do not change state-machine loop requirements for draft, build, or settle.
