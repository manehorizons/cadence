# 140-01 — SUMMARY gate provenance

## Objective

Record per-gate ran/skipped provenance and per-AC evidence class in SUMMARY, so a settle's PASS verdicts are auditable instead of opaque.

## Acceptance Criteria

AC-1: SUMMARY.json's `gates` array records a `ran` or `skipped` (+ reason) status for every one of the 8 settle-dispatched gates, in GATE_ORDER, on every successful settle.
AC-2: Each SUMMARY.json `acResults[]` row carries an optional `evidence` class (`ai-verified` | `executed` | `assertion` | `mention` | `unverified`) reflecting the strongest real evidence found for that AC.
AC-3: A mock-provider deep-verify pass never produces `ai-verified` evidence — it falls through to the AC's test-coverage evidence.
AC-4: SUMMARY.md renders a `## Gate provenance` section (one line per gate) and an evidence tag next to each AC line, plus deep-verify token usage when present.
AC-5: SUMMARY.json/Summary records written before this phase (missing `gates`/`evidence`) still parse and render unchanged.
