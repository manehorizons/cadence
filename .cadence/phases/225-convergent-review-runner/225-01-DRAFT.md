# 225-01 — Deepen the convergent-review protocol

## Objective

`nextConvergence()` in `packages/core/src/verify/converge.ts` is a shallow
6-line pass/reloop/escalate classifier, but the real weight of "bounded
convergence" — reading the sidecar's prior attempts, calling the verifier,
computing the verdict, pushing a history entry, writing back the sidecar
JSON (with its legacy top-level fields preserved), and then branching on
bypass/reloop/escalate to print findings, emit an `*Unconverged` event, and
return a refusal — is copy-pasted at all 4 call sites: `plan-review.ts`,
`code-review.ts`, and `spec-approve.ts` (twice, for spec-review and
ui-spec-review). Extract a shared `runConvergentReview` primitive that all
four delegate to, so future convergence-protocol changes (e.g. survey #4's
settle-gate convergence) land in one place instead of a fifth copy-paste.
This is a **behavior-preserving refactor**: no change to the convergence
policy, the sidecar JSON on-disk shape, or any of the four distinct
`*Unconverged` notify payloads.

## Acceptance Criteria

### AC-1: A shared convergent-review runner exists and is used by all 4 call sites
Given the four duplicated read-sidecar → verify → `nextConvergence` →
push-history → write-sidecar → branch sequences in `plan-review.ts`,
`code-review.ts`, and `spec-approve.ts` (x2)
When the refactor is complete
Then all four sites delegate that sequence through a single shared
`runConvergentReview` primitive, each supplying only its call-specific
parts (the verify call, sidecar read/write, id field + value, bypass flag,
and its own `*Unconverged` emit callback) — no site re-implements the
sequence inline.

### AC-2: Sidecar JSON output is byte-identical to today's
Given the existing sidecar JSON shapes (`plan-review`'s `draftId` +
legacy 29.7 top-level fields; `code-review`'s `draftId` + legacy fields;
`spec-approve`'s `specId` + legacy fields, for both the spec-review and
ui-spec-review sidecars)
When the refactored code writes a sidecar after a review, for every
pass/reloop/escalate/bypass branch
Then the JSON output (keys, ordering, legacy fields) is unchanged from
today's — existing tests assert this and must pass without modification.

### AC-3: Per-site branching behavior is preserved exactly
Given `code-review`'s OR-bypass (`force === true || allowCodeReviewFailure
=== true`) and its try/catch wrapper around `verify()` with its own
throw-path bypass semantics, versus `plan-review`/`spec-approve`'s
single-flag bypass with no try/catch
When each site runs through the shared runner
Then `code-review`'s bypass-OR and exception handling remain intact
(either kept caller-side around the shared call, or expressed through the
runner's parameters without changing runtime behavior), and
`plan-review`/`spec-approve` keep their existing (non-catching) behavior
unchanged — no site gains or loses a try/catch it didn't have before.

### AC-4: Full regression coverage, plus direct unit tests on the shared runner
Given the current test suites for all 4 call sites (`gates/plan-review.
test.ts`, `gates/code-review.test.ts`, `services/spec-approve.test.ts`,
`cli/draft-plan-review.test.ts`, `cli/draft-approve-convergence.test.ts`,
`cli/settle-code-review.test.ts`, `cli/settle-codereview-convergence.
test.ts`, `notify/emit-unconverged.test.ts`)
When the refactor lands
Then the full existing suite passes with no test modified to accommodate
a behavior change, and new unit tests in `verify/converge.test.ts` (or a
sibling file) exercise the shared runner's pass/reloop/escalate/bypass
branches directly, independent of any single call site.

## Boundaries

- DO NOT change `nextConvergence`'s logic or the attempt/reloop/escalate
  thresholds — this is a dedup/shape refactor only, not a behavior change.
- DO NOT unify the four distinct `*Unconverged` emit/notify functions
  (`ctx.emit.planReviewUnconverged`, `ctx.emit.codeReviewUnconverged`,
  `emitSpecReviewUnconverged`, `emitUiSpecReviewUnconverged`) into one
  payload shape — they stay pluggable per call site.
- DO NOT touch `code-review.ts`'s `collectHighFindings` HIGH-only
  finding-severity filter — it stays local to code-review, not part of the
  shared runner.
- DO NOT change any sidecar JSON on-disk shape, key, or ordering for any
  of the four call sites.
- DO NOT touch `docs/concepts.md`'s gate matrix or any CLI-visible flag —
  no CLI behavior changes as part of this refactor.
