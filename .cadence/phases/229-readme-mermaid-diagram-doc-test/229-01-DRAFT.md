# 229-01 — README mermaid diagram doc-content test

## Objective

README.md's mermaid architecture diagram (lines ~34-55) names the four
`VerifierProvider` values and the three entry surfaces inline as diagram
labels, but unlike the version line, command counts, and config defaults —
each asserted against code truth by a doc-content test in
`packages/core/tests/docs/` — nothing checks this diagram against the real
source. Add a doc-content test that parses the diagram out of README.md and
asserts its verifier-provider list and surface-category list match the
actual code, mirroring the parse-source-text pattern used by
`packages/core/tests/docs/cli-reference.test.ts` and
`gates-sealed-doc-sync.test.ts` (read + regex/parse the real source file;
never hand-duplicate a second copy of the list as the "expected" value).

## Acceptance Criteria

### AC-1: diagram's verifier-provider list matches code truth
Given README.md's mermaid diagram lists `mock / anthropic / local / host-cli`
as verifier providers
When the new doc-content test runs
Then it parses the actual `VerifierProvider` union from
`packages/core/src/verify/verifier-factory.ts` (source text, not a
hand-copied literal) and asserts the diagram's provider list is exactly that
set — failing loudly if a provider is added, removed, or renamed in code
without the diagram being updated

### AC-2: diagram's surface-category list matches code truth
Given README.md's mermaid diagram lists three entry surfaces — `cadence CLI`,
`Host adapters (Claude Code + Codex)`, `cadence mcp serve` — matching
CLAUDE.md's canonical "one core engine and three surface categories"
vocabulary
When the new doc-content test runs
Then it asserts the diagram's surface labels correspond to the actual set of
published host-adapter packages (`pnpm-workspace.yaml` / each
`host-*` package's `package.json` name) plus the CLI and MCP surfaces —
failing loudly if a host adapter is added or removed without the diagram
being updated

## Tasks

### T1: Add the README architecture-diagram doc-content test
- files: `packages/core/tests/docs/readme-architecture-diagram.test.ts`
- action: create the test file. Read `README.md`, isolate the ` ```mermaid
  ... ``` ` block between the markers used elsewhere in this repo's
  doc-content tests (see `cli-reference.test.ts` for the extraction style),
  and parse the verifier-provider and surface-category labels out of it.

  lists equal their respective derived-from-source sets.
- verify: `pnpm --filter @manehorizons/cadence-core test -- readme-architecture-diagram`
  passes; each `it()` block references its `AC-N` token per the coverage

- done: AC-1, AC-2

## Boundaries

- DO NOT modify README.md's diagram itself — this phase only adds a test
  that verifies it against code truth; the diagram is currently accurate
  (confirmed manually during the v1.51.1 release cut).
- DO NOT hand-duplicate the verifier-provider or surface list as a second
  hardcoded "expected" array — derive both from parsing the real source
  files, or the test only proves two copies of the same guess agree, not
  that the diagram matches the code.
- DO NOT expand scope to other README sections or other docs; this is
  narrowly the mermaid diagram named in `rec-20260726-004`.
