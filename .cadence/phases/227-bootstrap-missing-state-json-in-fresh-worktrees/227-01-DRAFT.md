# 227-01 — Bootstrap missing state.json in fresh worktrees

## Objective

`rec-20260726-002`: a fresh `EnterWorktree` worktree carries the committed
`.cadence/` scaffold but never `state.json`/`STATE.md` (both gitignored since
phase 196, never copied by git). Every state-mutating command throws
`NotInitializedError` with "run `cadence init` to get started" — but `cadence
init` then refuses ("`.cadence/` already initialized in this directory"),
a dead end. `cadence onboard` (added in phase 196 for exactly this scenario,
per its `bootstrapMissingState` helper) already bootstraps a fresh
`state.json` safely, but nothing in the failure path surfaces it — hit live
2026-07-25 during phase 222, worked around by hand-authoring `state.json`.
Fix the two message dead-ends so the CLI's own error output routes the user
to the command that already solves this, instead of reimplementing
`onboard`'s bootstrap logic a second time (which `deja` would flag as a
duplicate, per `bootstrapMissingState` in `onboard.ts`).

## Acceptance Criteria

### AC-1: NotInitializedError distinguishes "never initialized" from "state.json missing from an existing scaffold"
Given `SimpleStateBackend.readState()` is called in a directory where `.cadence/` exists but `state.json` does not (the fresh-worktree shape)
When it throws `NotInitializedError`
Then the message says state.json is missing from an existing `.cadence/` scaffold and directs the user to `cadence onboard`, not `cadence init`
And the pre-existing case — `.cadence/` itself absent — still throws the original "run `cadence init` to get started" message unchanged

### AC-2: `cadence init`'s refusal points at `cadence onboard` in the same scenario
Given `cadence init` is run in a directory where `.cadence/` exists but `state.json` does not
When it refuses (still exits non-zero — `init` must not silently bootstrap or touch the existing scaffold)
Then the printed message tells the user to run `cadence onboard` instead
And the existing fully-initialized case (`.cadence/` and `state.json` both present) still prints the original "already initialized" refusal unchanged

### AC-3: full verification passes
Given AC-1 and AC-2 are implemented
When `pnpm turbo run lint typecheck test build` runs
Then it exits successfully with no failing tests

## Boundaries

- DO NOT reimplement `onboard.ts`'s `bootstrapMissingState`/state-write logic inside `init.ts` or `simple.ts` — this phase only fixes *message routing*, `cadence onboard` already does the actual bootstrap.
- DO NOT make `cadence init` silently write `state.json` when `.cadence/` already exists — it must keep refusing (exit non-zero); only the message changes.
- DO NOT change `cadence onboard`'s existing behavior.
- DO NOT touch `docs/reference/commands.md` beyond what a doc-content test requires — no CLI flag surface changes in this phase.
