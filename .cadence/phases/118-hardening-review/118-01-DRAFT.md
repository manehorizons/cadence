# 118-01 - Harden phase paths, config, diff execution, docs drift

## Objective

Harden the review findings into a fail-closed, path-safe, shell-safe release candidate and verify the full gate.

## Acceptance Criteria

### AC-1: Phase inputs cannot escape managed phase directories
Given any command or MCP resource that accepts a phase slug
When the phase contains path separators, `..`, an absolute path, or other unsafe characters
Then CADENCE refuses with a clear invalid-phase message and writes nothing outside `.cadence/phases/<phase>/`.

### AC-2: Diff collection never uses shell interpolation
Given a DRAFT declares touched files with spaces, quotes, or shell metacharacters
When per-task, code-review, security-audit, or deep-verify diff collection runs
Then git receives a fixed argv array via `execFileSync` and no shell command string is built from DRAFT file paths.

### AC-3: Invalid config fails closed
Given `.cadence/config.json` exists but is invalid JSON or violates the schema
When gate-bearing commands load config
Then the command refuses with the config validation error instead of falling back to defaults or `null`.

### AC-4: Product surface docs match package reality
Given the repo ships `@manehorizons/cadence-host-codex`
When a maintainer reads the design and user docs
Then Codex is described consistently as a supported adapter or the package is removed; no doc claims it is archived while it ships.

### AC-5: Full local gate passes
Given the hardening changes are complete
When `pnpm.cmd -w lint`, `pnpm.cmd -w typecheck`, `pnpm.cmd -w test`, and `pnpm.cmd -w build` run
Then all commands pass on the local workspace.
