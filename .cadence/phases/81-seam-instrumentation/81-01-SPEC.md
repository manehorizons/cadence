# 81-01 — Instrument gate/hook/verify seams

## Objective

Wire the phase-80 logger into the three success-criteria seams — settle gate decisions,
hook/event dispatch, and AI verifier provider calls — via `getLogger().child({ seam })`, and
configure the process logger from `config.logging` at the entrypoints, so operators can turn on
diagnostics that stay default-off and stderr-only.

## Acceptance Criteria

### AC-1: Gate decisions are observable
Given a settle run at log level `debug`
When `runSettleGates` walks the gate order
Then it emits one `seam: 'gate'` record per gate covering skipped (not in set), ran-with-outcome
(`pass`/`refuse`), and the refusing gate that halts the loop (`{ gate, outcome }`); and at the
default `silent` level it emits nothing.

### AC-2: Hook/event dispatch is observable
Given the `HookDispatcher` at log level `debug`
When an abstract event is dispatched
Then it emits a `seam: 'hook'` record naming the routed event (`{ event }`), and emits nothing at
the default `silent` level.

### AC-3: Verifier provider calls are observable
Given the `anthropic` and `local` verifier providers at log level `debug`
When a verification request is made
Then each emits `seam: 'verify'` records for the request and its result (including token usage
when present), and on a provider/transport error emits a `warn` record before the error
propagates; and at `silent` they emit nothing.

### AC-4: config.logging takes effect at the entrypoints
Given `config.logging.level` set to a non-silent level and no `CADENCE_LOG_LEVEL` env override
When a CLI command, a hook dispatch, or the MCP server runs
Then the process logger is configured from `config.logging` (level + format) so seam records are
emitted; and when `CADENCE_LOG_LEVEL` is set it still overrides `config.logging` (env > config).

### AC-5: Seams never write to stdout
Given any seam emitting at any level
When records are written
Then they go only to stderr; stdout carries only the command's normal output, leaving golden
fixtures (MCP prompts / slash commands) and `--json` output byte-identical.

### AC-6: Default-off preserves existing behavior
Given the default `silent` level (no env/config)
When the full test suite and existing fixtures run
Then no seam emits anything and every existing test passes unchanged — instrumentation is purely
additive.

## Constraints

- Instrument by ADDITION via `getLogger().child({ seam })`. Audit confirms there is **no
  diagnostic `console.*` at these seams** to migrate; the one `console.log` in
  `cli/commands/hook.ts` is the user-facing context-payload contract and MUST remain on stdout.
- Do NOT alter gate verdict logic, dispatch routing, or verifier results — only add logging.
- Keep stderr-only + default-off (phase-80 invariants). No new runtime dependency.
- TDD: each AC referenced by token (`AC-N`) in a test under `packages/core/tests/`. Tests inject a
  capturing logger via `setLogger(...)` and assert records; reset with `resetLogger()`.

## Open Questions

- Whether gate "ran" records belong at `debug` or `info` (leaning `debug` for ran/skip, `warn` for
  refuse) — final levels pinned during planning.
- Whether to configure the logger once per CLI process or per hook dispatch (dispatch reloads
  config; configuring per-dispatch is cheap and idempotent).
