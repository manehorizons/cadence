# 273-01 — resume: warn on dangling lastHandoff pointer

## Objective

`locateFreshestHandoff` (`packages/core/src/handoff/locate.ts`) silently falls
back to a freshest-by-`generated_at` glob whenever `state.json`'s
`session.lastHandoff` names a `SESSION-*.md` file that no longer exists, with
zero signal to the caller that the pointer was dangling. The fallback ranking
itself is correct (confirmed by inspection: `rec-20260811-009`'s claim that it
picks lexicographically-last rather than most-recent does not match the code —
the incident's served doc was, in fact, the genuinely freshest doc present in
that checkout's own `.cadence/handoff/` at the time). The real defect is the
missing signal: nothing distinguishes "resume served the pointer's actual
target" from "resume silently guessed via fallback because the pointer was
broken," so a stale-but-plausible doc reads as authoritative. Add that signal
end-to-end (`locate.ts` → `run-resume.ts` → `ResumeResult` → the CLI/service
warning) without touching the unrelated loop-position drift comparison or the
sibling-worktree candidate behavior (phase 143), both of which are working as
designed and out of scope here.

## Acceptance Criteria

### AC-1: a dangling lastHandoff pointer produces a loud, distinct warning
Given `state.json`'s `session.lastHandoff` names a `SESSION-*.md` file that
does not exist in `.cadence/handoff/`, and at least one other `SESSION-*.md`
exists to fall back to
When `cadence resume` runs (any mode, any output surface — CLI text or
`resumeService`'s `CommandIO`)
Then the result records which pointer target was missing, and the rendered
output carries a warning naming that missing filename and the path of the doc
actually served, visibly distinct from the existing loop-position drift banner

### AC-2: normal resolution paths never emit the new warning
Given `state.json`'s `session.lastHandoff` is `null` (no session has ever
handed off) OR names a file that exists
When `cadence resume` runs
Then no dangling-pointer warning is emitted, and every previously-passing
case in `locate.test.ts`, `run-resume.test.ts`, and `resume.test.ts` (brief
output, full output, loop-position drift banner, sibling candidates, the
`--list`/`--pick`/`--path` paths) is byte-for-byte unchanged

## Boundaries

- DO NOT change the existing loop-position-only drift comparison (`located
  Position !== liveLoopPosition` in `run-resume.ts`) to also compare
  `active_phase`/`activePhase`. That's a materially different, riskier
  change: it would fire on every ordinary phase-to-phase transition and
  reproduce the chronic-warn pathology already tracked in
  `rec-20260811-003`. Out of scope for this phase.
- DO NOT alter the sibling-worktree `autoList`/candidate-demotion behavior
  (phase 143) — the `note: N other worktree(s) have resumable handoffs`
  stderr nudge is deliberate and unrelated to this bug.
- DO NOT add any auto-repair of `state.json`'s `lastHandoff` pointer (e.g.
  clearing or rewriting it). Surfacing the warning is the fix; the operator
  decides what to do next. `cadence resume` stays read-only.
- DO NOT remove or weaken any existing test to make the new ones pass.
