# 56-01 — cadence doctor — diagnose project setup

## Objective

Add a `cadence doctor` command that runs a set of deterministic, offline health
checks on a project's CADENCE setup and reports actionable problems, so silent
misconfiguration surfaces as clear diagnostics instead of looking like CADENCE
being broken.

## Acceptance Criteria

### AC-1: healthy project reports all-pass and exits 0
Given an initialized project with a valid `.cadence/` (config + state parse) on Node >= 20
When the operator runs `cadence doctor`
Then every check is reported as `ok`, no problems are listed, and the process exits 0.

### AC-2: uninitialized project is diagnosed, not crashed
Given a directory with no `.cadence/`
When the operator runs `cadence doctor`
Then the "initialized" check reports an `error` naming the missing `.cadence/`, gives a remediation hint (`cadence init`), and the process exits 1 (no stack trace / no `NotInitializedError` bubble).

### AC-3: each problem carries name + severity + remediation
Given any failing check
When `cadence doctor` renders its report
Then the problem line includes the check name, a severity (`error` | `warning`), a one-line detail, and a one-line remediation hint.

### AC-4: `--json` emits machine-readable results
Given any project state
When the operator runs `cadence doctor --json`
Then stdout is a single JSON object with a `checks` array of `{ name, status, severity, detail, remediation }` and a top-level `ok` boolean — and nothing else is written to stdout.

### AC-5: exit code reflects worst severity (CI-usable)
Given a project with at least one `error`-severity problem
When `cadence doctor` runs
Then it exits 1; given only `warning`-severity problems (or none) it exits 0. (So the command is usable as a CI gate.)

### AC-6: non-portable slash-command run-line is flagged
Given a Claude Code host install where a `.claude/commands/cadence-*.md` run-line contains a machine-absolute path (e.g. `!node C:\...` or `!node /abs/.../cli/index.js`)
When `cadence doctor` runs
Then the host-portability check reports a `warning` naming the offending file, with remediation pointing at re-running `install` without `--local`.

## Constraints

- **Report-only in v1.** `doctor` diagnoses and prints remediation text; it does
  NOT auto-fix. (A `--fix` mode is explicitly out of scope, a later increment.)
- **Deterministic + offline.** No network, no AI verifier, no host process spawn.
  Pure filesystem + config inspection. Safe to run anywhere, anytime.
- **Check only what's present.** Host checks (Claude Code hooks + slash commands)
  run only when `.claude/` exists; their absence is not itself a problem.
- Lives in `packages/core/src/cli/commands/doctor.ts`, registered in the CLI
  index alongside the other subcommands.
- TDD: drive each AC with `@manehorizons/cadence-testkit` ephemeral-repo
  fixtures; each AC referenced by `AC-N` token in a test (test-coverage gate).
- Human-readable output by default; `--json` for machine consumption (matches
  the convention of other `cadence` commands).

## v1 check set (scope)

1. **node** — Node major >= 20 (`error` if below the engines floor).
2. **initialized** — `.cadence/` present; `config.json` parses + validates against schema.
3. **state** — `state.json` present + parses; `STATE.md` present (derived view exists).
4. **git-hooks** — `git config core.hooksPath` resolves to `.githooks` (the pre-push gate); `warning` if unset/mismatched.
5. **host-hooks** — *(only if `.claude/` present)* `settings.json` carries the `_managedBy: "cadence"` hook entries.
6. **host-commands** — *(only if `.claude/commands/` present)* every managed `cadence-*.md` run-line is portable (no machine-absolute path). Directly motivated by the 2026-06-04 `--local` Windows-path bug.

## Open Questions

- Severity of the host-portability finding (AC-6): `warning` (non-blocking) vs
  `error` (fails CI)? Default assumption: **warning** — a stray local path
  breaks ergonomics, not the engine. Revisit if doctor is meant to gate CI hard.
- Should `git-hooks` be `error` rather than `warning`? It's the enforcement
  layer on GitHub Free; default assumption **warning** (a clone may legitimately
  not have run `git config core.hooksPath`).
