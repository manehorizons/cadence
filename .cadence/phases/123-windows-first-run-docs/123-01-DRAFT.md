# 123-01 - Fix Windows first-run command guidance

## Objective

Document Windows PowerShell npm shim failures and give new users reliable `cadence.cmd`, `npx.cmd`, and `npm.cmd` fallback commands anywhere first-run setup is taught.

## Acceptance Criteria

### AC-1: README install guidance names Windows command fallbacks
Given a Windows user installs CADENCE globally with npm
When PowerShell refuses the npm `.ps1` shim because script execution is disabled
Then README guidance tells them to use `cadence.cmd`, `npx.cmd`, or `npm.cmd` instead of changing execution policy.

### AC-2: Quickstart and CLI docs stay consistent
Given `docs/quickstart.md` and `docs/cli.md` explain first-run commands
When Windows-specific command fallback guidance is added
Then both docs point to the same fallback behavior and do not contradict README.

### AC-3: No host or verifier behavior changes
Given this milestone is documentation-only
When the change lands
Then runtime CLI, host adapter, MCP, and verifier behavior remain unchanged.

## Tasks

### T1: Add Windows fallback guidance to README
- files: `README.md`
- action: Add a Windows PowerShell note near install/quickstart explaining npm `.ps1` shim refusal and safe `.cmd` fallbacks.
- verify: README names `cadence.cmd`, `npx.cmd`, and `npm.cmd` and avoids telling users to loosen execution policy.
- done: AC-1

### T2: Mirror first-run fallback guidance in user docs
- files: `docs/quickstart.md`, `docs/cli.md`
- action: Add matching Windows fallback notes where first-run install/setup commands are taught.
- verify: Quickstart and CLI guide point to the same fallback behavior and remain consistent with README.
- done: AC-2

### T3: Verify docs-only scope
- files: `README.md`, `docs/quickstart.md`, `docs/cli.md`
- action: Confirm the diff only touches documentation and run the relevant markdown/doc checks available in the repo.
- verify: No runtime, host adapter, MCP, or verifier source files change.
- done: AC-3

## Boundaries

- DO NOT modify runtime CLI behavior.
- DO NOT modify host adapter, MCP, or verifier source.
- DO NOT recommend changing PowerShell execution policy.
