# 123-01 - Fix Windows first-run command guidance

## Objective

Document Windows PowerShell npm shim failures and give new users reliable `cadence.cmd`, `npx.cmd`, and `npm.cmd` fallback commands anywhere first-run setup is taught.

## Acceptance Criteria

### AC-1: README install guidance names Windows command fallbacks
Given a Windows user installs CADENCE globally with npm
When PowerShell refuses the npm `.ps1` shim because script execution is disabled
Then README guidance tells them to use `cadence.cmd`, `npx.cmd`, or `npm.cmd` instead of changing execution policy.

### AC-2: Quickstart and CLI docs stay consistent
Given `docs/quickstart.md` and `docs/cli.md` explain first-run commands
When Windows-specific command fallback guidance is added
Then both docs point to the same fallback behavior and do not contradict README.

### AC-3: No host or verifier behavior changes
Given this milestone is documentation-only
When the change lands
Then runtime CLI, host adapter, MCP, and verifier behavior remain unchanged.

## Constraints

- Documentation-only milestone; no runtime behavior changes.
- Keep PowerShell guidance safe: do not instruct users to loosen execution policy.
- Preserve cross-platform commands as the primary path; Windows fallbacks should be a troubleshooting note.

## Open Questions

- Should the website landing page get a short Windows note directly, or rely on synced README/quickstart content?
