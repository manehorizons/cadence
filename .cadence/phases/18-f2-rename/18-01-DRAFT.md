# 18-01 — Physical KEEL to CADENCE rename rollout (F2)

## Objective

Phase 12 renamed the *word* KEEL → CADENCE in DESIGN.md §8 and shipped `@cadence/*` package scopes. F2 remained: physical rollout of the rename to operational state the user actually hits — `.claude/commands/keel-*.md` slash commands, hook installer's legacy-managed-entry cleanup, root `package.json` name, `.cadence/config.json` template dir, `.cadence/PROJECT.md`, `.cadence/state.json` project name, testkit fixture prefix, and the one stray `CONTRIBUTING.md` reference. Resolves DESIGN.md F2.

## Acceptance Criteria

### AC-1: install.ts re-install removes legacy `_managedBy: 'keel'` hook entries
Given a `.claude/settings.json` that contains hook entries marked `_managedBy: 'keel'` (left over from a pre-Phase 12 install)
When `installHooks` runs again
Then it removes the legacy `'keel'`-managed entries and writes fresh `'cadence'`-managed ones. User-customized hooks (no `_managedBy` marker) are preserved unchanged. Idempotent: a second re-install is a no-op against the rewritten file.

### AC-2: stale `.claude/commands/keel-*.md` slash files are deleted from the tree
Given the workspace currently tracks `.claude/commands/keel-{approve,build,check,draft,progress,settle}.md` from the pre-rename era
When this phase lands
Then those six files are git-rm'd. The directory still contains the freshly-installed `cadence-*.md` set generated by `installCommands` (already updated in Phase 12). No `keel-*` slash command remains on `main`.

### AC-3: `.claude/settings.json` + `.claude/settings.local.json` regenerated
Given the two settings files currently use `npx @keel/host-claude-code` (or `--keel "..."`) in their command strings and `_managedBy: 'keel'` markers
When the phase lands
Then both files reference `@cadence/host-claude-code` (or `--cadence`) and carry `_managedBy: 'cadence'`. `settings.local.json`'s machine-specific absolute paths are updated to `...\Projects\cadence\...` to match the renamed repo. Both files round-trip through the install command without further drift.

### AC-4: project metadata normalized to "cadence"
Given the workspace has stale `keel`-flavored metadata in (a) root `package.json` `"name": "keel-monorepo"`; (b) `.cadence/config.json` `templates.dir: ".keel/templates"`; (c) `.cadence/PROJECT.md` (`# keel` heading + `> KEEL project. Then root pkg name is `cadence-monorepo`; `templates.dir` is `.cadence/templates`; PROJECT.md heads `# CADENCE` + points to `.cadence/ROADMAP.md`; `state.json` `project.name` is `cadence`; the fixture's tmpdir prefix is `cadence-test-`. State and STATE.md round-trip cleanly via the existing backend writer.

### AC-5: install-commands.ts + install.ts tests use CADENCE labels
Given `packages/host-claude-code/tests/install-commands.test.ts` and `install.test.ts` still describe themselves with "keel-*", "keel-managed", "_managedBy=keel", and `node /abs/keel.js`-style override values
When the phase lands
Then test labels + sample fixtures use CADENCE / cadence wording (`cadence-*.md`, `cadence-managed`, `_managedBy=cadence`, `node /abs/cadence.js`). Test surface tracks the production rename so green-line readers stop seeing the old name.

### AC-6: docs + `CONTRIBUTING.md`
Given `CONTRIBUTING.md` still has a stale `pnpm --filter @keel/core test` example
When the phase lands
Then the example is `pnpm --filter @cadence/core test`. DESIGN.md's KEEL-in-section-8 history table stays as-is (intentional rejected-name record). README's "Phase 12 renamed KEEL → CADENCE" status banner stays as-is (history). DESIGN.md §6 marks F2 resolved.

## Boundaries

- DO NOT touch DESIGN.md §8 "Rejected / set-aside" table — KEEL must remain as a documented retired name.
- DO NOT touch README's Phase 12 status banner — that's intentional rename history.
- DO NOT modify the `.keel/` top-level directory (archive + handoff state). It's preserved by design (DESIGN.md §1 footnote).
- DO NOT touch `.cadence/phases/*-DRAFT.md` or `.cadence/research/codex-hooks.md` — these are historical phase artifacts. Their KEEL references reflect the moment they were authored.
- DO NOT touch `packages/host-codex/` — archived per Phase 11, preserved on the `keel-codex-archive` git tag.
- DO NOT rename git remote or repo URL — the user owns that side of the rename and has already done it on GitHub.
- DO NOT add a `.keel/templates` → `.cadence/templates` migration shim. The path is referenced only via `defaultConfig` and isn't read on the live install path; switching the default is enough.
- DO NOT alter the `installHooks` write order or `isManaged` public surface beyond the legacy-eviction tweak. Backwards-compat: a settings.json without any `_managedBy: 'keel'` entries (already-renamed users) must produce identical output to today's installer.
