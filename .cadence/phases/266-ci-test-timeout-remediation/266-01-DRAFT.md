# 266-01 — CI test-timeout remediation: summary-verify-sweep + dispatcher skill-invoke

## Objective

Root-cause two confirmed, worsening Windows CI timeout failures (rec-20260806-010: summary-verify-sweep spawns one CLI subprocess per historical SUMMARY.json, 275+ and growing; rec-20260809-002: the skill-invoke FIFO-cap test drives 105 serial real-disk dispatcher round-trips) rather than raising timeouts -- both materialized together on PR #391's Windows leg (runs 31295920368, 31317685528, ~13m50s baseline) and independently on 3 of the last 5 push-to-main CI runs, blocking unrelated PRs. Bundled into one phase per dec-20260809-001.

## Acceptance Criteria

### AC-1: in-process --all sweep
Given cadence summary verify currently only checks one <phase> <num> target per invocation
When cadence summary verify-all is run against a repo with a historical .cadence/phases corpus
Then it walks every *-SUMMARY.json in-process (no subprocess spawn per file), reusing the existing per-file load+verify logic, reports MISMATCH and load/parse/schema failures as failures, treats NO_HASH as informational only, and exits nonzero iff at least one file failed

### AC-2: sweep test spawns one process, not N
Given summary-verify-sweep.test.ts currently spawns one cadence CLI process per historical SUMMARY.json at concurrency 12
When the test is rewritten to call cadence summary verify-all once
Then it still asserts zero failures across every real historical summary (>100 files) with the same failure-class semantics, in its own test block with a fresh AC token rather than a third token appended to the existing 257-01/AC-3, 264-01/AC-2 title

### AC-3: docs stay in sync
Given docs/reference/commands.md is diffed against the registered CLI command set by a doc-sync test
When the verify-all subcommand is registered
Then docs/reference/commands.md documents it and the doc-sync test passes

### AC-4: skill-invoke FIFO cap is pure and unit-tested directly
Given handleSkillInvoke's FIFO-cap-at-100 logic is inline in an impure handler, and its only test drives 105 serial real dispatcher round-trips through disk
When the cap logic is extracted into a pure function taking the cap as a parameter
Then a new unit test exercises FIFO-drop-at-100 by calling the pure function directly (no disk I/O), while the existing append/dedup/no-op dispatcher-level skill-invoke tests are left untouched and still prove real commit() wiring
