# 192-01 — Mandatory action-class prohibition boilerplate for dispatch packets

## Objective

`cadence dispatch plan` renders a self-contained implementation-agent prompt
(`renderPacket`) per task, but the current boilerplate only scopes which
*files* an agent may touch — it actually instructs the agent to self-record
its own outcome via `cadence build task <id> --status=...`. That is the exact
class of self-authorized action that let a dispatched fork agent, in a real
incident (deja repo, 2026-07-18; rec-20260718-001), commit directly to `main`
four times and run `cadence build`/`settle` itself, unsupervised, before any
orchestrator review. Add a mandatory prohibition block to every rendered
packet naming the forbidden action classes, and replace the self-report
instruction with an explicit stop-and-report-to-orchestrator instruction.

## Acceptance Criteria

### AC-1: packet includes the prohibition boilerplate
Given any task rendered through `renderPacket`
When the packet text is produced
Then it contains an explicit block prohibiting any state-mutating `cadence`
subcommand (`cadence build`, `cadence settle`, etc.), `git commit`/`git push`,
`gh`/other network actions, and invoking `AskUserQuestion`

### AC-2: packet no longer instructs self-recording
Given the previous packet told the agent to run
`cadence build task <id> --status=...` itself
When the packet is rendered now
Then it instead instructs the agent to stop and report task completion (or
blockage) back to the orchestrating session, which records the outcome
itself

### AC-3: existing packet behavior stays accurate under test
Given the packet's other existing content (objective, task fields, files
boundary, redundant-work reminder)
When `packet.test.ts` runs after the change
Then the still-relevant existing assertions pass, the outdated self-report
assertion is replaced with one asserting the new stop-and-report instruction,
and new assertions cover the prohibition boilerplate

### AC-4: docs describe the new contract
Given `docs/reference/commands.md` documents `cadence dispatch plan`'s
behavior
When the Behavior section is read after this change
Then it describes the mandatory prohibition preamble every rendered packet
now includes
