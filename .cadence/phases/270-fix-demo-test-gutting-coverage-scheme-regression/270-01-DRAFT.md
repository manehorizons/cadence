# 270-01 — Fix demo-test-gutting coverage-scheme regression

## Objective

Fix `examples/demo-test-gutting/run-demo.sh` so it reaches its documented
"Settled" end state again, by opting its post-init config patch into
`coverageScheme: 'bare'` — the same immunization Phase 239 already applied to
`packages/core/src/tutorial/fixtures.ts:47` — since the demo's fixtures use
bare `AC-N` tokens and Phase 239 changed the fresh-init default to
`phase-qualified`.

## Acceptance Criteria

### AC-1: run-demo.sh reaches the buggy-code coverage refusal, not a token-format refusal
Given a fresh `cadence init --gate-profile auto` repo patched by
`run-demo.sh`'s post-init `node -e` block
When the demo runs the "THE MONEY SHOT" step (`cadence settle run --auto`)
against `prorate.buggy.mjs` + the gutted test
Then the refusal is driven by the intentionally-broken AC-2 (rounding bug),
not by `coverage: <id>/AC-N has no linked test` on AC-1/AC-3, and the exit
code is non-zero for the reason the demo narrates

### AC-2: run-demo.sh reaches "Settled" at the redemption step
Given the "REDEMPTION" step restores `prorate.fixed.mjs` and the honest test
When `cadence settle run --auto` runs again
Then it exits 0 and prints the "Settled." message, completing the script
end-to-end exactly as `examples/demo-test-gutting/README.md` documents
