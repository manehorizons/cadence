# 195-01 — settle refuses bare TN: DONE with no verify evidence

## Objective

settle currently writes a bare 'T1: DONE' line into SUMMARY.md with zero evidence whenever a DRAFT task omits the '- verify:' line — the draft-parser (draft-parser.ts) silently defaults a missing verify line to an empty string instead of refusing, and no settle-time gate checks a task's verify content before it is rendered as DONE (summary-writer.ts). Add a tier-scoped settle gate that refuses to finalize a task as DONE when its verify field is empty, per GitHub issue #206 / rec-20260712-001.

## Acceptance Criteria

### AC-1: a new settle-time gate detects empty-verify tasks and is wired into standard/complex tiers
Given a DRAFT task whose `- verify:` line was omitted (so `Task.verify === ''` after parsing)
When `settle run` reaches gate evaluation for a `standard` or `complex` tier phase and that task's status is DONE
Then the new gate (e.g. `task-verify-required`) fires and refuses the settle, naming the offending task id, instead of silently allowing a bare `TN: DONE` into SUMMARY.md

### AC-2: the gate is tier-scoped and does not break existing quick-fix or already-evidenced phases
Given the gate is added to `DELTAS[profile][tier]` in `packages/core/src/gates/engine.ts` for `standard`/`complex` tiers only
When a `quick-fix` tier phase settles with an empty-verify task, or any tier settles a task whose `verify` field is non-empty
Then the gate does not refuse in either case — quick-fix stays exempt, and non-empty-verify tasks pass through unaffected

### AC-3: full test suite passes
Given the new gate and its regression tests are in place
When `pnpm --filter @manehorizons/cadence-core test` runs
Then it exits successfully with no failing tests, and typecheck/lint remain clean

### AC-4: gate matrix docs stay in sync
Given `docs/concepts.md` documents the full gate matrix (per-tier gate lists)
When the new `task-verify-required` gate is added to `engine.ts`'s `DELTAS`
Then `docs/concepts.md` is updated in the same commit to list the new gate under the `standard`/`complex` tier rows it now fires in

## Boundaries

- DO NOT touch build-time gates (`per-task-verify.ts`) — this fix is settle-time only; the two are named similarly but fire at different phases and must not be merged.
- DO NOT change `TaskZ.verify` from required (`z.string()`) to optional in `packages/types/src/plan.ts` — the schema is already correct; the bug is that the parser silently defaults a missing markdown line to `''` rather than the gate catching it downstream. Do not "fix" this by making the parser throw instead — that would be a broader, uncoordinated change to `draft-parser.ts` outside this phase's scope.
- DO NOT add the new gate to `quick-fix` tier's deltas — quick-fix is deliberately lighter-weight; this stays a `standard`+ tier gate per the issue's "above the configured tier" framing.
- DO NOT fold the `docs/concepts.md` update into T2's commit silently — it is T4's job, tracked under its own AC-4, so the doc change stays reviewable as its own line item.
