# 187-01 — gateBypasses records --allow-auto-complex overrides

## Objective

Fix --allow-auto-complex soft-cap overrides being invisible in SUMMARY.json's gateBypasses. settle.ts's soft-cap check (services/settle.ts:246-254) and draft-approve.ts's equivalent check (services/draft-approve.ts:60-68) each only print an io.err() stderr notice when --allow-auto-complex is used and never emit an AnomalyEvent, so gateBypassesFromAnomalies() (settle.ts:110-144) has no mapping for it and the override is silently absent from a settled phase's SUMMARY.json -- contradicting CLAUDE.md's claim that every bypass is 'loud and recorded in the SUMMARY (gateBypasses)'. Add a new auto-complex-override AnomalyType, wire settle.ts to record it into gateBypasses, and wire draft-approve.ts to emit it through the existing anomaly-notify notifier pathway (mirroring emitCoherenceWarns).

## Acceptance Criteria

### AC-1: settle-time override lands in SUMMARY.json's gateBypasses
Given a phase settled under the auto profile + complex tier (softCap active)
When `cadence settle run --allow-auto-complex` completes
Then the phase's `SUMMARY.json` `gateBypasses` array contains an entry for the soft-cap override (e.g. `{ gate: 'soft-cap', flag: '--allow-auto-complex', severity: 'warn' }`), matching the existing pattern for `coverage-bypassed`/`force-used`/`verifier-failure`

### AC-2: draft-approve-time override is emitted via the anomaly-notify pathway
Given a coherence-clean draft under the auto profile + complex tier (softCap active) with the `anomaly-notify` gate in the effective gate set
When `cadence draft approve --allow-auto-complex` runs
Then a new `auto-complex-override` `AnomalyEvent` is emitted through the existing notifier (mirroring how `emitCoherenceWarns` emits `coherence-warn`), and nothing is emitted when `anomaly-notify` is not in the gate set

### AC-3: existing anomaly/bypass regression suite remains green
Given the new `auto-complex-override` AnomalyType and its two emission sites
When the full `@manehorizons/cadence-core` and `@manehorizons/cadence-types` test suites, typecheck, and lint run
Then everything passes with no regressions to `force-used`/`coverage-bypassed`/`verifier-failure`/`coherence-warn` behavior

### AC-4: fix ships with a changeset
Given this is a bugfix to two published packages (`cadence-core`, `cadence-types`)
When the phase is ready to land
Then a `.changeset/*.md` entry describing the fix is present for both packages
