# 102-01 — Auto-archive wiring + recommendations.autoArchive config

## Objective

Wire automatic soft-archival onto the phase-101 primitive: a
`recommendations.autoArchive` config (default on) that archives a rec the moment it
reaches `shipped`/`rejected` via `promote`, and a best-effort settle→rec hook that
archives a `converted` rec when its phase completes SETTLE (v1.24 phase 2 of 3).

## Acceptance Criteria

### AC-1: `recommendations.autoArchive` config, default on, backward-compatible
Given `cadence-types` config
When a config omits the `recommendations` block (pre-v1.24)
Then it parses with `recommendations.autoArchive` defaulting to `true`; `defaultConfig`
carries `recommendations: { autoArchive: true }`; an explicit `false` round-trips.

### AC-2: pure `autoArchiveReasonForPromotion`
Given a promotion's target status
When `autoArchiveReasonForPromotion(status)` is called
Then it returns `'shipped'` for `shipped`, `'rejected'` for `rejected`, and `null` for
every other status (`accepted`/`deferred`/`undefined`).

### AC-3: promote → shipped auto-archives (autoArchive on)
Given a repo with `autoArchive` on (the default) and a live `candidate` rec
When `runRecommendationPromotion(root, id, { status: 'shipped', shippedRef })` runs
Then a single atomic write both sets `status='shipped'` and moves the rec into
`archived` with `archiveReason='shipped'`; a reload shows 0 active / 1 archived.

### AC-4: promote → rejected auto-archives (autoArchive on)
Given a repo with `autoArchive` on and a live `accepted` rec
When `runRecommendationPromotion(root, id, { status: 'rejected' })` runs
Then the rec ends archived with `archiveReason='rejected'`.

### AC-5: autoArchive off leaves the rec active
Given a repo whose config sets `recommendations.autoArchive=false`
When a rec is promoted to `shipped` (or `rejected`)
Then the status is set but the rec stays in `recommendations` (not archived).

### AC-6: non-terminal promotions never auto-archive
Given any config
When a rec is promoted to `accepted` or `readiness` only (no terminal status)
Then it is never archived.

### AC-7: pure/impure settle→rec helper
Given a ledger with recs converted to various phases
When `runAutoArchiveConvertedForPhase(root, phaseId)` runs
Then exactly the `converted` recs whose `convertedToPhaseId === phaseId` are archived
with `archiveReason='converted-settled'` (others untouched), written once; it returns
the archived ids and is a no-op (`[]`) when none match.

### AC-8: settle integration is gated, reported, best-effort
Given a settling phase `P` and a rec converted to `P`
When `cadence settle run` completes with `autoArchive` on
Then the rec is auto-archived and a line is reported (`archived rec <id> (converted →
settled)`); with `autoArchive=false` the rec is left active; and any failure in the
hook never throws or changes the settle exit code (best-effort).

## Boundaries

- DO NOT auto-archive at `convert` time — a converted rec stays live until its phase
  settles (the whole point of the settle hook). `runRecommendationTransition`
  (`convert`) is untouched.
- DO NOT let the settle hook throw or change settle's exit code — strictly best-effort
  (same posture as `gatherOccupancy` / handoff pruning).
- DO NOT add the manual-command/storage surface — that was phase 101. No new
  `archiveReason` values beyond the phase-101 enum.
- DO NOT write user-facing docs (`config.md`/`commands.md`) — that is phase 103.
