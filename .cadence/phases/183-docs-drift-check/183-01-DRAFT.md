# 183-01 — Generated docs drift-check

## Objective

Extend this repo's existing generated-from-source, fail-on-drift doc
discipline (already applied to `RECOMMENDATIONS.md`, and narrowly to
`commands.md`'s top-level command-name marker block via
`cli-reference.test.ts`) to cover per-command flags, the config schema's
field set, and a new exit-code taxonomy doc — per rec-20260712-012's
confirmed gaps. Each check is an assertion-mode vitest test reading live
source truth (Commander's registered options, the Zod config schema, actual
`exitCode`/`process.exit` call sites), so it already runs under the required
`ci-success` check (`pnpm test` in `ci.yml`) — no new CI workflow is needed.

## Acceptance Criteria

### AC-1: commands.md documents every top-level command's registered flags
Given a CLI command registered via `registerAllCommands` with N long-flag
options (e.g. `--json`, `--filter-status`)
When a test reads that command's live Commander registration and searches
`docs/reference/commands.md` for each registered long-flag name
Then the test fails if any registered flag is missing from `commands.md`,
and passes once every registered top-level-command flag is documented

### AC-2: config.md documents every top-level config schema field
Given `CadenceConfigZ` in `packages/types/src/config.ts` with a fixed set of
top-level keys (e.g. `schemaVersion`, `loopEnforcement`, `subagentPolicy`)
When a test reads the schema's live top-level key set and searches
`docs/reference/config.md` for each key name
Then the test fails if any top-level schema key is missing from
`config.md`, and passes once every key is documented

### AC-3: an exit-code taxonomy doc exists and matches real exit-code usage
Given the CLI (`packages/core/src`) uses a small, closed set of numeric
process exit codes today (grepped and confirmed: `0`, `1`, `2`, `3`)
When a new `docs/reference/exit-codes.md` documents the meaning of each
code and a test greps `packages/core/src` for every distinct exit-code
integer literal in use
Then the test fails if any code used in source is undocumented in
`exit-codes.md`, or if `exit-codes.md` documents a code no longer used in
source

### T3: Add the exit-code taxonomy doc and its drift guard
- files: `docs/reference/exit-codes.md`, `packages/core/tests/docs/exit-codes.test.ts`
- action: write `docs/reference/exit-codes.md` documenting each of the 4
  distinct exit codes used across `packages/core/src` today (0 success; 1
  general failure/refusal; 2 invalid input/usage error; 3 the
  `handoff --check` "unfilled sections" signal, distinct from "no doc
  found" which is 1) and add a test that greps `packages/core/src` for
  every distinct `exitCode`/`process.exit` integer literal and cross-checks
  it against the documented set in both directions
- verify: `pnpm --filter @manehorizons/cadence-core test -- exit-codes`
- done: AC-3

## Boundaries

- DO NOT regenerate the full prose of `commands.md`/`config.md` from
  source — the drift guards check structural surface (flag names, schema
  keys, exit codes), not behavioral prose, which stays hand-authored.
- DO NOT add a new GitHub Actions workflow — the existing `test` job
  already runs these as part of the required `ci-success` check.
- DO NOT modify `.github/workflows/ci.yml`, `release.yml`, `docs.yml`, or
  any file phase 182 already added (`codeql.yml`, `security.yml`,
  `docs/security/`, `scripts/check-audit-exceptions.mjs`).
- DO NOT touch `packages/core/src/cli/register.js` or any command's actual
  flags/behavior — this phase only adds drift-detection tests and doc
  content, not CLI behavior changes.
