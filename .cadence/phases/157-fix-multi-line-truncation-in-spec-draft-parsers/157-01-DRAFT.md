# 157-01 — Fix multi-line truncation in spec/draft parsers

## Objective

`parseSpecMd` (spec-parser.ts:57) truncates the Objective to its first line
(`extractSection(...).split('\n')[0]`) and each AC's Given/When/Then clause
to its first line (spec-parser.ts:38-40, `.exec(block)` without the `/s`
flag so `.` cannot match a newline). `parseDraftMd` (draft-parser.ts:86,
38-40) has the identical bug shape, confirmed by direct inspection —
`draft-parser.ts` is deliberately hand-duplicated rather than shared
(spec-parser.ts's own header comment: "Helpers reproduced verbatim from
draft-parser.ts ... copying is the only path, no shared refactor"), so both
copies drifted the same defect and both need the same fix applied
independently. Reproduced live on phase 155-01: a multi-sentence Objective
and five multi-clause ACs were silently truncated mid-sentence when `cadence
draft new --from-spec` seeded a DRAFT from an approved SPEC.md (rec-20260704-002).
Fix both extractors to capture the full multi-line Objective/clause text up
to its natural boundary (the next `## ` heading for Objective; the next
Given/When/Then label or end of AC block for each clause) instead of
stopping at the first newline.

## Acceptance Criteria

### AC-1: parseSpecMd preserves a multi-line Objective
Given a SPEC.md whose `## Objective` section spans more than one line
When `parseSpecMd` parses it
Then `spec.objective` contains the full section text (all lines, trimmed),
not just the first line

### AC-2: parseSpecMd preserves multi-line Given/When/Then clauses
Given a SPEC.md AC block whose Given, When, or Then clause wraps across
more than one line
When `parseSpecMd` parses it
Then each of `given`/`when`/`then` contains the clause's full wrapped text,
not just its first line

### AC-3: parseDraftMd preserves a multi-line Objective and multi-line clauses
Given a DRAFT.md whose `## Objective` section or an AC's Given/When/Then
clause spans more than one line
When `parseDraftMd` parses it
Then `draft.objective` and the affected `given`/`when`/`then` fields contain
the full wrapped text, mirroring AC-1/AC-2 for the draft parser

### AC-4: existing single-line Objective/AC parsing is unchanged
Given a SPEC.md or DRAFT.md whose Objective and every AC clause are each a
single line (the pre-fix, still-common case)
When `parseSpecMd`/`parseDraftMd` parse it
Then the parsed `objective`/`given`/`when`/`then` values are byte-identical
to their pre-fix output — no regression for the common case

### AC-5: SPEC-to-DRAFT seeding carries full multi-line text end-to-end
Given an approved multi-line SPEC.md (multi-line Objective and at least one
multi-line AC clause)
When `cadence draft new --from-spec` seeds a new DRAFT.md from it (`parseSpecMd`
feeding `renderDraftBody`) and the resulting DRAFT.md is parsed back with
`parseDraftMd`
Then the seeded DRAFT's Objective and AC clauses match the SPEC's full
original text, reproducing and closing the exact phase-155 discovery
scenario

## Boundaries

- DO NOT introduce a shared module between `spec-parser.ts` and
  `draft-parser.ts` — their duplication is an existing, deliberate
  convention (see spec-parser.ts's own header comment); a shared-helper
  refactor is a separate concern, out of scope here.
- DO NOT touch `draft-scaffold.ts`'s `renderDraftBody` — it already renders
  whatever `spec.objective`/`ac.given/when/then` it is given verbatim; the
  bug is entirely upstream in the two parsers.
- DO NOT touch frontmatter parsing, Tasks/Boundaries parsing, or the phase-151
  name-less-heading (`[ \t]*`) fix in `draft-parser.ts` — out of scope.
- DO NOT change any existing single-line SPEC/DRAFT fixture's parsed output
  (AC-4's byte-identical regression guard).
