# 108-01 — Zero-prompt init that auto-wires the host

## Objective

Make `cadence init` a zero-prompt front door: derive the project name and gate
profile automatically, and — when a Claude Code workspace is present — offer/auto-run
the host install in the same step, so a newcomer reaches a wired `.cadence/` with one
command and no questions.

## Acceptance Criteria

### AC-1: No-flag init asks nothing and derives a real name
Given a git repo with a `package.json` (or a non-empty dir name) and no `.cadence/`
When the user runs `cadence init` with no flags in a TTY
Then `.cadence/` is scaffolded with a derived project name (never the literal
`unnamed`) and a git-suggested gate profile, and no interactive prompt is shown.

### AC-2: Explicit flags still override the derivations
Given the same repo
When the user runs `cadence init --name X --preset team --gate-profile strict`
Then the written config uses the supplied name, preset, and gate profile (the
derivations are overridden, not merged).

### AC-3: Host auto-wire without core importing host code
Given a repo containing a `.claude/` directory
When the user runs `cadence init` (auto-run) or accepts the host-wire offer
Then the Claude Code host install runs via a subprocess/spawn seam (core does not
import `@manehorizons/cadence-host-claude-code`), and init's output names what was wired.

### AC-4: Non-TTY never blocks
Given stdin is not a TTY (CI / agent)
When `cadence init` runs with no flags
Then it completes without reaching any prompt path and without the host-wire step
hanging (auto-run is skip-or-spawn, never an interactive question).

### AC-5: Already-initialized behavior unchanged
Given a dir that already has `.cadence/`
When `cadence init` runs
Then it refuses with the existing message/exit code, and `cadence init --claude-md`
still regenerates only the managed CLAUDE.md block.

## Tasks

### T1: Auto-derive name + gate profile in init
- files: `packages/core/src/cli/commands/init.ts`
- action: Derive the default project name from `package.json#name` then the cwd dir
  name (fallback to existing `unnamed` only if both are empty); when `--name` is
  absent, use the derivation instead of prompting. Reuse `suggestGateProfile` for the
  default gate profile when `--gate-profile` is absent, without prompting. Keep
  `--name`/`--preset`/`--gate-profile` as overrides.
- verify: `pnpm --filter @manehorizons/cadence-core test -- -t "init"` covers
  derived-name + override + non-TTY-no-prompt cases.
- done: AC-1, AC-2, AC-4

### T2: Host auto-wire via spawn seam
- files: `packages/core/src/cli/commands/init.ts`, `packages/host-claude-code/src/install.ts`
- action: Detect `.claude/` in the target root; when present, run the host install via
  an injected spawn seam (re-spawn `npx @manehorizons/cadence-host-claude-code install`
  or the local bin), mirroring `start`'s launcher discipline — core must not import host
  code. Add a flag to control auto-run vs offer; report what was wired in init output.
- verify: a test injects a fake spawn and asserts init invokes it with the install
  args when `.claude/` exists and skips it otherwise; grep confirms no host import in
  `init.ts`.
- done: AC-3

### T3: Preserve already-initialized + --claude-md paths
- files: `packages/core/src/cli/commands/init.ts`, `packages/core/tests/cli/init.test.ts`
- action: Confirm the existing already-initialized refusal and the `--claude-md`
  regenerate path are untouched by the new auto-derive/auto-wire branches; extend tests.
- verify: existing init tests stay green; new assertions for AC-5.
- done: AC-5

## Boundaries

- DO NOT change the gate matrix, gate semantics, or `suggestGateProfile`'s heuristic
  (only consume it).
- DO NOT import host-package code into `cadence-core` — the host wire must go through a
  spawn/subprocess seam.
- DO NOT alter the `--demo` or `--activate` flows — those are phases 109 / 110.
- DO NOT change the already-initialized refusal message or exit code.
