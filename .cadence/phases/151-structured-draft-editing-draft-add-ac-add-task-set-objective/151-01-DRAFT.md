# 151-01 — Structured draft editing: draft add-ac / add-task / set-objective

## Objective

Add three additive `cadence draft` subcommands — `set-objective`, `add-ac`, `add-task` — that mutate a `DRAFT.md`'s Objective/Acceptance-Criteria/Tasks sections from the CLI and produce output byte-compatible with `parseDraftMd` (`packages/core/src/parse/draft-parser.ts`) and the existing hand-edit format (`renderDraftBody` in `packages/core/src/parse/draft-scaffold.ts`). Hand-editing DRAFT.md stays fully supported; this is an additive write path for agents so a hand-typed heading typo can no longer silently corrupt AC/Task id sequencing.

## Acceptance Criteria

### AC-1: set-objective replaces only the Objective section
Given a PENDING draft with existing Objective/AC/Tasks/Boundaries content
When `cadence draft set-objective <phase> <num> --text "<sentence>"` runs
Then the file's `## Objective` body is replaced with `<sentence>`, `parseDraftMd(...)` returns the new `objective`, and the frontmatter plus every other section is byte-identical to before

### AC-2: add-ac appends a sequential AC block that parses correctly
Given a PENDING draft whose highest existing AC id is `AC-k`
When `cadence draft add-ac <phase> <num> --given <g> --when <w> --then <t> [--name <n>]` runs
Then a new `### AC-(k+1): <n>` block is appended to `## Acceptance Criteria` in the exact `Given/When/Then` line shape `parseAcceptanceCriteria` expects, and `parseDraftMd(...).acceptanceCriteria` includes it with matching id/name/given/when/then

### AC-3: add-task appends a sequential Task block and validates its `--done` AC ids
Given a PENDING draft whose highest existing Task id is `T-k`
When `cadence draft add-task <phase> <num> --files <f1,f2,...> --action <a> --verify <v> --done <AC-id[,AC-id...]>` runs
Then, if every referenced AC id exists in the draft's current acceptance criteria, a new `### T-(k+1)` block is appended with backtick-listed files and the given action/verify/done lines, and `parseDraftMd(...).tasks` includes it correctly; if any referenced AC id does not exist, the command refuses (exit 1, stderr names the unknown id) and the file is left unmodified

### AC-4: all three subcommands refuse outside PENDING status
Given a draft whose frontmatter `status` is not `PENDING` (e.g. `APPROVED`)
When any of `set-objective` / `add-ac` / `add-task` is run against it
Then the command refuses (exit 1, clear stderr) and the file is left unmodified — mirroring the guard pattern already used by `draft check`/`draft approve`

### AC-5: round-trip regression coverage
Given the three subcommands implemented above
When their unit tests run
Then each subcommand's output, re-parsed via `parseDraftMd`, matches the equivalent hand-edited-draft structure exactly (no drift in id sequencing, quoting, or section formatting), and the AC-3/AC-4 refusal paths are covered

## Boundaries

- DO NOT remove or restrict hand-editing — DRAFT.md stays plain markdown editable by hand; these subcommands are an additive write path only.
- DO NOT change the byte-exact format `renderDraftBody`/`parseDraftMd` already depend on (frontmatter shape, `### AC-N`/`### T-N` heading style) — appended sections must match it exactly.
- DO NOT allow any of the three subcommands to run against a draft whose status isn't `PENDING`.
