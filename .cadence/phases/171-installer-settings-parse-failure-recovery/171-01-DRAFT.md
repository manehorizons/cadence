# 171-01 — Installer destructive recovery: preserve third-party settings on parse failure

## Objective

Fix installHooks() in packages/host-claude-code/src/install.ts so a malformed .claude/settings.json is never silently discarded. Currently JSON.parse failure (ENOENT and malformed JSON alike) resets to {} and overwrites non-atomically with no backup, which is what caused the real deja-hooks-wiped incident (31f1351 / PR #170). ENOENT should still mean "new file"; malformed JSON must refuse the install instead of discarding third-party keys. Every write must go through a timestamped backup + atomic temp-file rename, and the successful-merge path's existing behavior of preserving non-cadence keys must be unaffected.

## Acceptance Criteria

### AC-1: malformed settings.json with third-party hooks is never silently wiped
Given a `.claude/settings.json` on disk that contains malformed (non-parseable) JSON, with third-party (non-cadence) content that would be lost if the file were reset
When `installHooks()` runs against that file
Then it refuses the install with a clear error instead of resetting the file to `{}`, and the on-disk file is left byte-for-byte unchanged

### AC-2: ENOENT still creates a fresh settings file
Given no `.claude/settings.json` exists at the target path
When `installHooks()` runs
Then it creates a new settings file with the cadence-managed hooks, exactly as it does today (no regression to the absent-file path)

### AC-3: every successful write goes through a timestamped backup + atomic rename
Given `installHooks()` performs a successful write (fresh file or valid existing file merged)
When the write completes
Then a timestamped backup of the prior file content exists (skipped only when there was no prior file), and the write itself is atomic (written to a temp file, then renamed into place) rather than an in-place `writeFile` on the final path

### AC-4: existing successful-parse merge behavior is unaffected
Given a valid, parseable existing `.claude/settings.json` containing third-party keys and hooks
When `installHooks()` runs
Then non-cadence keys/hooks are preserved exactly as the current merge logic already does, with no behavior drift from this fix

## Tasks

### T1: Reproduce the defect
- files: `packages/host-claude-code/tests/install.test.ts`
- action: add a failing regression test that writes malformed JSON to a temp `.claude/settings.json` containing recognizable third-party content (e.g. a non-cadence hook entry) alongside it, runs `installHooks()`, and asserts the third-party content still exists on disk afterward
- verify: the new test fails against current `install.ts` (it silently resets to `{}`, losing the third-party content)
- done: AC-1

### T2: Distinguish ENOENT from malformed JSON and refuse on malformed
- files: `packages/host-claude-code/src/install.ts`
- action: replace the current catch-all `try { JSON.parse(...) } catch { /* start fresh */ }` with logic that treats `ENOENT` as "no file yet" (start fresh, as today) but treats any other read/parse failure (file exists but is not valid JSON) as a hard refusal — throw a descriptive error and make no write
- verify: the AC-1 regression test now passes; a new ENOENT-path test confirms fresh-file creation still works (AC-2)
- done: AC-2

### T3: Add timestamped backup + atomic temp-file rename to every write
- files: `packages/host-claude-code/src/install.ts`
- action: before writing, if a prior file existed, copy it to a timestamped backup path (e.g. `.claude/settings.json.bak-<ISO8601>`); write the new content to a temp file in the same directory and `rename()` it over the final path instead of writing the final path directly
- verify: a new test asserts a backup file appears after a successful install over an existing settings file, and that the write is observably atomic (temp file used then renamed)
- done: AC-3

### T4: Confirm existing merge/preserve behavior and full suite pass
- files: `packages/host-claude-code/tests/install.test.ts`
- action: re-run the existing successful-parse/merge tests unchanged and add one asserting third-party keys survive a normal (valid-JSON) install end-to-end after the T2/T3 changes; run the package test suite
- verify: `pnpm --filter @manehorizons/cadence-host-claude-code test` exits successfully with no failing tests, including all AC-1..4 tests
- done: AC-4
