# 105-01 — cadence start: menu + render core

## Objective

Build the pure, I/O-free core of `cadence start`: the onboarding menu catalog
(options → runner + args) and its text/JSON/confirm renderers.

## Acceptance Criteria

### AC-1: Menu catalog routes every option correctly
Given the static `START_OPTIONS` catalog
When it is inspected
Then there are six options numbered 1..6, the core options (tutorial/init/mcp
install/doctor) carry runner `cadence` with the right args, and the two host
options carry runner `npx` with the `@manehorizons/cadence-host-*` install args.

### AC-2: Out-of-range picks resolve to nothing
Given the `resolvePick` resolver
When it is called with a number outside 1..6 (e.g. 0 or 7)
Then it returns `undefined`.

### AC-3: The menu renders all options, the quit line, and a bounded annotation
Given `renderMenu`
When it renders uninitialized
Then it lists all six options plus a `q. Quit` line and contains no "already
set up" annotation; and when it renders initialized, only the init option gains
the `(already set up — re-runs are safe)` annotation. `renderConfirm` names the
chosen command and shows the `[Y/n]` prompt.

### AC-4: The structured menu is emitted for `--json`
Given `renderJson`
When called with an `initialized` flag
Then it returns `{ options, initialized }` with all six options, each carrying a
`runner` field.

## Tasks

### T1: Menu catalog + pick resolution
- files: `packages/core/src/start/menu.ts`, `packages/core/tests/start/menu.test.ts`

### T2: Render text + JSON + confirm
- files: `packages/core/src/start/render.ts`, `packages/core/tests/start/render.test.ts`
- action: `renderMenu(initialized)`, `renderJson(initialized)` (→ `StartMenuJson`),
  `renderConfirm(option)`. TDD per plan Task 2.
- verify: `pnpm --filter @manehorizons/cadence-core test -- start/render.test.ts`
- done: AC-3, AC-4

## Boundaries

- DO NOT add any I/O, spawning, readline, or `commander` wiring in this phase —
  that is phase 106 (the CLI shell).
- DO NOT modify existing commands, `register.ts`, or `quickstart` here.
- Keep `menu.ts` and `render.ts` pure (no `node:fs`, no `process`).
