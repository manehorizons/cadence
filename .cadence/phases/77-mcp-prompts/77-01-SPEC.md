# 77-01 — Shared guidance extraction + MCP Prompts

## Objective

Extract the canonical command-guidance prose + the `cadence-scout` dialogue into a shared module,
then expose guided workflows as MCP **Prompts** on `cadence mcp serve`, so non-Claude-Code hosts get
the same guidance — with a single source of truth.

## Acceptance Criteria

### AC-1: Guidance is shared without changing the host slash commands
Given the guidance prose (descriptions, trailing steps, scout dialogue) moved into a shared module
(`@manehorizons/cadence-types`)
When `cadence-host-claude-code install` renders its `.claude/commands/cadence-*.md` files
Then the rendered files are byte-identical to before the extraction (regression-guarded by a test).

### AC-2: Prompts are advertised
Given a `cadence mcp serve` server in an initialized repo
When the client calls `prompts/list`
Then it advertises `cadence_scout`, `cadence_next`, `cadence_draft`, and `cadence_settle`, and the
server declares the `prompts` capability.

### AC-3: The scout prompt interpolates its topic
Given the connected server
When the client calls `prompts/get` for `cadence_scout` with a `topic` argument
Then the returned message text is the shared scout dialogue with the topic substituted for the
`$ARGUMENTS` placeholder.

### AC-4: Workflow prompts return their guidance
Given the connected server
When the client calls `prompts/get` for `cadence_next`, `cadence_draft` (with phase/num), and
`cadence_settle`
Then each returns a user-facing message built from the shared guidance (no MCP SDK imported by the
shared module).

## Constraints

- **Byte-identical host output.** The extraction is behavior-preserving for
  `cadence-host-claude-code`; the only change is the *source* of the strings. A test asserts the
  rendered command files are unchanged.
- **Shared module home = `cadence-types`** (refinement of the design doc's `core/guidance`):
  host-claude-code already imports values from `cadence-types` and none from `core` (core's barrel
  is intentionally empty post phase-55), so types is the lowest common dependency and avoids a new
  host→core engine coupling. The module is pure data — no logic, no I/O, no MCP SDK.
- **Prompts live in `packages/core/src/mcp/prompts.ts`**, registered from `server.ts`; they consume
  the shared module. No prompt drives the loop (they orient; the tools act).
- **TDD, house style:** prompt tests via the SDK in-memory transport against a `cadence-testkit`
  repo; the parity test renders host commands to a temp dir and diffs. Each AC referenced by its
  `AC-N` token. Tests under `packages/core/tests/mcp/` and `packages/host-claude-code/tests/`.

## Open Questions
