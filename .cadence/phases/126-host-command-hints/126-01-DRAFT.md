# 126-01 - Fix generated host command hints

## Objective

Update Claude Code and Codex generated command hints so `cadence-build` advertises valid `build task` statuses: `DONE`, `DONE_WITH_CONCERNS`, `NEEDS_CONTEXT`, and `BLOCKED`.

## Acceptance Criteria

### AC-1: Claude Code command hint matches CLI statuses
Given `cadence-host-claude-code install` generates `.claude/commands/cadence-build.md`
When the command frontmatter is rendered
Then its argument hint uses `--status=<DONE|DONE_WITH_CONCERNS|NEEDS_CONTEXT|BLOCKED>`.

### AC-2: Codex prompt hint matches CLI statuses
Given `cadence-host-codex install` generates `cadence-build.md` in Codex prompts
When the prompt frontmatter is rendered
Then its argument hint uses `--status=<DONE|DONE_WITH_CONCERNS|NEEDS_CONTEXT|BLOCKED>`.

### AC-3: Tests guard against stale invalid status hints
Given the old hint advertised `PASS|FAIL|BLOCKED|ESCALATED`
When targeted host command tests run
Then they fail if generated hints contain those invalid values.

## Tasks

### T1: Update Claude Code build argument hint
- files: `packages/host-claude-code/src/install-commands.ts`
- action: Change `cadence-build` argument hint to valid `build task` statuses.
- verify: Generated Claude command content contains `DONE|DONE_WITH_CONCERNS|NEEDS_CONTEXT|BLOCKED`.
- done: AC-1

### T2: Update Codex build argument hint
- files: `packages/host-codex/src/install-commands.ts`
- action: Change `cadence-build` argument hint to valid `build task` statuses.
- verify: Generated Codex prompt content contains `DONE|DONE_WITH_CONCERNS|NEEDS_CONTEXT|BLOCKED`.
- done: AC-2

### T3: Add/adjust targeted host command tests
- files: `packages/host-claude-code/tests/*`, `packages/host-codex/tests/*`
- action: Ensure tests assert the valid hint and reject stale `PASS|FAIL|BLOCKED|ESCALATED`.
- verify: Targeted host command tests pass.
- done: AC-3

## Boundaries

- DO NOT change runtime `build task` status semantics.
- DO NOT change command names or CLI invocations.
- DO NOT weaken Claude/Codex command parity.
