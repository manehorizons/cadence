# 283-01 — Bypass-aware assurance grading

## Objective

A settle whose gates were bypassed, or whose real verifier failed ACs that --force overrode, must not be gradable as assurance.overall: 'strong' -- deriveAssuranceRecord currently reads acResults only, which by settle time already records pass:true for a --force-overridden AC, so a forced settle over real failures is indistinguishable from a clean one (measured: 272-assurance-record-correctness and 282-coverage-scanner-determinism both graded 'strong' over recorded gateBypasses and real host-cli deepVerify failures).

## Acceptance Criteria



### AC-1: overall never strong under an error-severity bypass
Given a settle whose SUMMARY carries a non-empty gateBypasses array with at least one error-severity entry
When the assurance record is derived
Then overall is capped at 'mixed' and can never be 'strong', regardless of verifier identity or evidence ratio

### AC-2: real verifier failures excluded from strongRatio
Given a deepVerify entry with pass:false from a non-mock provider for some AC
When the assurance record is derived
Then that AC does not contribute to strongRatio as though it passed, without acResults[].pass being altered

### AC-3: clean settles are byte-identical to pre-change output
Given a settle with no gateBypasses and no failing verifier verdicts
When the assurance record is derived
Then overall is byte-identical to the pre-change output, proven against a fixture captured before this phase's implementation change

### AC-4: deriveAssuranceRecord stays pure and gate-agnostic
Given the new bypass/deepVerify input deriveAssuranceRecord now accepts
When the function executes
Then it remains pure (no I/O, no clock) and never branches on gateBypasses[].gate or any gate name; the existing phase-233 gate-agnostic tripwire test passes unmodified

### AC-5: corpus report enumerates every grade change, no SUMMARY mutated
Given the full on-disk corpus of .cadence/phases/**/*-SUMMARY.json records
When the new grading rule is applied read-only to each record
Then a committed report enumerates every record whose grade would change (phase id, old grade -> new grade), no SUMMARY.json on disk is modified, and cadence summary verify-all reports 0 MISMATCH / 0 failed both before and after this phase's code change

### AC-6: bypass state rendered alongside the grade
Given a settled SUMMARY carrying both an assurance record and a non-empty gateBypasses array
When cadence summary render runs
Then the rendered artifact surfaces the bypass state next to the overall grade line, not only in the raw JSON
