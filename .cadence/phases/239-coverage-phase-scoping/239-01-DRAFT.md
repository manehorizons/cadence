# 239-01 — Phase-attributable AC coverage: close the collision and the false drift

## Objective

Nothing in a settled phase's artifacts records which phase a test belongs to, and CADENCE's two coverage consumers each paper over that with an opposite guess. The `test-coverage` gate searches every `packages/**/*.test.ts` for the bare token `AC-N`; since AC ids restart at `AC-1` each phase, any past phase's `AC-3` satisfies every future phase's `AC-3` — measured here, `AC-1` is satisfied by 189 unrelated files, so a phase can pass the gate having written no tests. `replayPhaseCoverage` instead scopes to the files the DRAFT declared, which under-declares constantly — replaying phase 233 reports 5/5 ACs drifting against a SUMMARY recording all five as pass/executed, a false positive, since 233's tests exist and assert correctly. The gate under-refuses and the replay over-refuses, from one shared cause. This phase fixes the cause: a phase-qualified prefix token (`239-01/AC-3`) makes each test self-identify, which lets the gate demand this phase's own evidence and lets the replay drop file-scoping entirely and match repo-wide on a globally unique token. Phases settled before the scheme existed have no phase-attributable evidence and their true coverage is unrecoverable, so the replay reports them `indeterminate` rather than asserting a verdict it cannot support. Gated behind `verification.coverageScheme` so consumer projects on `@manehorizons/cadence-core@1.51.1` are untouched until they opt in.

## Acceptance Criteria

### AC-1: the bare scheme is unchanged
Given a config with `verification.coverageScheme: "bare"` or with the field absent entirely
When the `test-coverage` gate runs
Then coverage resolution is byte-for-byte identical to current behavior, including `mention`/`assertion` mode and the existing weak-link, skip-only, and refusal message text

### AC-2: the qualified scheme refuses an unqualified or foreign-phase reference
Given `coverageScheme: "phase-qualified"` and a draft whose id is `239-01`
When an AC's only references are a bare `AC-3` token, or another phase's `211-01/AC-3` token, inside an asserting test block
Then the gate refuses that AC as uncovered rather than passing it

### AC-3: the qualified scheme passes on this phase's own token
Given `coverageScheme: "phase-qualified"` and a draft whose id is `239-01`
When an asserting test block references `239-01/AC-3`
Then the gate counts AC-3 as covered, and that same test satisfies no other phase's AC-3

### AC-4: the refusal names the exact expected token
Given a refusal raised under `coverageScheme: "phase-qualified"`
When the gate writes its refusal to stderr
Then the message contains the literal token string the test must carry, so the fix requires no source reading

### AC-5: back-compat holds through the real load path, and the field is operator-editable
Given a `.cadence/config.json` that predates this field, or no config file at all, versus one written by a fresh `cadence init`
When each is resolved through `loadConfig` — the actual path the gate uses, not the Zod schema in isolation
Then the pre-existing and absent cases both resolve to `"bare"` while the fresh init resolves to `"phase-qualified"`, and the field is editable through `cadence config edit`

As built: this AC originally asserted only the Zod schema layer, and that layer was correct while the shipped behavior was not. `loadConfig` (`config/loader.ts:20-28`) merges the user's `config.json` *over* `defaultConfig`, so a `defaultConfig` carrying `"phase-qualified"` is injected into every pre-existing config before Zod parses and the field-level `.default("bare")` never fires — flipping every consumer of published 1.51.1 to the strict scheme on upgrade. The phase-139 `coverageMode` precedent does not transfer, because `cadence init` writes `coverageMode` explicitly into every config.json so the user's own value wins the merge, whereas no config on earth contains `coverageScheme`. The AC is therefore restated to bind the end-to-end load path, and the mechanism moves: `defaultConfig` holds `"bare"` and `cadence init` writes `"phase-qualified"` explicitly in its existing verification overlay (`init.ts:372-378`, alongside `testGlobs`/`coverageMode`).

### AC-6: the prefix form keeps the bare token lexable
Given a qualified token in the prefix form `239-01/AC-3`
When any existing consumer of `AC_TOKEN_RE` scans it
Then the embedded `AC-3` still lexes as a bare token, and `cadence verify coverage --explain` additionally reports whether each occurrence satisfies the configured scheme

### AC-7: the settle records which scheme produced the evidence
Given a phase settles under either scheme
When `SUMMARY.json` is written
Then it records the `coverageScheme` and `coverageMode` in force at settle, as additive optional fields that leave every pre-existing SUMMARY parsing unchanged

### AC-8: replaying a qualified-scheme phase matches repo-wide with no file scoping
Given a settled phase whose SUMMARY records `coverageScheme: "phase-qualified"`
When `cadence verify phase` replays it
Then it matches that phase's qualified tokens across the whole repo, never scopes to the DRAFT's declared files, and never returns `no-scoped-files` — so a phase that under-declared its test files replays correctly

### AC-9: replaying a pre-scheme phase reports indeterminate, never drift
Given a settled phase whose SUMMARY records no coverage scheme, such as phase 233
When `cadence verify phase` replays it
Then each AC is reported `indeterminate` with `drift: false`, the output states that pre-scheme coverage is not phase-attributable and therefore unverifiable, and the command does not claim drift it cannot substantiate

### AC-10: docs are paired and this repo dogfoods the scheme
Given the gate, replay, and config schema have changed
When the doc-content test surface runs
Then `docs/concepts.md`'s `test-coverage` gate row and `docs/reference/config.md`'s field table both describe `coverageScheme`, a doc test asserts the pairing, and this repo's `.cadence/config.json` is set to `"phase-qualified"` so this phase settles under its own new rule

## Boundaries

- DO NOT change `AC_TOKEN_RE` or the bare-token lexing path — AC-6 depends on the embedded token staying lexable, and every existing scanner consumes it.
- DO NOT migrate historical tests to the qualified form. The gate only evaluates the phase being settled, and pre-scheme phases are reported indeterminate by design.
- DO NOT attempt to compute a real coverage verdict for a pre-scheme phase. The evidence is not phase-attributable; asserting a verdict is the bug being fixed.
- DO NOT change the Zod-level default away from `bare` — that is the back-compat contract for every consumer project on upgrade.
- DO NOT bump `SUMMARY.schemaVersion`; the kernel-assurance arc owns that bump and a second one here would collide at merge.
- DO NOT touch the criteria-anchoring surface (`verify/anchor.ts`, `verify/criteria-gap.ts`, `gates/code-review.ts`) — it lives on the arc branch, not here.
- DO NOT add a runtime dependency.
