# 144-01 — Docs + release for cross-worktree handoff picker (v1.38.0)

## Objective

Document the cross-worktree handoff-picker feature (phases 142+143) across the reference docs and DESIGN.md, then cut the v1.38.0 lockstep release — the final phase of this 3-phase milestone.

## Acceptance Criteria

### AC-1: commands.md documents the full current `resume` surface
Given `docs/reference/commands.md`'s `### resume` section, which predates phases 142+143 and only documents `--json` (missing even the pre-existing `--full`/`--brief` flags)
When it is rewritten
Then it documents every current flag (`--json`, `--full`, `--brief`, `--list`, `--pick <n>`, `--path <p>`, `--local`), the default-2+-candidates stderr nudge, the sibling-pick read-only behavior + its text markers, and the two flag-conflict refusals (multiple selectors; `--local` + a selector)

### AC-2: config.md documents the `resume` config block
Given `docs/reference/config.md`'s existing `## phaseGuard` / `## handoff` sections as the style precedent
When a new `## resume` section is added in the same style (field table, behavior prose, a `.cadence/config.json` example)
Then it documents `resume.crossWorktree` (default `true`) and `resume.autoList` (default `false`), and explicitly notes — matching the phase-143 AC-8 precedent — that this block is schema-only and intentionally absent from `config edit`/`config explain`'s curated field set, the same as `phaseGuard`/`handoff`/`logging`

### AC-3: concepts.md's worktree section gets a cross-worktree-resume addendum
Given `docs/concepts.md`'s "Worktrees & the single-writer assumption" section, which currently only describes the phase-collision guard
When a short addendum paragraph is added after the existing phase-collision-guard paragraph
Then it describes `cadence resume`'s cross-worktree candidate discovery as a sibling application of the same ground-truth philosophy (live `git worktree list` scan, no cached index), links to the new `resume` config.md section, and names the default nudge-not-auto-picker UX

### AC-4: DESIGN.md §13 gets an addendum, no new D-number
Given `DESIGN.md`'s `## 13. Worktree safety (phase-collision guard)` section and its existing "Polished in the v1.19 milestone" addendum paragraph as the style precedent
When a new addendum paragraph is appended after it
Then it records the v1.38 cross-worktree-handoff-discovery milestone (phases 142-144) as a sibling application of §13's locked "observe ground truth, not a registry" decision — extended from phase numbers to handoff docs — with no new D-number (deepens §13, matching the v1.19 follow-on pattern)

### AC-5: lockstep v1.38.0 release across all four published packages
Given the four published packages (`cadence-core`, `cadence-types`, `cadence-host-claude-code`, `cadence-host-codex`) all currently at `1.37.0`
When a changeset is added (all four `minor`) and `pnpm changeset version` is run
Then all four `package.json` files read `1.38.0` and each package's `CHANGELOG.md` gets a new `1.38.0` entry

### AC-6: doc-sync gate passes and full monorepo verify is green
Given the repo's `doc-sync` pre-commit hook, which fails a commit changing `packages/core/package.json`'s version unless `CLAUDE.md` mentions the new version
When `CLAUDE.md`'s release narrative is updated to describe v1.38.0 (mentioning the literal string `1.38.0`) alongside the version bump commit
Then the doc-sync hook passes, and `pnpm build && pnpm typecheck && pnpm lint && pnpm test` are all green
