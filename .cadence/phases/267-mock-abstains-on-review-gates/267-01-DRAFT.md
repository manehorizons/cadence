# 267-01 — Mock abstains on review gates

## Objective

Make it structurally impossible for CADENCE's mock verifier to record a review-gate pass: code-review, security-audit, plan-review, spec-review, and ui-spec-review gates abstain (status: skipped + skipReason) under a mock provider instead of passing, decided at the gate/registry layer before the verifier is ever dispatched; deep-verify and per-task-verify keep their existing mock pass semantics; and once abstention is verified, the repo's own gate profile moves off auto with an explicitly approved value, closing dec-20260804-001's deferred baseline-profile decision.

## Acceptance Criteria

### AC-1: Review-family gate abstains under mock, decided upstream of verify()
Given a review-family gate (code-review, security-audit, plan-review, spec-review, or ui-spec-review) resolves to the mock provider for that seam
When the gate would otherwise run and record a result
Then it records status: 'skipped' with a skipReason naming the mock-abstention reason, and no configuration of CADENCE can produce a persisted 'pass' for that gate under mock -- including when the diff is empty -- because the abstention decision is made at the gate/registry layer before the verifier is ever dispatched, not inside the verifier's own diff-based early return
- As built (2026-08-09): corrected per dec-20260809-004 (supersedes dec-20260809-003). "Before the verifier is ever dispatched" was the wrong mechanism -- T2's first attempt implemented it literally and broke 124 pre-existing tests across 20 files that exercise real mock-verifier gate behavior (console.log-as-HIGH-finding detection, refuse/reloop/escalate convergence, --force/--allow-*-failure bypass mechanics), all of which requires verify() to actually run under mock. The corrected, load-bearing bar: verify() dispatches normally under mock, exactly as today; the abstention decision moves to the *recording* layer -- registry.ts derives status:'skipped'+skipReason (instead of 'ran') if and only if the resolved identity is mock AND the outcome is a clean pass. A mock-served 'refuse' (a real finding was flagged) keeps its normal refusal recording, never relabeled -- a refusal is never false confidence. This still closes the empty-diff/no-marker-found false-clean-pass gap (those cases resolve to outcome:'pass' under mock, so they get relabeled skipped), while preserving every real capability mock's verify() methods have.

### AC-2: deep-verify and per-task-verify keep existing mock pass semantics
Given a settle where deep-verify or per-task-verify resolves to the mock provider
When the gate runs
Then it keeps its existing AC-linked-test pass/fail semantics, unaffected by the review-family abstention change, proven by adversarial fixtures covering both families
