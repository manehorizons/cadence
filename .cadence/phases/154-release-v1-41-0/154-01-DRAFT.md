# 154-01 — Release v1.41.0: MCP parity for the intelligence lifecycle

## Objective

Document phase 153's three new MCP tools + SUMMARY.json resource in docs/mcp.md, then cut the v1.41.0 lockstep release across all four published packages bundling phase 153 (MCP parity for the intelligence lifecycle) -- the accumulated unreleased work on main since v1.40.0.

## Acceptance Criteria

### AC-1: docs/mcp.md documents the three phase-153 MCP additions
Given docs/mcp.md's Tools table says the server advertises 15 tools and lists neither cadence_recommendation_convert, cadence_milestone_propose, nor cadence_recommendation_archive, and its Resources table has no summary.json row
When the Tools table gains rows for the three new tools (with the advertised-tool-count prose updated from 15 to 18) and the Resources table gains a cadence://phase/{phase}/summary.json row
Then docs/mcp.md accurately reflects the current MCP surface

### AC-2: lockstep v1.41.0 release across all four published packages
Given the four published packages (cadence-core, cadence-types, cadence-host-claude-code, cadence-host-codex) all currently at 1.40.0
When a changeset is added (all four minor) and pnpm changeset version is run
Then all four package.json files read 1.41.0 and each package's CHANGELOG.md gets a new 1.41.0 entry

### AC-3: doc-sync gate passes and full monorepo verify is green
Given the repo's doc-sync pre-commit hook, which fails a commit changing packages/core/package.json's version unless CLAUDE.md mentions the new version
When CLAUDE.md's release narrative is updated to describe v1.41.0 (mentioning the literal string 1.41.0) alongside the version bump commit
Then the doc-sync hook passes, and pnpm build && pnpm typecheck && pnpm lint && pnpm test are all green
