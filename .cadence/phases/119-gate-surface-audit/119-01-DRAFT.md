# 119-01 - Audit remaining gate surfaces

## Objective

Audit remaining gate surfaces for unsafe path construction, shell-string execution, and silent config fallback outside the Phase 118 repair set, then fix any concrete gaps found.

## Acceptance Criteria

### AC-1: Path joins reviewed beyond Phase 118
Given command, MCP, host-adapter, and gate code can build paths from user or state input
When remaining path joins are searched and reviewed
Then any unsafe join has validation, canonicalization, or documented non-user-input reasoning.

### AC-2: Shell execution reviewed beyond Phase 118
Given shell execution can turn filenames or config into command injection risk
When remaining `execSync`, `spawn`, `execa`, and child-process call sites are reviewed
Then any shell-string use with dynamic data is replaced or documented as intentionally configured command execution.

### AC-3: Config fallback reviewed beyond Phase 118
Given invalid config should not silently weaken gates
When remaining `loadConfig` and config parse call sites are reviewed
Then invalid config fails closed for gate-bearing flows and any non-gate fallback is explicit.

### AC-4: Findings are durable
Given this is an audit phase
When the review completes
Then settled artifacts summarize reviewed surfaces, fixes, and residual risk.

## Tasks

### T1: Search remaining path surfaces
- files: `packages/**/src/**/*.ts`
- action: Inventory `join`, `resolve`, Cadence URI parsing, phase/task path assembly, and host adapter file writes outside files changed by Phase 118.
- verify: `rg` evidence captured in notes or code comments where risk is dismissed.
- done: AC-1

### T2: Search remaining shell surfaces
- files: `packages/**/src/**/*.ts`, scripts if relevant
- action: Inventory child-process call sites and classify as argv-safe, configured-command, or unsafe dynamic shell.
- verify: Any unsafe dynamic shell has code fix plus regression coverage.
- done: AC-2

### T3: Search remaining config fallback surfaces
- files: `packages/**/src/**/*.ts`
- action: Inventory config loading and parsing fallback paths, especially gates, hosts, MCP, and command startup.
- verify: Gate-bearing invalid config errors propagate; non-gate defaults are documented by local control flow.
- done: AC-3

### T4: Patch concrete gaps
- files: discovered during T1-T3
- action: Apply narrow fixes only for confirmed issues; avoid speculative refactors.
- verify: Focused tests for each behavior changed.
- done: AC-1, AC-2, AC-3

### T5: Run gate and settle
- files: workspace
- action: Run relevant focused tests plus full workspace gate if code changed.
- verify: `pnpm.cmd -w lint`, `pnpm.cmd -w typecheck`, `pnpm.cmd -w test`, `pnpm.cmd -w build`, then `cadence settle run`.
- done: AC-4
