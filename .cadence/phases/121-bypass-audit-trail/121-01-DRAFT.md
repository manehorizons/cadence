# 121-01 — Loud audit trail for settle bypasses

## Objective

Make every successful settle that bypasses a verification gate leave a loud, durable audit trail in SUMMARY artifacts and stderr.

## Acceptance Criteria

### AC-1: Durable JSON bypass record
Given a BUILD phase settles successfully with a bypass flag such as `--allow-missing-coverage`, `--allow-verifier-failure`, or `--force`
When `SUMMARY.json` is written
Then it includes a structured `gateBypasses` array naming the bypass type, severity, flag, and human-readable reason.

### AC-2: Human-readable SUMMARY section
Given `SUMMARY.json` contains one or more gate bypasses
When `SUMMARY.md` is rendered
Then it includes a `## Gate bypasses` section with each bypass shown as a loud audit line.

### AC-3: Visible settle-time warning
Given a settle succeeds only because one or more bypass paths were used
When `cadence settle run ...` exits successfully
Then stderr includes a visible warning that the settle completed with bypassed verification.

### AC-4: Clean settles stay quiet
Given a settle completes without bypassing verification
When `SUMMARY.json`, `SUMMARY.md`, and stderr are inspected
Then no `gateBypasses` field, no Gate bypasses section, and no bypass warning are emitted.

### AC-5: Existing anomaly semantics preserved
Given a profile includes `anomaly-notify`
When a bypass also produces existing anomaly events
Then notification behavior remains unchanged while the new summary audit trail is still written.
