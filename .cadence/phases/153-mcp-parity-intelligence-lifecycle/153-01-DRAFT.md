# 153-01 — MCP parity for the intelligence lifecycle

## Objective

An MCP-only client can add or promote a recommendation but cannot convert it to a phase, propose a milestone, or archive it. Close the scout-to-phase story over MCP by adding cadence_recommendation_convert, cadence_milestone_propose, and cadence_recommendation_archive tools, plus a per-phase SUMMARY.json resource, as thin wrappers over the existing service/store functions.

## Acceptance Criteria

### AC-1: recommendation_convert tool
Given a recommendation exists and its target phase has been scaffolded
When the cadence_recommendation_convert MCP tool is called with the rec id and phase
Then the recommendation's status becomes converted with convertedToPhaseId set, matching cadence recommendation convert

### AC-2: milestone_propose tool
Given at least one recommendation is accepted with readiness ready-for-milestone or ready-for-cadence-spec
When the cadence_milestone_propose MCP tool is called
Then the milestone ledger is updated with proposed milestones identical to cadence milestone propose's clustering output

### AC-3: recommendation_archive tool
Given a live recommendation exists in the ledger
When the cadence_recommendation_archive MCP tool is called with its id
Then the recommendation moves into the archived array with archivedAt/archiveReason stamped, recoverable via recommendation_unarchive semantics

### AC-4: SUMMARY.json resource
Given a phase has a *-SUMMARY.json artifact on disk
When an MCP client reads cadence://phase/{phase}/summary.json
Then the raw SUMMARY.json bytes are returned with mimeType application/json

### AC-5: promote tool description no longer dead-ends
Given an MCP-only client has just called cadence_recommendation_promote
When it reads the tool's description text
Then the description names cadence_milestone_propose and cadence_recommendation_convert as the real next-step tools, not CLI-only commands

## Boundaries

- DO NOT change the CLI surface (`cli/commands/recommendation.ts`, `cli/commands/milestone.ts`) — this phase is MCP-only parity, not a CLI feature.
- DO NOT change the pure store/core logic (`runRecommendationTransition`, `runProposeMilestones`, `runRecommendationArchive`) — reuse as-is, thin-wrap only.
- DO NOT add resource subscriptions or file-watching — matches the existing read-on-demand-only line from phase 75.
- DO NOT add a `cadence_recommendation_unarchive` or `cadence_milestone_accept/defer/export` tool in this phase — out of scope per rec-20260701-010's stated fix list; a follow-up rec if more parity is wanted later.
