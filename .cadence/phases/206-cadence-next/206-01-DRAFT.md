# 206-01 — cadence next: state-derived legal next moves at any loop position

## Objective

Add a read-only cadence next command that answers "what now?" deterministically from live loop state at any position — ranked legal moves with exact commands, plus a stable --json contract — by extending the engine's existing nextAction() rather than reimplementing it.

## Acceptance Criteria

### AC-1: cadence next reports ranked legal moves at any loop position
Given the loop is at any position -- empty ledger, pending DRAFT, mid-BUILD with remaining tasks, all tasks DONE, or settled with a converted/unconverted rec
When cadence next is run
Then it prints the current position plus 1-3 ranked legal moves with exact commands, computed via the same underlying logic nextAction() already provides to quickstart/progress -- not a parallel reimplementation (dec-20260721-001)

### AC-2: cadence next --json exposes a stable, versioned contract
Given the loop is at any position
When cadence next --json is run
Then the output includes schemaVersion: 1 (dec-20260721-003) and the shape {position, remainingTasks, blockedOn, legalMoves[]}

### AC-3: nextAction() upgrade is non-breaking for existing callers
Given quickstart and progress (packages/core/src/progress.ts) already depend on nextAction()'s single {command, reason} shape
When nextAction() is extended to also compute ranked legalMoves[]
Then quickstart and progress continue rendering their existing one-line next-step output unchanged -- no regression in either command's current behavior or tests

### AC-4: /cadence-next slash command is registered
Given packages/host-claude-code/src/install-commands.ts's COMMANDS array (14 entries today)
When this phase ships
Then a cadence-next CommandSpec entry exists (15 total) and docs-command-count.test.ts plus any README/quickstart doc asserting the command count are updated to match

## Boundaries

- DO NOT subsume quickstart's other state-summary content (dec-20260721-001) — cadence next owns only the ranked-legal-moves surface.
- DO NOT wire the empty-state footer integration for rec-20260721-001 — that rec is a separate, not-yet-converted phase; only expose nextAction()'s ranked output in a form that phase can consume later.
- DO NOT change nextAction()'s existing single-command `{command, reason}` return shape/signature for current callers — quickstart and progress must keep working unchanged.
- DO NOT have cadence next advise how to implement work — it names the door (the command), never the path through it.
