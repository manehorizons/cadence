# 03-01 — Local-link dogfood story for unpublished adapters

## Objective

Make `keel-host-claude-code install` and `keel-host-codex install` produce
runnable hooks against an unpublished local checkout, so KEEL can fully
dogfood itself before either package ships to npm.

## Acceptance Criteria

### AC-1: --local flag emits absolute-path commands (host-claude-code)
Given a fresh repo with workspace KEEL checked out at `<keelRoot>`
When `keel-host-claude-code install --local` runs
Then `.claude/settings.json` hook commands are
`node <abs>/packages/host-claude-code/dist/cli.js hook --keel "node <abs>/packages/core/dist/cli/index.js"`
(no `npx`).

### AC-2: --local also works for host-codex
Given the same setup
When `keel-host-codex install --local` runs
Then `.codex/hooks.json` hook commands point at
`node <abs>/packages/host-codex/dist/cli.js hook --keel "node <abs>/packages/core/dist/cli/index.js"`.

### AC-3: slash-command / skill bodies are re-pointed too
Given install --local
Then rendered slash command bodies (Claude Code) and SKILL.md bodies (Codex)
reference `node <abs>/packages/core/dist/cli/index.js <verb>` instead of `keel <verb>`.

### AC-4: default (no --local) is unchanged
Given install with no flags
Then commands still default to `npx @keel/host-claude-code hook` /
`npx @keel/host-codex hook` and slash bodies still say `keel <verb>`.
Back-compat preserved.

### AC-5: self-install proof
Given the current KEEL repo
When the committed `.claude/settings.json` is regenerated with `--local`
Then a unit test spawning the installed shim command with simulated
SessionStart stdin observes `.keel/state.json` updating end-to-end.

## Tasks

### T1: locate-self utility (per adapter)
- files: `packages/host-claude-code/src/locate-self.ts`, `packages/host-codex/src/locate-self.ts`, plus tests
- action: TDD `resolveLocalPaths()` returning `{ shimCli, coreCli }` as
  absolute paths derived from the running installer's own
  `import.meta.url`. One copy per adapter (paths differ).
- verify: tests assert resolved paths end with `dist/cli.js` for the
  adapter and `dist/cli/index.js` for core; both files exist on disk
  when the package is built.
- done: AC-1, AC-2

### T2: wire --local into installHooks (both adapters)
- files: `packages/host-claude-code/src/install.ts`,
  `packages/host-codex/src/install.ts`, plus updated tests
- action: add `local?: boolean` to InstallOptions. When true and
  `command` / `keelCommand` are not explicitly set, use
  `node <shimCli> hook` and `node <coreCli>` respectively. When false
  (default), preserve current npx defaults.
- verify: new tests cover both branches; existing tests still pass.
- done: AC-1, AC-2, AC-4

### T3: wire --local into installCommands (both adapters)
- files: `packages/host-claude-code/src/install-commands.ts`,
  `packages/host-codex/src/install-commands.ts`, plus updated tests
- action: add `local?: boolean` to InstallCommandsOptions. When true,
  default `keelCommand` to `node <coreCli>` so rendered slash commands
  and SKILL.md bodies invoke the local core build.
- verify: tests assert the rendered body contains the absolute core
  path; default behavior unchanged.
- done: AC-3, AC-4

### T4: --local CLI flag on both adapters
- files: `packages/host-claude-code/src/cli.ts`,
  `packages/host-codex/src/cli.ts`
- action: add `--local` to the `install` subcommand on both adapters;
  pass through to installHooks and installCommands.
- verify: `--help` lists the flag; new integration test invokes
  `install --local` and asserts written commands are absolute paths.
- done: AC-1..AC-4

### T5: regenerate self-install + smoke
- files: `.claude/settings.json`, `.claude/commands/keel-*.md`
  (regenerated by the new flag), plus a smoke test
- action: run `keel-host-claude-code install --local` against the KEEL
  repo itself, commit the result. Add a unit test that spawns the
  installed shim command with SessionStart stdin and asserts
  `.keel/state.json` updates.
- verify: smoke test green; `.claude/settings.json` shows local
  absolute paths.
- done: AC-5

### T6: README + memory update
- files: `README.md`, memory `project_keel.md`
- action: document `--local` in both "Use with …" sections; note it's
  intended for monorepo dogfood pre-publish. Memory: mark dogfood
  story closed.
- verify: README has --local snippet for both adapters; memory updated.
- done: AC-5

## Boundaries

- DO NOT publish either adapter to npm in this phase.
- DO NOT change abstract event schema or core hook handlers.
- DO NOT introduce a new shared package; if logic duplicates across
  adapters, accept it for now and revisit in a future host-shared phase.
- DO NOT break the npx-style defaults — they remain the published-
  package behavior.
