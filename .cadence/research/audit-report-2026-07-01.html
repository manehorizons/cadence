Cadence — audit & assessment

The demo enforces.
The default doesn’t.

Cadence’s first touch is exceptional — npx -y @manehorizons/cadence-core tutorial stages a lie and lets the settle gate catch it, in 0.4 seconds, with zero installs. But on a fresh cadence init, the same lie settles green: coverage counts comments, no test command is configured, and every verifier is a mock. The architecture underneath is excellent; the out-of-box configuration doesn’t yet deliver the enforcement the pitch — and the tutorial — promise. Closing that gap is the highest-leverage work available.

01

Scorecard

Grades reflect what a user experiences today, not the quality of the underlying code — which is consistently strong. The spread between Architecture (A−) and Out-of-box enforcement (C) is the report in one line.

A−
First-touch onboarding

The zero-install tutorial is a model first touch; init --dry-run and zero-prompt init are genuinely thoughtful. Docked for the --demo dead-end and the doctor bug.

A−
Architecture quality

Single-source gate matrix, io-seam shared by CLI + MCP, Record-total gate registry, 290 test files, testkit fixtures. Well-factored throughout.

B
Loop ergonomics

State-aware refusals are among the best in class — but all draft content is hand-edited markdown, and approve re-demands args the state already holds.

B−
Agent drivability

agent-prompt is a great idea, but progress — the command agents need most — has no --json, and the prompt walks agents into a non-TTY approve trap on mature repos.

B−
Docs accuracy

The flagship README example refuses for a different reason than the comment claims; three docs give three different slash-command counts (11 / 9 / 12).

C
Out-of-box enforcement

Default chain: mention-mode coverage + no testCommand + all-mock verifiers + every gate --force-bypassable. The wedge doesn’t hold weight until the user reconfigures it.

02

What’s genuinely strong

A fair audit names what works. These aren’t pleasantries — each is a deliberate piece of discipline most tools at this stage don’t have.

✓The tutorial is a model first touch

Zero install, real engine services (it structurally cannot lie), the refusal as the centerpiece, self-cleaning sandbox, 0.4s runtime. It even fails loudly if the staged lie isn’t caught.

✓Honesty messaging can’t drift

One MOCK_VERIFIER_NOTICE constant feeds init, doctor, activate, config explain, and the settle banner — the "mock is not real verification" wording is provably single-source.

✓State-aware, actionable refusals

draft new names your loop position and the exact command out; build task lists the valid task ids on a typo. Among the best error UX in a CLI this size.

✓init --dry-run pre-flight

Resolves name, preset, profile, layout, globs, verification, host and the exact file list — writes nothing, and previews rather than refuses on an already-initialized repo.

✓Bypasses leave evidence

Every override flag prints a stderr notice and lands in gateBypasses in the SUMMARY. Escape hatches exist, but they’re auditable.

✓One engine, three surfaces

The io-seam puts a single service implementation behind CLI, hooks, and MCP; slash-command prose is golden-fixture-guarded byte-identical across hosts.

✓Non-TTY thinking is centralized

resolveInteractivity(env, isTTY) is one pure seam driving both interactive gates, with env overrides — the right shape, even if per-command policy still varies.

✓146 settled phases of dogfooding

The repo’s own .cadence/ is live state. The tool has planned and shipped itself through 35 releases — rare, verifiable credibility.

03

Key findings

Ordered by severity. Marks follow Cadence’s own doctor vocabulary: ✗ would refuse in a strict gate; ! warning-grade friction. Every finding was verified against source or reproduced hands-on in a sandbox during this audit.

✗critical

F1 · The default enforcement chain is hollow — a comment-only "test" settles green

Reproduced live (header, right pane). Three independent defaults compound: (1) coverage ships in mention mode, where a bare // AC-1 comment satisfies the gate by design; (2) init detects test globs but never sets verification.testCommand, so build-test-must-pass — a headline always-fire gate — passes silently without running anything; (3) all six verifier seams default to mock, which checks token-linkage only. The competitive wedge — "in-loop enforcement" — is exactly what a fresh install doesn’t deliver. The assertion-mode fix already exists (v1.28); it just isn’t the default.

verify/coverage.ts:39–46 · gates/build-test-must-pass.ts:14–16 · types config.ts:311–317 · sandbox repro 2026-07-01

✗critical

F2 · doctor leaks a Cadence-repo assumption into every consumer repo — and --fix makes it worse

The git-hooks check warns in any git repo whose core.hooksPath isn’t .githooks — it never checks whether a .githooks/ directory exists. Reproduced: in a fresh repo with no such directory, doctor --fix ran git config core.hooksPath .githooks, pointed git at nothing, and then reported the check ok. Worse: a Husky user (core.hooksPath=.husky) gets flagged as misconfigured, and --fix would overwrite their setting and silently disable their hooks. This is a "safe repairs" feature applying an unsafe repair.

doctor/run.ts:138–160 · doctor/fix.ts:95–104 · sandbox repro: hooksPath set, ls .githooks → No such file or directory

✗critical

F3 · SUMMARY overstates: AC-1: PASS with no provenance of what "pass" meant

The settle SUMMARY from F1’s comment-only run records every AC as PASS and every task DONE — indistinguishable from a rigorously verified settle. Nothing records which gates ran, which skipped, and how each AC was satisfied (comment mention vs. asserting test vs. executed test vs. AI-verified). Verifier token usage is captured in deepVerifyMeta but never rendered in SUMMARY.md. For a tool whose identity is honest state, the closing artifact is the least honest surface it has.

settle/summary-writer.ts:1–45 · gates/deep-verify.ts:40–51 · sandbox SUMMARY.json inspection

!high

F4 · progress — the command agents script most — has no --json, and the loop-critical set is text-only

Fifteen commands support --json, but progress isn’t one of them (reproduced: error: unknown option '--json'), even though its service already returns the structured payload MCP gets for free. draft/approve/build task/settle run have no JSON output at all — a CLI-driving agent must regex strings like "Approved 132-01; loopPosition=BUILD". And recommendation show|list alone spell it --format json.

cli/commands/progress.ts:5–12 · services/progress.ts:27 · recommendation.ts:182,260

!high

F5 · init --demo prints instructions that immediately refuse

--demo seeds a ready-to-approve phase, which leaves the loop in DRAFT — but init still prints the generic "Your first loop" block (step 1: cadence draft new …) and the agent prompt telling an agent to run draft new. A user or agent following the most prominent instruction on screen hits draft new refused: loopPosition is DRAFT, not IDLE as their very first post-init experience.

cli/commands/init.ts:436–471 · services/draft-new.ts:56,127

!high

F6 · The agent path walks into a non-TTY approve trap on exactly the repos that matter

init hands any repo with ≥20 commits the standard profile — where draft approve gates interactively and refuses headless without --no-approve. But the README’s first-real-phase example and the copy-paste agent-prompt both use plain cadence draft approve. So the more real the adopter’s repo, the more likely their agent stalls at approve with no guidance in the prompt it was handed.

init/plan.ts:18–31 · agent-prompt/render.ts:32 · README.md:89

!high

F7 · The hand-edit cliff: the CLI drives transitions, humans hand-author all content

Between draft new and approve sits the largest unassisted step in the product: rewriting placeholder objectives, ACs, tasks and literal `source-file` stubs in raw markdown. There is no draft add-ac / add-task / set-objective. The markdown is then parsed structurally — a typo in a ### T1: heading silently changes the task id and later fails as "unknown task id." The stale-draft mtime gate exists precisely because this fragile hand-editing is load-bearing.

parse/draft-scaffold.ts:19–35 · parse/draft-templates.ts:46–48 · cli/commands/draft.ts:10–48

!high

F8 · Every gate is bypassable; boundary enforcement is advisory; subagent edits are invisible

All 13 gates honor --force or a per-gate --allow-* flag — even the production preset removes none of them. The pre-tool-edit boundary check only ever emits warn anomalies; the sole blocking edit hook (preToolUseBuildGate) is off by default; and subagent activity merely increments a counter. The "files:" declaration in a DRAFT is decoration, not a boundary.

gates/types.ts:144–158 · hooks/checks/boundary.ts:59–68 · hooks/handlers.ts:133–142 · types config.ts:296,333–338

!medium

F9 · Docs drift: the flagship example is wrong, and one fact has four values

README’s headline flow (mark only T1 done, settle, "Cadence refuses: AC-1 has no test") actually refuses on the structural-verifier — the bugfix template creates T1–T3, and coverage only fires after all tasks are terminal. Meanwhile the slash-command count is stated as 11 (README), 9 (docs/quickstart.md, twice), and 12 (docs/claude-code.md body — the correct one). Small things, but they sit on the most-read pages of an honesty-branded tool.

README.md:22,87–92 · docs/quickstart.md:507 · docs/claude-code.md:34,168 · install-commands.ts (12 entries)

!medium

F10 · The front doors disagree, and small UX papercuts accumulate

The start menu omits activate — the remedy its own honesty banner points to — while quickstart lists it; "start" vs "quickstart" naming inverts newcomer intuition. draft approve on a missing draft dumps a raw ENOENT (its sibling spec approve guards properly). The BUILD-state next-action is an unrunnable compound (… OR … with an <id> placeholder). settle run out of position names no next step. resume happily replays a handoff that is still all <!-- FILL IN --> placeholders. Each is small; together they erode the "it always tells you the next move" feel that is otherwise Cadence’s best quality.

start/menu.ts:26 · draft-approve.ts:35 vs spec-approve.ts:34 · progress.ts:53–55 · settle.ts:147 · sandbox resume repro

04

Recommendations

Twelve improvements, ranked by value. Presented in Cadence’s own vocabulary — each is written to be liftable straight into cadence recommendation add. Value and effort meters are this audit’s judgment on a 10-point scale.

R-01

Make the default install enforce what the tutorial demonstrates

critical · fixes F1
value
effort

This is the wedge. Every competitive claim rests on "settle refuses work the tests don’t back" — and today that’s only true in the tutorial’s hand-tuned sandbox.

How: (a) default coverageMode to assertion for new inits (existing configs untouched — the mention default stays for back-compat via schema default vs. init-written value); (b) teach init to derive verification.testCommand from package.json#scripts.test the same way it already derives name and globs, and say so in the init summary; (c) when no testCommand can be derived, print one loud line at settle — the silent pass is the trap.

types config.ts:86,311 · init/plan.ts (extend detection) · gates/build-test-must-pass.ts:14

R-02

Fix the doctor git-hooks check for consumer repos — it’s a bug, not a polish item

critical · fixes F2
value
effort

Doctor is the trust surface — a health check that mis-diagnoses every repo except Cadence’s own, and whose --fix can break a Husky setup, undermines everything else it says.

How: in checkGitHooks, return "not applicable" when no .githooks/ directory exists; never flag a custom hooksPath as wrong (report it as info); make the --fix repair refuse to overwrite an existing non-.githooks value. Add the missing-directory case to the doctor test suite.

doctor/run.ts:138–160 · doctor/fix.ts:95–104

R-03

Give the SUMMARY gate provenance: what ran, what skipped, what "PASS" meant

high · fixes F3
value
effort

The SUMMARY is the artifact people (and future sessions) trust. Recording per-AC evidence class — mention / assertion / executed / ai-verified — turns "PASS" from a claim into a receipt, and makes weak settles visibly weak instead of silently green.

How: extend the summary schema with a gates array (id, outcome, skipped-reason) and per-AC evidence; render both in SUMMARY.md; while in there, render the already-captured deepVerifyMeta token usage so paid verification runs show their cost. All data already exists at settle time — this is plumbing, not new machinery.

settle/summary-writer.ts · types summary schema · gates/deep-verify.ts:40–51

R-04

Agent-grade JSON across the loop — starting with progress --json

high · fixes F4
value
effort

Cadence’s growth story is agents driving the loop. The io-seam already computes structured payloads for every service — the CLI just drops them on the floor.

How: add --json to progress (an option + one branch — the payload exists), then draft new/check/approve, build task, and settle run; convert recommendation --format to --json with the old flag kept as a hidden alias. One release, mostly mechanical.

cli/commands/progress.ts:5–12 · services/io.ts · recommendation.ts:182,260

R-05

Make init --demo print one coherent next step

high · fixes F5
value
effort

It’s the happy path the docs push hardest, and today its most prominent instruction refuses. First impressions don’t get retried.

How: when demoSeeded is true, suppress the generic "Your first loop" block and the draft new agent prompt; print only the demo continuation (approve → done → settle). Also genericize the hardcoded 01-fix-login-timeout slug in the non-demo block to the user’s actual derived phase id.

cli/commands/init.ts:436–471

R-06

Defuse the non-TTY approve trap in the agent path

high · fixes F6
value
effort

The agent persona hits this on precisely the repos Cadence most wants to win — mature ones. The v1.29 interactivity seam did the hard part; the guidance surfaces never caught up.

How: make renderAgentPrompt profile-aware — when the active profile gates approve interactively, the prompt’s step 3 should tell the agent to stop and hand the human a cadence draft approve … command to run themselves (which is the intended control point anyway), and the README first-real-phase block should note the same. The trap becomes the feature: the human approval gate, explained.

agent-prompt/render.ts:32 · README.md:89 · init/plan.ts:18–31

R-07

Finish the "always a next move" promise: three small refusal fixes

high · fixes F10 (part)
value
effort

Cadence’s best UX quality is that refusals guide. Three surfaces break the pattern, and they’re all trivial.

How: (a) BUILD-state progress should emit one runnable command — the first PENDING task id is known (cadence build task T2 --status=DONE); (b) guard draft approve for a missing draft file exactly as spec approve already does; (c) append current position + "run cadence progress" to the settle run loop-position error.

progress.ts:53–55 · draft-approve.ts:35 vs spec-approve.ts:34–35 · settle.ts:147

R-08

Shrink the hand-edit cliff with structured draft editing

high · fixes F7
value
effort

The DRAFT is the product’s central artifact and the only part of the loop the CLI can’t touch. Structured edits kill the typo-in-a-heading failure class and give agents a safe write path that can’t produce unparseable markdown.

How: add cadence draft set-objective "…", draft add-ac --name … --given … --when … --then …, and draft add-task --name … --files … --done AC-N, all round-tripping through the existing parseDraftMd machinery. Hand-editing stays fully supported; this is an additive rail, not a lock-in. Biggest single ergonomic investment on this list — and the one that most compounds with R-04 for agents.

parse/draft-scaffold.ts · parse/draft-md.ts · cli/commands/draft.ts

R-09

Sealed gates: let the production preset make named gates non-bypassable

medium · fixes F8 (part)
value
effort

Today the strictest posture Cadence can express is "bypassable, but logged." Teams adopting it as a real gate — the CI persona — need at least one mode where --force doesn’t work.

How: a gates.sealed: [gate-ids] config list that makes listed gates ignore --force and their --allow-* flag; wire it into the production preset for test-coverage and build-test-must-pass. Bypass logging stays for everything unsealed.

gates/types.ts:144–158 · types config.ts:333–338 · settle.ts:431–433

R-10

MCP parity for the intelligence lifecycle

medium
value
effort

An MCP-only client can add and promote a recommendation but can’t convert it to a phase or milestone propose — the promote tool’s own description points at a command that isn’t a tool. The scout→rec→phase story, a genuine differentiator, dead-ends over MCP.

How: add cadence_recommendation_convert, cadence_milestone_propose, and cadence_recommendation_archive tools (the services exist behind the io-seam); expose SUMMARY.json as a resource alongside the .md template.

mcp/tools.ts:57–355 (15 tools) vs cli/register.ts:34–62 (31 groups) · tools.ts:331

R-11

A docs truth pass + front-door coherence

medium · fixes F9, F10 (part)
value
effort

For a tool whose brand is honesty, a flagship example that misattributes its own refusal and a fact with four published values are outsized credibility leaks at near-zero fix cost.

How: fix the README flow (mark T1–T3 done so the refusal really is coverage, or correct the annotation); reconcile the slash-command count to 12 everywhere — ideally generated from install-commands.ts under the existing doc-sync-gate pattern so it can’t drift again; add activate and explain to the start menu so the interactive front door can reach the remedy its own banner recommends.

README.md:22,87–92 · docs/quickstart.md:507 · docs/claude-code.md:34 · start/menu.ts:26

R-12

Make declared boundaries enforceable — including for subagents

medium · fixes F8 (part)
value
effort

The DRAFT declares files: per task and Boundaries per phase, but edit-time checks only warn, and subagent edits bypass hooks entirely (the documented reason OpenCode was rejected as a host). Making boundaries optionally blocking turns a paper declaration into Cadence’s only real-time guardrail.

How: a boundaryEnforcement: warn | block config (default warn, unchanged); in block mode the pre-tool-edit handler returns a refusal for out-of-boundary writes; extend the subagent-result handler to diff-scan for out-of-boundary changes after the fact and raise a blocking anomaly at settle rather than a counter tick. Scope honestly: post-hoc detection at settle is achievable everywhere; true edit-time blocking only where the host supports it.

hooks/checks/boundary.ts:59–68 · hooks/handlers.ts:50,133–142 · types config.ts:296

05

Suggested sequencing

Three waves, matched to how Cadence already ships — each wave is one or two loop phases. Wave 1 is almost entirely small diffs with outsized trust returns.

WaveContentsWhy this order
1 · quick wins R-02 doctor bug · R-04 progress --json · R-05 demo dead-end · R-06 approve trap · R-07 refusal trio · R-11 docs truth pass All small-effort; every one removes a first-session credibility leak. Shippable as a single "onboarding-honesty" patch release.
2 · the wedge R-01 real defaults · R-03 SUMMARY provenance · R-09 sealed gates Together these make the marketing claim true out of the box: the gate is real by default, the receipt proves it, and production mode can’t be forced past it.
3 · structural R-08 structured draft edits · R-10 MCP parity · R-12 boundary enforcement Larger investments that compound with waves 1–2: agents get a safe write path, MCP gets the full lifecycle, and boundaries get teeth.
06

Method & scope

Conducted 2026-07-01 against main @ 8ed57dc (v1.35.0). Three parallel code audits covered the onboarding surfaces, the day-to-day loop UX, and the capability architecture (gates, verifiers, hosts, MCP, intelligence, config, observability) — every claim carries a file:line reference. In parallel, the CLI was rebuilt from HEAD and exercised hands-on in a throwaway sandbox: init --dry-run, init, the template → approve → done → settle loop (including the comment-only coverage repro), tutorial, doctor --fix, handoff/resume, and the --json matrix. Terminal excerpts in this report are unedited captures from those runs. Not covered: the npm publish pipeline, live Anthropic/local verifier calls, and the Codex host adapter beyond source review.
