## Things that bit this session (so they don't bite again)

1. **DRAFT-read mtime gate trips integration tests** that edit DRAFT.md after `draft approve`. Fix: edit DRAFT before approve, OR pass `--allow-stale-draft` on settle.
2. **`tempRepo` default profile is `auto`** — auto×* doesn't carry the `approve` / `per-task-verify` / `code-review` gates. To exercise those gates in tests, force `config.profile = 'strict'` (or `'standard'`) and edit `.cadence/config.json` directly.
3. **Existing tests broke when `'approve'` gate fired by default under standard×standard**: had to add `--no-approve` to ~5 pre-existing tests (`draft-read-gate.test.ts`, `settle-anomaly.test.ts`, `soft-cap.test.ts`). Next gate phase: watch for similar fallout when strict/standard cells gain a new gate.
4. **Coherence regex `DO NOT edit foo.bar`**: the regex (`packages/core/src/coherence/check.ts:13`) requires `\.(?:\s|$)` after the captured path. `path/to/file.ts.\n` matches; `path/to/file.ts\n` does NOT. Trailing period needed when seeding fixtures.
5. **Windows + spawned git tests are slow** (~3.5s each). Set `{ timeout: 30_000 }` on the describe block, or first test of the file will time out at the default 5000ms.
6. **`--no-approve` is a commander auto-flag**: declaring `.option('--no-approve', ...)` exposes `opts.approve` (boolean, default `true`). Check `opts.approve !== false` to detect bypass — NOT `opts.noApprove`.
7. **`opts.allowPerTaskFailure` capitalization** — commander camelCases `--allow-per-task-failure`. Easy to mistype `opts.allowPerTaskFailure` vs `opts.allow_per_task_failure`.
8. **Pre-existing lint errors persist** in `packages/core/src/notify/loop-violation.ts:5` (type-only import) and `packages/core/src/verify/coverage.ts:89` (`import()` type annotation). Out of scope for v0.5.0 — see backlog.
