  mid-session (harmless — it's a transient daemon-connection marker, not

  files came back).
- `gh pr merge --delete-branch` fails to delete the *local* branch whenever
  that branch is checked out in a worktree (which it always was this
  session, five times in a row) — it still errors with exit 1, but the
  *remote* merge and remote branch deletion both succeed regardless. Always
  re-check via `gh pr view <n> --json state,mergedAt` before assuming a
  non-zero exit means the merge failed; then `git worktree remove --force`
  + `git branch -D` + `git push origin --delete <branch>` to finish local
  cleanup.
- Recommendation-ledger edits made directly on the primary checkout (before
  branching into a worktree for the actual PR) become stale duplicates once
  the worktree's version merges — `git restore` them rather than trying to
  reconcile, since only `archivedAt`/`updatedAt` timestamps differ from a
  second run of the same `cadence recommendation promote` command.
