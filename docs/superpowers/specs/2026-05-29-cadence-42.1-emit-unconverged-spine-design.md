# CADENCE Phase 42.1 — `emitUnconverged` notify spine — Design + Plan

> Architecture review candidate #4. Three convergence emitters under
> `packages/core/src/notify/` (`plan-review.ts`, `spec-review.ts`,
> `code-review.ts` — ~48 LoC each) share an identical try / notify /
> stderr-degrade / ts-stamp spine; ~70% is duplication. Extract
> `emitUnconverged(notifier, kind, payload)`; the three sites supply only the
> payload. **Pure bit-identical refactor** — no operator-approved behavior
> change (contrast 41.1). Decoupled by design: 39.4/39.7 consume convergence
> emission through the `ctx.emit.*Unconverged` ports, so this is an internal
> swap *behind* the ports — the extracted gates need no re-touch, and 42.1 is
> order-independent w.r.t. 39.x.

## Why this IS bit-identical

The three `*Unconverged` emitters are byte-for-byte the same except for three
varying tokens. The transport tail (try → `notifier.notify([event])` → catch →
one `process.stderr.write` warning, never throws) and the `ts:
new Date().toISOString()` stamp are identical across all three. What differs:

| Token | plan-review | spec-review | code-review |
|---|---|---|---|
| anomaly `type` | `plan-review-unconverged` | `spec-review-unconverged` | `code-review-unconverged` |
| entity key in `context` | `draftId` | `specId` | `draftId` |
| message prefix word | `plan-review` | `spec-review` | `code-review` |

Everything else — `severity: 'error'`, the message body
(`… did not converge for <id> after <a>/<max> attempts (<n> finding(s))`), and
the `context` field order (`<entityKey>, attempts, maxAttempts, findings,
provider, …model?, …bypassed?`) — is identical. The message prefix word **is**
the `kind` string verbatim, so a single template reproduces all three messages
exactly.

`emitCodeReviewHigh` in `code-review.ts` is a **different** shape (multi-event,
per-finding, `anomaly-notify`-gated at the caller). It is NOT part of this
extraction and stays untouched.

## Design

New `packages/core/src/notify/emit-unconverged.ts`:

```ts
export type UnconvergedKind = 'plan-review' | 'spec-review' | 'code-review';

interface UnconvergedPayload {
  entityId: string;          // draftId or specId
  attempts: number;
  maxAttempts: number;
  findings: number;
  provider: string;
  model?: string;
  bypassed?: boolean;
}
```

A `KIND_META` table maps each `kind` → `{ type, entityKey }`. The spine builds
the event (message via template, `context` with the computed `[entityKey]` key
first, optional `model`/`bypassed` via the same conditional-spread the originals
use, then `ts: new Date().toISOString()`), then runs the shared transport tail.

The three emitters keep their **public signatures unchanged** (`ctx.draftId` /
`ctx.specId`, etc.) so the `ctx.emit.*Unconverged` ports and their gate callers
need no change. Each shrinks to a destructure + single `emitUnconverged(...)`
call (≤ 8 LoC). `model`/`bypassed` reach the spine as present-or-absent (callers
already conditional-spread them — never explicit `undefined` — so the
destructure+spread is safe under `exactOptionalPropertyTypes`).

## Files

- `packages/core/src/notify/emit-unconverged.ts` (new) — the spine.
- `packages/core/src/notify/plan-review.ts` — shrink to payload builder.
- `packages/core/src/notify/spec-review.ts` — shrink to payload builder.
- `packages/core/src/notify/code-review.ts` — shrink `emitCodeReviewUnconverged`
  only; `emitCodeReviewHigh` untouched.
- `packages/core/tests/notify/emit-unconverged.test.ts` (new) — spine tested
  once: ts-stamp, single-event dispatch, per-kind type/message/context shape
  (bit-identical proof for all three), and stderr-degrade on transport throw.

## ACs

1. `emitUnconverged` is the single home for the convergence transport contract
   (try / notify / degrade / ts-stamp).
2. Each of the three emitters becomes ≤ 8 LoC (destructure + call).
3. Stderr-degrade behavior identical across all three kinds, centrally tested.
4. Adding a fourth convergence emitter costs ≤ 4 LoC (one `KIND_META` row + a
   thin builder).
5. Notifier injection seam unchanged — the three public signatures and the
   `ctx.emit.*Unconverged` ports are byte-identical to callers; existing notify
   + draft/settle convergence E2E suites pass unchanged.
