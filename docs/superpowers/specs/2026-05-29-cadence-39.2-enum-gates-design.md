# CADENCE Phase 39.2 — Total enum coverage: `draft-read` + `structural-verifier` + `build-test-must-pass` — Design

> Second v1.3.0 "Architecture deepening" phase. Builds on the 39.1 gate
> contract (`SettleContext` / `GateResult` / `GateImpl`,
> `docs/superpowers/specs/2026-05-29-cadence-gate-contract-39.1-design.md`).
> Brings the `Gate` enum to **total registry coverage**: every member except the
> `anomaly-notify` finalizer exception becomes a discrete `GateImpl`.
>
> **Anchor change (see Decision Log).** Unlike 39.1, this phase is *not*
> uniformly bit-identical. `draft-read` is a verbatim extraction (transcript-
> anchored). `structural-verifier` and `build-test-must-pass` have **no in-engine
> enforcement today** — they are declared in `ALWAYS_FIRE` (`gates/engine.ts`)
> and documented in `DESIGN.md §4.1` / `docs/concepts.md` but never checked. This
> phase **wires them for real**, consciously trading the v1.3 bit-identical
> anchor to satisfy the older v1.0 anchor: *"Every gate in DESIGN.md §4.1 fires.
> The matrix is no longer decorative."* (operator decision, 2026-05-29).

## Summary

After 39.1, `settle.ts` routes two gates (`test-coverage`, `deep-verify`)
through the contract; the rest are still inline or absent. 39.2 lifts the last
cheap enum gate that *has* an inline block — `draft-read` (`settle.ts:164–187`)
— into `gates/draft-read.ts`, and **implements** the two `ALWAYS_FIRE` gates
that were decorative:

- **`structural-verifier`** — refuses settle while any task is non-terminal
  (`PENDING` / `IN_PROGRESS`). Terminal = `DONE` / `DONE_WITH_CONCERNS` /
  `NEEDS_CONTEXT` / `BLOCKED`. Pure policy over `ctx.progress.tasks`; closest
  analog is `coverage.ts`. New refusal behavior.
- **`build-test-must-pass`** — runs the configured test command via an injected
  **runner port** and refuses on a non-zero exit. New refusal behavior, and a
  new `verification.testCommand` config field + `RunnerPort` on `SettleContext`.

Net result: the registry is **total** over the 13-member `Gate` enum — 12
discrete `GateImpl`s once 39.3–39.7 land, plus the single `anomaly-notify`
finalizer exception (confirmed structurally in 39.1).

## Product Boundary

**Behavior changes — intentionally.** This is the first v1.3 phase that alters
user-visible `cadence settle run` behavior, by operator decision:

- `draft-read`: byte-identical (verbatim extraction; transcript-anchored, as
  39.1).
- `structural-verifier`: settle now **refuses** when a task is `PENDING` or
  `IN_PROGRESS`. Bypass: `--allow-open-tasks` (per-invocation) or `--force`.
- `build-test-must-pass`: when `verification.testCommand` is configured, settle
  now **runs it and refuses** on failure. Bypass: `--allow-failing-build` or
  `--force`. When `testCommand` is unset, the gate passes **silently** (cannot
  enforce what is not configured; no stderr, so existing green settles stay
  bit-identical — AC-7).

No other gate, sidecar, SUMMARY field, or notification changes shape.

## Implementation Pattern

### `gates/types.ts` additions

```ts
/** Result of the build-test-must-pass runner. `ran:false` ⇒ no testCommand
 *  configured (gate passes with a note). */
export interface TestRunResult {
  readonly ran: boolean;
  readonly ok: boolean;          // meaningful only when ran === true
  readonly exitCode?: number;
  readonly command?: string;
}

/** Subprocess collaborator for build-test-must-pass. Injected so gate tests
 *  never spawn a real process. settle builds it from config.verification.testCommand. */
export interface RunnerPort {
  test(): Promise<TestRunResult>;
}

export interface SettleOpts {
  readonly force?: boolean;
  readonly auto?: boolean;
  readonly deep?: boolean;
  readonly allowMissingCoverage?: boolean;
  readonly allowVerifierFailure?: boolean;
  readonly allowStaleDraft?: boolean;     // draft-read (was read off raw opts)
  readonly allowOpenTasks?: boolean;      // structural-verifier (new)
  readonly allowFailingBuild?: boolean;   // build-test-must-pass (new)
}

export interface SettleContext {
  // …39.1 fields unchanged…
  /** Memoized DRAFT.md mtime in ms; null when no DRAFT / stat fails. */
  draftMtimeMs(): Promise<number | null>;
  readonly runner: RunnerPort;
}
```

`GateResult` / `GateImpl` / `mergeInto` / the `SettleAccumulator` shape are
**untouched** — exactly the "core contract stays frozen, ctx grows" success
criterion 39.1 set. Neither new gate contributes `summaryPatch` or `flags`
(they are pure pass/refuse), so the accumulator is unchanged too.

### `gates/draft-read.ts` (verbatim extraction)

Moves `settle.ts:164–187` behind `GateImpl`. Reads `ctx.state.draftReadAt` and
`ctx.draftMtimeMs()`; refuses (same message, via `ctx.io.err`) when
`mtimeMs > baselineMs` and not `ctx.opts.allowStaleDraft`; emits the same
"--allow-stale-draft set" note on bypass. `null` draftReadAt or `null` mtime ⇒
pass (matches today's `state.draftReadAt !== null` guard). Transcript-anchored
bit-identical (AC-7).

### `gates/structural-verifier.ts` (new pure policy)

```ts
const TERMINAL = new Set(['DONE', 'DONE_WITH_CONCERNS', 'NEEDS_CONTEXT', 'BLOCKED']);
export const runStructuralVerifierGate: GateImpl = async (ctx) => {
  const open = Object.entries(ctx.progress.tasks)
    .filter(([, t]) => !TERMINAL.has(t.status));
  if (open.length > 0 && !ctx.opts.allowOpenTasks && !ctx.opts.force) {
    for (const [id, t] of open) {
      ctx.io.err(`structural-verifier: task ${id} is ${t.status} (not terminal)\n`);
    }
    ctx.io.err('settle run refused: all tasks must be terminal (DONE / DONE_WITH_CONCERNS / NEEDS_CONTEXT / BLOCKED). Pass --allow-open-tasks to bypass, or --force to settle anyway.\n');
    return { outcome: 'refuse' };
  }
  return { outcome: 'pass' };
};
```

Pure; no I/O; tested by constructing a `ctx` with a fixture `progress` + capture
`io`. No port needed.

### `gates/build-test-must-pass.ts` (new, runner-port-backed)

```ts
export const runBuildTestGate: GateImpl = async (ctx) => {
  const res = await ctx.runner.test();
  if (!res.ran) {
    return { outcome: 'pass' };   // no testCommand → pass silently (bit-identical)
  }
  if (!res.ok && !ctx.opts.allowFailingBuild && !ctx.opts.force) {
    ctx.io.err(`build-test-must-pass: ${res.command} exited ${res.exitCode}\n`);
    ctx.io.err('settle run refused: the test suite must pass before settle. Pass --allow-failing-build to bypass, or --force to settle anyway.\n');
    return { outcome: 'refuse' };
  }
  return { outcome: 'pass' };
};
```

`settle.ts` builds the runner: when `config.verification.testCommand` is set,
`test()` spawns it (`spawn`, inherit-free, capture exit code) and returns
`{ ran:true, ok: code===0, exitCode, command }`; when unset, returns
`{ ran:false, ok:true }`. Gate tests inject a stub runner — **no real spawn**.

### Execution order (recorded for the 44.1 `GATE_ORDER`)

The two new `ALWAYS_FIRE` gates need a defined position. Chosen sequence — cheap
structural check first, build-test before any expensive AC/verifier work:

```
softCap (inline pre-check, unchanged)
→ draft-read        (was first inline gate; relative order preserved)
→ structural-verifier   (new; cheap, pure)
→ build-test-must-pass  (new; before coverage/interactive/deep)
→ test-coverage     (39.1)
→ interactive / deep-verify / code-review / security-audit (existing)
→ finalizers (AC-merge, anomaly-notify, skill-audit, SUMMARY, state)
```

`draft-read` keeps its current relative position (after `softCap`, before
`coverage`) ⇒ bit-identical for that gate. The two new gates slot between
`draft-read` and `coverage`. 39.2 hand-wires this order in the unrolled call
sequence and **records it** so 44.1's `GATE_ORDER` constant encodes it.

> Note: `draft-read` moves a few lines *down* in `settle.ts` (it must run after
> the `SettleContext` is built, since it now reads `ctx`). `softCap` stays an
> inline pre-check above the ctx build, preserving softCap→draft-read order.

## Acceptance Criteria

- **AC-1** `runDraftReadGate(ctx)` is the single home for the draft-read mtime
  gate; `settle.ts` no longer stats DRAFT.md inline for it. Output bit-identical.
- **AC-2** `runStructuralVerifierGate(ctx)` refuses iff a task status ∉
  {DONE, DONE_WITH_CONCERNS, NEEDS_CONTEXT, BLOCKED} and neither `--allow-open-tasks`
  nor `--force` is set; passes otherwise.
- **AC-3** `runBuildTestGate(ctx)` passes (silently) when no `testCommand`;
  refuses on non-zero runner exit unless `--allow-failing-build`/`--force`;
  passes on zero exit.
- **AC-4** All three conform to `GateImpl` with no casts
  (`const _c: GateImpl = runStructuralVerifierGate` compiles for each).
- **AC-5** Each gate writes stderr only through `ctx.io.err`; captures observe
  exact messages. The `build-test` runner is reached only via `ctx.runner`,
  never a direct `spawn` import inside the gate.
- **AC-6** Gate tests reach every branch (pass / refuse / bypass-flag / `--force`;
  for build-test additionally: `ran:false`, `ok:true`, `ok:false`) without
  standing up the CLI command stack or spawning a real subprocess.
- **AC-7** `cadence settle run` is bit-identical for the `draft-read` path
  (snapshot transcript) and for runs where the two new gates pass
  (all tasks terminal; no `testCommand`) — i.e. **no regression for existing
  green settles**.
- **AC-8** New refusals are behaviorally tested at the settle level (ephemeral
  repo): an open task refuses; a configured failing command refuses; the
  documented bypass flags clear each.
- **AC-9** The registry is total: a compile-time exhaustiveness check (or test)
  asserts every `Gate` enum member except `anomaly-notify` now has a `GateImpl`
  module — i.e. only `coherence-check`'s 39.x successors remain (tracked for
  39.3–39.7), with no enum member silently unimplemented.

## Decision Log

- **Wire structural-verifier + build-test-must-pass for real** (operator,
  2026-05-29). They were `ALWAYS_FIRE` enum members with zero enforcement —
  decorative despite the v1.0 "matrix no longer decorative" anchor. Options
  weighed: (A) wire both [chosen]; (B) extract `draft-read` only, document the
  two as external-enforcement exceptions like `anomaly-notify`; (C) split —
  wire structural-verifier (in-engine), leave build-test to pre-push/CI.
  Operator chose A to make the matrix load-bearing. **Consequence: the v1.3
  bit-identical anchor is amended** — it holds for `draft-read` and for existing
  green settles, but the two new gates add refusal paths, tested behaviorally
  (AC-8), not by golden transcript. Record this amendment in `.cadence/ROADMAP.md`.
- **`build-test-must-pass` is config-gated, not unconditional.** With no
  `verification.testCommand`, the gate passes **silently** (no stderr — a note on
  every settle would break bit-identical green settles, AC-7) rather than
  guessing a command. Rationale: an unconditional `pnpm test` would break every consumer
  whose suite isn't `pnpm test`, and would duplicate this repo's own pre-push
  hook. "Always-fire" means "always *evaluated*"; enforcement is gated on config.
  Rejected: hard-coded `pnpm test` (platform/consumer coupling).
- **Runner is an injected port, not a `spawn` in the gate.** Mirrors 39.1's
  port philosophy (gates never import a factory/subprocess directly). Keeps gate
  tests spawn-free and lets a future phase consolidate process execution.
  Rejected: `child_process.spawn` inside the gate (untestable without a real run).
- **`DONE_WITH_CONCERNS` is terminal.** `docs/concepts.md:176` lists only
  DONE/BLOCKED/NEEDS_CONTEXT, but `TaskStatusZ` has six members. A
  done-with-concerns task is settled, not open. Classified terminal; concepts.md
  to be corrected. Non-terminal = {PENDING, IN_PROGRESS} only.
- **`draftMtimeMs` as a memoized thunk, not a `draftPath` field.** Keeps the fs
  read out of the gate (testable via stub), consistent with `coverage()`.
  Rejected: exposing `draftPath` and stat-ing inside the gate (re-introduces the
  disk dependency 39.1 designed out).
- **New gates contribute no `summaryPatch`/`flags`.** Both are pure pass/refuse;
  the `SettleAccumulator` is unchanged. Confirms the contract handles the
  simplest gate shape with zero ceremony.
