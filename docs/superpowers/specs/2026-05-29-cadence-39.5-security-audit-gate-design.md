# CADENCE Phase 39.5 — Lift the security-audit gate into `gates/security-audit.ts` — Design + Plan

> Fifth v1.3.0 phase. Extracts the Phase 25.2 security-audit gate from
> `settle.ts` (`:413–471`) into `gates/security-audit.ts` against the 39.1
> contract. **Bit-identical.** The simplest expensive-gate extraction — no
> convergence sidecar, no emit (unlike 39.4): just the verifier port + the
> reused `ctx.diff()`.

## Summary

The block runs the OWASP-aware security auditor over the touched-file git diff;
CRITICAL findings refuse settle unless `--force` / `--allow-security-audit-failure`;
all findings land on `SUMMARY.securityAudit`. Extraction:

- New `gates/security-audit.ts` exposing `runSecurityAuditGate: GateImpl`,
  returning `{ outcome, summaryPatch: { securityAudit } }`. `SettleAccumulator.securityAudit`
  already exists (39.1).
- New **`verifiers.securityAudit`** port — `{ verify(input): Promise<SecurityAuditResult> }`,
  lazily `selectSecurityAuditVerifier(config)` (mirrors `deep` / `codeReview`).
- **`ctx.diff()`** reused from 39.4 (same memoized git diff; no new collaborator).
- `SettleOpts` gains `allowSecurityAuditFailure`.

No emit port member and no sidecar: the block neither notifies nor persists
state. The `Finding` type here is `@cadence/types` `Finding` (with `critical`) —
same as `SecurityAuditResult.findings` and `SettleAccumulator.securityAudit`, so
no disambiguation is needed (contrast 39.4's code-review `Finding`).

## Bit-identical notes

## Decision Log

- **Reuse `ctx.diff()`; no new diff collaborator.** 39.4 introduced the memoized
  collector for exactly this second consumer; one git invocation now serves both
  gates per settle (the inline code ran `collectDiffForCodeReview` twice).
- **No emit / no sidecar port.** The block does neither; adding them would be
  dead surface. Security-audit is a single-shot refuse gate, not a convergence loop.
- **`@cadence/types` `Finding` throughout.** `SecurityAuditResult.findings` and
  `SettleAccumulator.securityAudit` already agree on it — no `CodeReviewFinding`-style
  disambiguation needed.
