# CADENCE Phase 40.1 — Verifier-factory consolidation — Design + Plan

> Architecture review candidate #1. Six factory files under
> `packages/core/src/verify/` (`factory`, `code-review-factory`,
> `plan-review-factory`, `spec-review-factory`, `per-task-factory`,
> `security-audit-factory` — 355 LoC) are byte-for-byte the same selection
> algorithm with a `mock | anthropic | local` switch and identical fallback
> warnings. Collapse into one generic `createVerifierFactory` + six thin
> bindings. **Bit-identical** behavior — pure refactor.

## What's identical (verified)

All six `select…Verifier(config, opts)` functions differ only in:
1. **config slice** read for `{ provider, model }` — `verifier`, `codeReview`,
   `planReview`, `specReview`, `perTaskVerifier`, `securityAudit`.
2. **warn label** prefix — `verifier`, `code-review`, `plan-review`,
   `spec-review`, `per-task-verify`, `security-audit`.
3. the three **verifier classes** (`Mock`/`Anthropic`/`Local`) constructed.

Everything else is the same: `provider = override ?? slice.provider ?? 'mock'`;
`anthropic` needs `ANTHROPIC_API_KEY` (else warn + mock); `local` needs
`CADENCE_LOCAL_BASE_URL` + a model (`slice.model ?? CADENCE_LOCAL_MODEL`, else
warn + mock); `Anthropic` ctor gets `{ apiKey, ...(model ? { model } : {}) }`;
`Local` ctor gets `{ baseURL, model }`. The two warn strings are identical up to
the label. The `Anthropic*VerifierOptions` are all `{ apiKey?, model?, … }` and
`Local*VerifierOptions` all `{ baseURL, model, … }`, so a uniform
`{ apiKey, model? }` / `{ baseURL, model }` payload is assignable to every ctor.

## Design

New `verify/verifier-factory.ts`:

```ts
export type VerifierProvider = 'mock' | 'anthropic' | 'local';
export interface VerifierSelectOptions {
  override?: VerifierProvider;
  env?: NodeJS.ProcessEnv;
  warn?: (message: string) => void;
}
export interface VerifierFactorySpec<C, V> {
  label: string;
  read(config: C | null): { provider?: VerifierProvider; model?: string } | undefined;
  mock(): V;
  anthropic(opts: { apiKey: string; model?: string }): V;
  local(opts: { baseURL: string; model: string }): V;
}
export function createVerifierFactory<C, V>(
  spec: VerifierFactorySpec<C, V>,
): (config: C | null, opts?: VerifierSelectOptions) => V;
```

The returned function reproduces the shared algorithm exactly, interpolating
`spec.label` into the two warn strings.

Each of the six factory files becomes a thin binding:

```ts
export type SelectCodeReviewVerifierOptions = VerifierSelectOptions; // back-compat alias
export const selectCodeReviewVerifier = createVerifierFactory<
  Pick<CadenceConfig, 'codeReview'>,
  CodeReviewVerifier
>({
  label: 'code-review',
  read: (c) => c?.codeReview,
  mock: () => new MockCodeReviewVerifier(),
  anthropic: (o) => new AnthropicCodeReviewVerifier(o),
  local: (o) => new LocalCodeReviewVerifier(o),
});
```

### API preservation

- Same export names + call signatures. The factory is **generic over `C`** (the
  `Pick<CadenceConfig, K>` slice) so each binding keeps its exact
  `(config: Pick<CadenceConfig, K> | null, opts?) => V` type — `factory.test.ts`
  passes a `{ verifier: … }` Pick literal *without* `as any`, so the param type
  must stay a Pick, not widen to `CadenceConfig`.
- `selectX` change from `function` to `const` arrow — call sites and
  `import { selectX }` are unaffected.
- `Select*VerifierOptions` kept as re-exported aliases of `VerifierSelectOptions`
  (no external importers found, but `@cadence/core` is published — zero API
  regression).
- A `read` accessor (`(c) => c?.codeReview`) is used instead of a `keyof`-based
  index, so no unsafe indexing and `noUncheckedIndexedAccess` stays satisfied.

## Files

- NEW `verify/verifier-factory.ts` — generic + shared types (~70 LoC).
- MOD the six `verify/*-factory.ts` — thin bindings (~18 LoC each).
- NEW `tests/verify/verifier-factory.test.ts` — the generic's algorithm
  (provider resolution, both fallbacks + warn strings, env seams) once, against
  a trivial fake verifier family.
- Tests untouched otherwise: `factory.test.ts` + `local-factories.test.ts`
  exercise the six bindings and must pass unchanged (bit-identical proof).

## Acceptance Criteria

- **AC-1** One `createVerifierFactory<C, V>`; the six factories are thin bindings
  with no duplicated selection logic.
- **AC-2** Selection algorithm + both warn strings byte-identical — existing
  `factory.test.ts` and `local-factories.test.ts` pass unchanged.
- **AC-3** Public API preserved: `selectX` names, `Pick`-based signatures, and
  `Select*VerifierOptions` type names all still exported.
- **AC-4** Net LoC down (~355 → ~180).

## Decision Log

- **Generic over the config slice `C`.** Preserves each binding's `Pick<…>`
  param so the untyped Pick literal in `factory.test.ts` keeps compiling; widening
  to `CadenceConfig` would break it.
- **`read` accessor over `keyof` indexing.** Type-safe extraction of the
  `{ provider, model }` slice; avoids `noUncheckedIndexedAccess` friction and
  keeps the six config keys' differing names explicit at the binding.
- **Keep `Select*Options` as aliases.** `@cadence/core` publishes these; aliasing
  to `VerifierSelectOptions` is a one-liner that prevents any downstream break.
- **Pure refactor, no behavior change.** Unlike 39.2, nothing is newly wired;
  the warn strings and fallbacks are reproduced verbatim via `spec.label`.
