# CADENCE Phase 39.6 — Lift the skill-audit check into `checks/skill-audit.ts` — Design + Plan

> Sixth v1.3.0 phase. Extracts the Phase 34.1 required-skill enforcement from
> `settle.ts` (`:537–591`) into a NEW **`packages/core/src/checks/`** namespace.
> **Bit-identical.** First inhabitant of `checks/` — `skill-audit` is **not** a
> `Gate` enum member (declaring required skills IS the opt-in, so it is an
> anomaly check, not a profile×tier gate). It reuses `SettleContext` + a
> `GateResult`-style outcome for a uniform return, but is **dispatched
> explicitly** by settle and stays OUTSIDE the Phase 44.1 registry.

## Summary

The block computes the effective required-skill set (config ∪ DRAFT frontmatter,
deduped), then enforces it: telemetry-off yields an *unenforceable* warn anomaly;
a real shortfall refuses settle unless `--allow-skill-audit-miss`; the
`skill-audit-miss` anomaly is emitted **unconditionally** (NOT under the
`anomaly-notify` guard — a strict phase that fails the requirement must still
leave an audit trail). On every non-refuse path `state.skillAudit.required` is
set to the effective union so SUMMARY stays truthful. Extraction:

- New `checks/skill-audit.ts` exposing `runSkillAuditCheck(ctx): Promise<SkillAuditResult>`,
  where `SkillAuditResult = { outcome: 'pass' | 'refuse'; effectiveRequired: string[] }`.
  It is **not** a `GateImpl` (it returns the effective set settle must record on
  `state`, which is outside the `GateResult`/`summaryPatch` contract) and is
  never placed in a `Record<Gate, GateImpl>`.
- New **`EmitPort.skillAuditMiss`** port — wraps `emitSkillAuditMiss` over the
  selected notifier. The unconditional-emission divergence stays a property of
  the check, not the port.
- `SettleOpts` gains `allowSkillAuditMiss` (the CLI flag already exists at the
  command surface; this just exposes it to the check).
- `settle.ts` replaces the inline block with explicit dispatch: `refuse →
  process.exitCode = 1; return`; otherwise `state.skillAudit.required =
  res.effectiveRequired`.

`missingSkills` moves into the check; `emitSkillAuditMiss` stays imported in
`settle.ts` (now used only by the emit-port adapter). `selectNotifier` stays —
still used by the `anomaly-notify` block and the code-review emit adapters.

## Why `checks/`, not `gates/`

`skill-audit` is absent from the `Gate` enum (verified: no `gates/engine.ts`
matrix cell, no `registry-coverage.test.ts` row). It is the same class of thing
as `boundary` (43.1) — a cross-cutting anomaly check, not a profile×tier gate.
Per ROADMAP §"Non-gates move out of `gates/`", both relocate to `checks/` and
stay outside the 44.1 registry, keeping `gates/` coherent: one decision engine +
the discrete enum-gate impls. `checks/` may depend on `gates/types.ts`
(`SettleContext`) — the forbidden direction is `gates/engine.ts`/registry →
`checks/`, which this preserves.

## Acceptance Criteria

- **AC-1** The check is one module under `checks/`; `settle.ts` no longer runs
  the enforcement inline.
- **AC-2** DRAFT `requiredSkills` ∪ `config.skillAudit.required` union semantics
  (dedup, order) preserved.
- **AC-3** `--allow-skill-audit-miss` bypass preserved (warn + `bypassed:true` +
  proceed stderr + exit 0).
- **AC-4** `state.skillAudit.invoked` remains the source of truth; satisfaction
  uses `missingSkills` (suffix-tolerant) unchanged.
- **AC-5** Behavior bit-identical: stderr, exit codes, anomaly payloads,
  `SUMMARY.skillAudit.required` — existing `settle-skill-audit` E2E passes unchanged.
- **AC-6** `checks/` is not referenced by `gates/engine.ts` or the registry —
  dispatched explicitly from settle; the notifier is reached only via `ctx.emit`.

## Decision Log

- **Return `effectiveRequired`, don't mutate `state` in the check.** The set is
  recorded on `state.skillAudit.required` (feeds both `state` and SUMMARY), which
  is outside the `GateResult`/`summaryPatch` contract. Returning it keeps the
  check side-effect-light and leaves the `state` write owned by the settle
  adapter (mirrors how gates return patches rather than touching `state`). This
  is why the check is intentionally NOT a `GateImpl`.
- **New `emit.skillAuditMiss` port over a raw notifier import.** Honors the
  39.1 gate-collaborator policy (reach the notifier only through `ctx`), even
  though this is a check — keeps `checks/` testable with an emit spy and consistent
  with the gates. The unconditional-emission rule stays the check's property.
- **No registry-coverage change.** `skill-audit` is not a `Gate` enum member, so
  the 13-gate exhaustiveness test is untouched. Registry coverage stays 8/13.
- **First `checks/` inhabitant.** Establishes the namespace 43.1 (`boundary`)
  later joins; no engine/registry wiring, dispatched explicitly.
