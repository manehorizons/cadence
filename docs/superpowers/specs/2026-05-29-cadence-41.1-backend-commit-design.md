# CADENCE Phase 41.1 — Backend `commit(state)` seam — Design + Plan

> Architecture review candidate #3. The `StateBackend` interface is too narrow:
> callers pair `backend.writeState(state)` with a manual `renderStateMd(state)` +
> `atomicWriteText(STATE.md, …)`. Forgetting the second step → stale `STATE.md`.
> Add `commit(state)` that writes BOTH artefacts and demote `writeState` to a
> private primitive, so no caller can omit the STATE.md write. **Operator-
> approved behavior change** (kills the stale-STATE.md class — AC-5).

## Why this is not a pure bit-identical refactor

`renderStateMd` renders `session.subagentSpawns`, `skillAudit.invoked`, and
`activeTask` (id/status) — so four sites that today write `state.json` ONLY
currently leave STATE.md stale until the next command regenerates it:

| Site | state mutation | STATE.md today | after commit() |
|---|---|---|---|
| `build/record.ts` (`build task`) | sets `activeTask` | stale | shows recorded task |
| `handlers.ts` `handleSubagentResult` | `subagentSpawns += 1` | stale | counter fresh |
| `handlers.ts` `handleSkillInvoke` | appends `skillAudit.invoked` | stale | list fresh |
| `handlers.ts` `handlePostToolEdit` | `activeTask.touchedFiles` | n/a (not rendered) | identical bytes, per-edit write |

The operator chose **commit() everywhere + demote `writeState`** (over keeping a
state-only path for the hot-path hooks): one write path, STATE.md never stale.
The post-edit per-edit STATE.md write is a tiny derived file with identical
content (touchedFiles isn't rendered), so its only cost is an extra atomic write.

The two-step sites (`settle`, `draft`, `draft-new`, `spec`×2,
`handlers.handleUserPrompt`, `init`) are byte-identical under commit().

## Design

`state/backend.ts`:
- Add `commit(state: CadenceState): Promise<void>` to `StateBackend`.
- **Remove** `writeState` from the interface (AC-3).

`state/simple.ts` (the only implementer):
```ts
async commit(state: CadenceState): Promise<void> {
  await this.writeState(state); // state.json (validated, atomic)
  await atomicWriteText(
    join(await this.resolveStateDir(), 'STATE.md'),
    renderStateMd(state),
  );
}
private async writeState(state: CadenceState): Promise<void> { /* unchanged */ }
```
`writeState` becomes `private` — `simple.ts` is inside `state/`, so it may import
`renderStateMd` (AC-2 forbids that only *outside* `state/`). All STATE.md paths
resolve to `<cwd>/.cadence/STATE.md` today; `commit()` uses `resolveStateDir()`,
identical for every call site (verified: CLI backends are `new
SimpleStateBackend(cwd)`; `init`'s `cadenceDir === join(cwd, '.cadence')`).

## Call-site conversions (one method, every site)

- `settle.ts`, `draft.ts`, `draft-new.ts`, `spec.ts`×2 — drop the
  `renderStateMd` + STATE.md `atomicWriteText` lines; `writeState` → `commit`;
  drop the now-unused `renderStateMd` import.
- `hooks/handlers.ts` — `handleUserPrompt` two-step → `commit`; the three
  state-only hooks `writeState` → `commit`; drop `renderStateMd` +
  `atomicWriteText` imports (no longer used; `join` stays for draftPath).
- `build/record.ts` — `writeState` → `commit` (now refreshes STATE.md).
- `init.ts` — replace the direct `atomicWriteJSON(state.json)` +
  `writeFile(STATE.md)` pair with `new SimpleStateBackend(cwd).commit(state)`;
  drop the `renderStateMd` import (`atomicWriteJSON` stays for `config.json`).

After this, **no file outside `state/` imports `renderStateMd`** (AC-2) and
**no caller can reach `writeState`** (AC-3/AC-5).

## Files

- MOD `state/backend.ts` — interface: `+commit`, `-writeState`.
- MOD `state/simple.ts` — implement `commit`; `writeState` → private; import
  `atomicWriteText` + `renderStateMd`.
- MOD `cli/commands/{settle,draft,draft-new,spec,init}.ts`, `hooks/handlers.ts`,
  `build/record.ts` — swap to `commit`.
- MOD `tests/state/simple.test.ts` — the lone `writeState` round-trip → `commit`.
- NEW `tests/state/commit.test.ts` — `commit` writes both artefacts; STATE.md
  reflects the committed state; both land atomically.

## Plan (TDD)

1. **simple.ts + commit.test.ts (red→green):** add `commit`, make `writeState`
   private; test both artefacts written + STATE.md content matches `renderStateMd`.
2. **backend.ts:** `+commit`, `-writeState` from the interface; fix `simple.test.ts`.
3. **Convert the seven call-site files** to `commit`; run each owner's suite
   (settle/draft/spec/build/hook + init) after conversion.
4. **Full gate** `pnpm turbo run lint typecheck test build`. The build-task and
   hook suites are the proof for the intended STATE.md-freshness change; all
   other suites stay green unchanged.

## Acceptance Criteria

- **AC-1** `commit(state)` writes `state.json` + `STATE.md` together.
- **AC-2** No caller outside `state/` imports `renderStateMd`.
- **AC-3** `writeState` is gone from the public `StateBackend` interface
  (private on `SimpleStateBackend`).
- **AC-4** A new state-derived artefact = one method change (`commit`).
- **AC-5** No two-step path remains for any caller to omit — stale-STATE.md class
  eliminated (build task + subagent/skill hooks now refresh STATE.md).

## Decision Log

- **commit() everywhere, `writeState` private (operator-approved).** Single
  write path > preserving a state-only fast path; the per-edit STATE.md write is
  a tiny identical-content derived file.
- **`writeState` stays as a private primitive** (not inlined into `commit`) so
  the validated atomic `state.json` write has one home; `commit` composes it with
  the STATE.md render.
- **`init` routes through a throwaway `SimpleStateBackend`** rather than a bespoke
  write, so even bootstrap can't drift from the one write path (and drops its
  `renderStateMd` import, satisfying AC-2).
- **Behavior change is conscious and scoped** (like 39.2's wiring): only the four
  previously-stale sites change observably; recorded here and in the commit.
