## Why this IS bit-identical (and the three subtleties)

Both sites compute the same allow-set (`draft.tasks.flatMap(t => t.files)`) and
emit one `warn` `files-outside-boundary` event per file not in it, with the
identical message `<file> touched but not declared in any task's files:`. The
shared rule is "a touched file not in the union of task `files:` is an
outsider." But the two call sites differ in three preserved ways — so the
extracted function is parameterized, never opinionated:

| Aspect | Hook (`handlePreToolEdit`) | Settle (`collectAnomalies`) |
|---|---|---|
| candidate files | raw `ctx.raw.files` (order + dups kept) | deduped `Set` of `progress.*.touchedFiles` |
| `context` shape | `{ file, source: 'hook.preToolEdit' }` | `{ file }` |
| `ts` | one precomputed string for all events | per-event via injectable `opts.now` |

`runBoundaryCheck` therefore (1) iterates `touchedFiles` **as given** (no
internal dedup — the caller owns dedup/order), (2) merges a caller `extraContext`
after the `file` key, and (3) calls a caller `stamp()` per event. The hook
passes its raw array + `stamp: () => now`; settle passes its `Set` + its
per-event `stamp`. Output bytes are unchanged at both sites.

**Emission stays at each call site.** Only *detection* is shared. The hook keeps
its `anomaly-notify` gate-membership check + `selectNotifier` + notify/stderr
fallback; settle keeps pushing the returned events into its anomaly array. This
is why the function is a pure events-builder, not `SettleContext`-coupled (the
hook has no `SettleContext`).

## Files

- `packages/core/src/checks/boundary.ts` (new) — `runBoundaryCheck(input)` +
  shared `boundaryMessage(file)`.
- `packages/core/src/hooks/handlers.ts` — `handlePreToolEdit` calls the check;
  drops the now-unused `AnomalyEvent` import.
- `packages/core/src/notify/collect.ts` — `collectAnomalies` replaces its inline
  boundary block with `runBoundaryCheck(...)`.
- `packages/core/tests/checks/boundary.test.ts` (new) — targets the check
  directly (order/dedup contract, extraContext, per-event stamp, message).

## ACs

1. Boundary detection lives in one module under `checks/`.
2. The PreToolEdit hook and the settle-time collector both call it — one rule,
   two emission points.
3. The hook handler shrinks to read/parse + check + gate/notify (no inline
   event construction).
4. Tests target the check, not the hook.
5. Behavior bit-identical at both call sites (existing
   `hooks/handlers-anomaly`, `notify/collect`, and `cli/status-anomalies`
   suites pass unchanged).
