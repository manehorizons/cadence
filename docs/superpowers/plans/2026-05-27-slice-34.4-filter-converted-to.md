# Slice 34.4 — `recommendation list --filter-converted-to` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `--filter-converted-to <phaseId>` to `cadence recommendation list` so an operator can ask "which rec produced phase X?" — the reverse direction of Slice 34.1's `recommendation show <recId>` forward link. Pairs with Slice 34.3's `--from-rec` forward-conversion command.

**Architecture:** Single-filter addition that slots into the existing list-filter pipeline between text/regex and reverse: `status → text-or-regex → converted-to → reverse → offset → limit`. No schema changes; the field `Recommendation.convertedToPhaseId` already exists (Slice 34.1). Filter compares for exact equality (`r.convertedToPhaseId === <phaseId>`), which implicitly restricts to `status='converted'` recs (only converted recs populate the field). Empty-result dim mirrors the established `<key>="<value>"` shape.

**Tech Stack:** TypeScript (strict, `exactOptionalPropertyTypes`), commander for CLI parsing, vitest for tests, `@cadence/testkit`'s `tempRepo`, `pnpm turbo` for the gate.

**Upstream design source:** `docs/superpowers/specs/2026-05-25-cadence-rec-phase-linkage-design.md` § Slice 34.4 (lines 495–509)

```typescript
  it('Slice 34.4 AC-1: --filter-converted-to <phaseId> returns only recs converted to that phase', async () => {
    active = await tempRepo({ initialized: true, projectName: 'slice34_4_happy' });
    // Seed three recs.
    await run(['recommendation', 'add', '--title', 'A', '--summary', 's'], active.root);
    await run(['recommendation', 'add', '--title', 'B', '--summary', 's'], active.root);
    await run(['recommendation', 'add', '--title', 'C', '--summary', 's'], active.root);
    // Directly mark rec[0] converted→34.4-x and rec[2] converted→34.4-y via
    // ledger edit (the public converter has FK + state requirements that are
    // overkill for this fixture; the same edit-the-ledger pattern is used by
    // Slice 34.3's invalid-status tests).
    const ledgerPath = join(active.root, '.cadence/intelligence/recommendations.json');
    const ledger = JSON.parse(await readFile(ledgerPath, 'utf8'));
    ledger.recommendations[0].status = 'converted';
    ledger.recommendations[0].convertedToPhaseId = '34.4-x';
    ledger.recommendations[2].status = 'converted';
    ledger.recommendations[2].convertedToPhaseId = '34.4-y';
    const { writeFile: wf } = await import('node:fs/promises');
    await wf(ledgerPath, JSON.stringify(ledger, null, 2));

    const r = await run(
      ['recommendation', 'list', '--filter-converted-to', '34.4-x', '--format', 'json'],
      active.root,
    );

    expect(r.code).toBe(0);
    const arr = JSON.parse(r.stdout);
    expect(arr).toHaveLength(1);
    expect(arr[0].title).toBe('A');
    expect(arr[0].convertedToPhaseId).toBe('34.4-x');
  });
```
